# 盘序 Panxu Studio

本地网盘内容营销工作台。管理本人网盘账号，把资源整理、同盘转存、本人分享、本地知识库、流量选题和内容分发串成一个工作流。

## 主要功能

- 工作台与规划：侧边栏组织资源、选题与效果，工作台按功能组提供各项工作操作入口，后续新功能组统一接入；百度知道登录统一在账号管理，答题、资源采集、网盘处理与 CSDN 创作发布分别保留在所属分组。
- 网盘账号：夸克、百度、UC、迅雷、光鸭与 PikPak 的账号管理及隔离登录。同一网盘可配置多个账号，按账号执行保存和本人分享。
- 其他账号：统一管理微博、百度营销和百度知道等非网盘账号。微博使用隔离的官方网页会话，支持昵称与 UID 核验、手写文案、本地配图自动上传、确认提交及自动保存回执；发布本身无需模型或第三方付费 API。已完成本人会话下单张配图、仅自己可见的真实发布验证。
- 资源整理：录入链接、分类、标签、说明和粘贴封面；结合本地 SQLite、全文检索与 Obsidian 笔记整理资源。
- 批量处理：CSV 预检和导入后继续检查转存；支持勾选资料目录或本人网盘目录，批量插入文件夹、图片和 TXT 素材。
- 目录拆分：最多展示三级树状目录，逐项勾选文件或文件夹生成独立本人链接，处理父子重叠及浅层文件。
- 流量词库：接入百度批量扩词、百度营销及已开通的 5118 找词、搜索量和热点接口，积累本地词库；通过 OpenRouter 与本地词库生成选题建议，调用与费用在设置中统计。
- 内容与分发：维护平台内容规则、草稿、媒体素材及发布映射，连接比特浏览器的指定指纹窗口，进入对应平台发布流程。
- CSDN 单篇自动化（开发版）：从本地词库选题并匹配本人资料，生成与审阅教程后，自动填写指定比特窗口并提交；保存回执与断点，未知结果先核对。使用与验证范围见 [CSDN 自动创作与发布](docs/csdn-automation.md)。
- 微博内容（开发版）：统一保存选题、直接发布稿件、资源任务和本地统计，支持账号文风、独立版本及手工计划时间。资源分享保留本人历史排版、资料归属与账号权限核验，附件默认应用托管；仍需审阅、明确上传及最终提交，保留原官方回执与人工交接恢复。范围见 [微博内容工作区](docs/features/weibo-content.md)及[资源图文发布](docs/weibo-marketing.md)。
- 微博数据统计（开发版）：选择已有回执或本人单条桌面链接，显式读取官方详情页提供的指标，查看本地采集历史；不使用付费统计 API。范围见 [微博数据统计](docs/features/weibo-statistics.md)。
- 什么值得买文章（开发中）：从公众号链接导入原文，复用资源入库流程替换本人分享，整理、润色和审阅后交给绑定单账号投稿；未知结果先核对。真实投稿验收范围见 [什么值得买文章分发](docs/features/smzdm-articles.md)。

各网盘及内容平台的实际能力受账号状态、接口权限和平台规则影响；具体接口的真实验收范围见开发文档。同盘转存是当前已实现的主要路径。付费查询、内容生成、转存、建链和发布均需显式触发。

## 开发与实时调试

使用 Node.js 24 或更新的兼容版本。

```sh
npm ci
npm run dev
```

前端由 Vite 热更新，桌面后端编译后暂存，点击“应用更新并重启”后统一加载至 `dist-dev`。开发时直接修改当前工作区，不反复制作安装包。macOS 开发程序的程序坞图标带有 DEV 标识，便于与安装版区分。`npm start` 读取已有生产构建，不提供热更新。

默认数据目录：

| 环境 | macOS | Windows |
| --- | --- | --- |
| 正式版 | `~/Library/Application Support/盘序` | `%APPDATA%/盘序` |
| 开发版 | `~/Library/Application Support/盘序开发` | `%APPDATA%/盘序开发` |

同一项目只运行一个 `npm run dev` 后台，支持多个带功能与会话标识的窗口，共用源码、数据库、Cookie、缓存和附件。通过顶部“会话窗口”或 `npm run dev:window -- --label "资源目录" --session "开发会话"` 打开窗口，各窗口单独保留导航与未提交输入。共享窗口自动化使用 `test:session`，运行或暂停期间阻止手动应用后端更新。首次采用手动应用策略需有序重启现有开发服务一次，详情见[会话窗口](docs/development/session-windows.md)。

不同端口和临时数据目录仍共用后台启动锁，重复启动不会另开后台或覆盖正在使用的 `dist-dev`。退出时等待本服务的桌面子进程结束后释放锁；开发父进程意外断开时，桌面子进程也会退出。异常终止后启动锁最多等待约 10 秒恢复。

工作空间切换记录随环境隔离。测试使用绝对路径的 `PANXU_DATA_DIR` 指定临时空间；不要让开发版和安装版同时使用同一个真实空间。原生产数据保持原位，新开发环境不会自动复制账号或资源。

## 验证

日常开发、修复和验证默认执行与本次改动相关的自动化测试，优先使用脚本连续运行，无须逐次请求授权。主工作台（窗口 ID 为 `main`）保留给用户操作和最终验收，界面测试通过 `test:session` 在本任务专属窗口执行并传入 `--close` 收尾，详见[会话窗口](docs/development/session-windows.md#共享窗口自动化)。纯文档改动按需进行静态检查，不例行跑全量套件。

生产编译使用 `npm run build`。已有测试入口包括：

```sh
npm test
npm run test:e2e
npm run test:e2e:updates
```

单元测试与专用隔离测试使用临时数据库和模拟外部服务；共享界面测试沿用当前工作空间，不清库、不重置登录态，付费调用和真实远端操作按本次已授权范围执行。历史 `test:e2e:*` 脚本须先核对是否兼容共享后台，不直接另开 Electron 实例或套用全局网络拦截。安装包生成与 `test:e2e:packaged`、`test:e2e:production` 在用户要求打包、发布或安装包验收时执行，发布仍需签名、公证与更新文件完整性校验。界面验收面向14寸及以上桌面设备，按受影响布局选择1366×768、1440×900或1920×1080；不例行进行小屏专项，视觉核验可批量查看测试窗口的关键截图。

## 正式发布

0.0.1 按用户明确要求以已签名、尚未公证的状态交付并发布，公证结果不阻塞该历史版本的交付；校验通过显式选项 `--allow-unnotarized` 标明这一状态，仍强制验证签名、构建内容和更新文件。0.0.2 已按默认流程完成公证，不沿用该例外。

发行平台统一记录在 [release.config.json](release.config.json)，CI 矩阵与最终附件检查使用同一配置。本次仅启用 macOS ARM64。

本机已有有效 Developer ID Application 身份后，在本机交互终端配置公证凭据：

```sh
npm run release:setup:mac
```

凭据保存在钥匙串 `panxu-notary`；构建命令自动使用该配置，不将密码或私钥写入源码和安装包。输出为 `release/<当前版本>` 的 DMG、ZIP、blockmap、更新清单及摘要文件。只有签名、公证、Gatekeeper、包内容和更新文件校验通过后才上传并正式发布；本轮未运行自动化功能测试。

日常发行只需点击以下两个命令之一：

```sh
# 全量发行：自动增加次版本，如 0.0.4 → 0.1.0
npm run release:full
# 差分更新：自动增加补丁版本，如 0.0.4 → 0.0.5
npm run release:differential
```

两个入口一次完成自动升版、说明生成、当前源码提交、签名公证打包、分支与标签推送、附件上传核验及 GitHub 正式发布，无须再运行 `release:draft` 或手动创建标签。提交包含当前工作区全部未忽略改动；构建期间源码变化会停止发布。失败重跑继续同一目标，旧版已打包任务先续发当前版本，正式发布成功后的下次运行才继续升版。`--dry-run` 仅查看本地计划，不升版、不写文件、不联网或发布。不自动运行功能测试；固定版本构建仍保留 `release:mac` / `release:win`。凭据、平台及续跑规则见[本地发布脚本](docs/updates.md#本地发布脚本)。

本次使用本机签名和公证。CI 发布工作流保留手动触发，使用前需配置对应的 GitHub Secrets，并选择与版本号一致的标签。日常开发和内部构建不会自动发布。

旧 0.x 联调版的版本号高于 0.0.1，首次需要退出旧版后手动安装；用户数据不随版本重置而删除。后续正式版本递增为 0.0.2、0.0.3 等，保持升级校验和禁止降级。
