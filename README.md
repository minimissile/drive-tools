# 盘序 Panxu Studio

本地网盘内容营销工作台。管理本人网盘账号，把资源整理、同盘转存、本人分享、本地知识库、流量选题和内容分发串成一个工作流。

## 主要功能

- 工作台与规划：侧边栏组织资源、选题与效果，工作台按功能组提供各项工作操作入口，后续新功能组统一接入；百度知道登录统一在账号管理，答题、资源采集、网盘处理与 CSDN 创作发布分别保留在所属分组。
- 网盘账号：夸克、百度、UC、迅雷、光鸭与 PikPak 的账号管理及隔离登录。同一网盘可配置多个账号，按账号执行保存和本人分享。
- 其他账号：统一管理微博、百度营销和百度知道等非网盘账号。微博使用隔离的官方网页会话，支持昵称与 UID 核验、手写文案、本地配图自动上传、确认提交及自动保存回执；发布本身无需模型或第三方付费 API。已完成本人会话下单张配图、仅自己可见的真实发布验证。
- 资源整理：录入链接、分类、标签、说明和粘贴封面；结合本地 SQLite、全文检索与 Obsidian 笔记整理资源。
- 批量处理：CSV 预检和导入后继续检查转存；支持勾选资料目录或本人网盘目录，批量插入文件夹、图片和 TXT 素材。
- 目录拆分：最多展示三级树状目录，逐项勾选文件或文件夹生成独立本人链接，处理父子重叠及浅层文件。
- 流量发现：接入已开通的 5118 找词、长尾词、搜索量和热点接口，记录调用、结果及费用信息；通过 OpenRouter 与本地积累的词库生成选题建议。
- 内容与分发：维护平台内容规则、草稿、媒体素材及发布映射，连接比特浏览器的指定指纹窗口，进入对应平台发布流程。
- CSDN 单篇自动化（开发版）：从本地词库选题并匹配本人资料，生成与审阅教程后，自动填写指定比特窗口并提交；保存回执与断点，未知结果先核对。使用与验证范围见 [CSDN 自动创作与发布](docs/csdn-automation.md)。
- 微博图文营销（开发版）：关联本地选题与本人资料，手工或 AI 创作资源推荐，复用资源封面和实际图片，核验同一微博身份后自动填写、上传、确认提交并读取官方回执，关联原有发布记录与效果；仍保留人工交接及回执恢复。网盘外链沿用本人资料和账号权限核验。范围见 [微博图文营销](docs/weibo-marketing.md)。
- 微博数据统计（开发版）：选择已有回执或本人单条桌面链接，显式读取官方详情页提供的指标，查看本地采集历史；不使用付费统计 API。范围见 [微博数据统计](docs/features/weibo-statistics.md)。
- 什么值得买文章（开发中）：从公众号链接导入原文，复用资源入库流程替换本人分享，整理、润色和审阅后交给绑定单账号投稿；未知结果先核对。真实投稿验收范围见 [什么值得买文章分发](docs/features/smzdm-articles.md)。

各网盘及内容平台的实际能力受账号状态、接口权限和平台规则影响；具体接口的真实验收范围见开发文档。同盘转存是当前已实现的主要路径。付费查询、内容生成、转存、建链和发布均需显式触发。

## 开发与实时调试

使用 Node.js 24 或更新的兼容版本。

```sh
npm ci
npm run dev
```

前端由 Vite 热更新，桌面后端编译至 `dist-dev`，在空闲时重启。开发时直接修改当前工作区，不反复制作安装包。macOS 开发程序的程序坞图标带有 DEV 标识，便于与安装版区分。`npm start` 读取已有生产构建，不提供热更新。

默认数据目录：

| 环境 | macOS | Windows |
| --- | --- | --- |
| 正式版 | `~/Library/Application Support/盘序` | `%APPDATA%/盘序` |
| 开发版 | `~/Library/Application Support/盘序开发` | `%APPDATA%/盘序开发` |

同一项目只允许一个 `npm run dev` 服务，不同端口和临时数据目录也共用启动锁。重复启动会直接提示复用现有窗口，不再创建额外桌面实例或覆盖正在使用的 `dist-dev`。退出时等待本服务的桌面子进程结束后释放锁；开发父进程意外断开时，桌面子进程也会退出。异常终止后启动锁最多等待约 10 秒恢复。桌面实例限制按开发版/安装版环境生效，不随工作空间目录改变。

工作空间切换记录随环境隔离。测试使用绝对路径的 `PANXU_DATA_DIR` 指定临时空间；不要让开发版和安装版同时使用同一个真实空间。原生产数据保持原位，新开发环境不会自动复制账号或资源。

## 验证

```sh
npm test
npm run build
npm run test:e2e
npm run test:e2e:updates
```

测试使用临时数据库与模拟外部服务，不自动访问本人网盘或进行付费调用。`test:e2e:*` 是不同业务的交互回归入口。正式包还需执行 `test:e2e:packaged`、`test:e2e:production`、签名/公证与更新文件校验。界面验收包含常用桌面尺寸及 840px 最小窗口，自动化不能代替查看实际界面。

## 正式发布

0.0.1 按用户明确要求以已签名、尚未公证的状态交付并发布，公证结果不阻塞本轮；校验通过显式选项 `--allow-unnotarized` 标明这一状态，仍强制验证签名、构建内容和更新文件。以下默认流程继续包含公证，不自动降低后续版本的检查要求。

发行平台统一记录在 [release.config.json](release.config.json)，CI 矩阵与最终附件检查使用同一配置。本次仅启用 macOS ARM64。

本机已有有效 Developer ID Application 身份后，在本机交互终端配置公证凭据：

```sh
npm run release:setup:mac
npm run release:mac
```

凭据保存在钥匙串 `panxu-notary`；构建命令自动使用该配置，不将密码或私钥写入源码和安装包。输出为 `release/<当前版本>` 的 DMG、ZIP、blockmap、更新清单及摘要文件。只有签名、公证、Gatekeeper、包内容和更新文件校验通过后才上传并正式发布；本轮未运行自动化功能测试。

本次使用本机签名和公证。CI 发布工作流保留手动触发，使用前需配置对应的 GitHub Secrets，并选择与版本号一致的标签。日常开发和内部构建不会自动发布。

旧 0.x 联调版的版本号高于 0.0.1，首次需要退出旧版后手动安装；用户数据不随版本重置而删除。后续正式版本递增为 0.0.2、0.0.3 等，保持升级校验和禁止降级。
