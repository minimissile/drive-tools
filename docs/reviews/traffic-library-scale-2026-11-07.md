# 流量词库50万规模压测

2026-11-07，记录v34结构优化前基准，保留作前后对照。后续v35优化与复测见[优化复测报告](traffic-library-optimized-scale-2026-11-07.md)。本基准结论：可以存储50万个独立词，但当时不能保证所有读取都在5秒内；长尾范围查询、深分页和概要失效后的组合查询已经出现超时目标。另外，测试库超过当时应用内备份恢复的512MiB上限，容量维护尚未闭环。

## 测试条件

- 本机Apple M3、8逻辑核心、16GiB内存、macOS arm64、Node v24.3.0。
- 使用全新临时SQLite磁盘文件与项目真实迁移、写入触发器、压缩归档和`TrafficKnowledge`读取代码，没有访问或改写实际工作空间，也没有重启客户端。
- 分别生成“5万个独立词/50万条观察”和“50万个独立词/50万条观察”；每组2万条查询档案，中文词约30字，包含4种来源、多平台、默认/实测/未知月量与完整压缩响应。
- 每页50词，档案每页20条；计时包含数据组装及JSON序列化，不包含Electron传输与界面渲染。
- 首次读取前关闭并重新打开SQLite连接，概要缓存为空；没有清空操作系统文件缓存，不能称为物理磁盘冷启动。重复场景记录每次采样，表中采用最大值；部分场景只有一次采样，结果不代表P95或跨设备SLA。

50万观察/5万词库约283MiB，生成数据约87.4秒；50万独立词库约780MiB，生成约73.6秒。生成时间不属于读取耗时，也不是单条新增延迟。

额外测量当前全历史CSV在内存中生成：50万条、约116.5MiB CSV，4332ms，返回后进程RSS约1532MiB（不是持续采样的内存峰值）。该测量不包括保存文件，也不等同一次把50万条载入界面；不能据此保证完整导出流程5秒完成。

## 当前瓶颈与维护限制

1. 普通列表仍计算词条总数；概要统计随数据库整体`total_changes/data_version`失效，无关设置或后台写入也会触发全库概要重算。
2. 长尾类型会为每个词条查找合格来源的观察，并处理来源范围内的排序；与深页`OFFSET`组合时成本更高。应优先维护按来源的最新词条读模型，并采用游标分页。
3. 中文子串搜索使用`instr`扫描词条。当前样本仍然达标，不能直接推断数百万词时仍满足5秒。
4. `core/backups.ts`拒绝恢复超过512MiB的数据库。本次780MiB词库超过这个实际限制；备份导出本身没有同等拦截，可能导出一个应用内无法恢复的文件。导出时还会把整库读入内存计算校验，需一起调整。
5. 公共词库不随应用快照全量传输，但所有命名词池及其关键词会进入快照；将50万词再保存进大量命名词池是另一种负载，本次没有验证其首屏与传输性能。

要把50万独立词作为正式容量目标，需要先修复超过5秒的长尾查询及深分页、缩小概要缓存失效范围，并提高备份恢复兼容性；之后再做真实界面及并发写入验收。本轮仅测量并记录，没有修改这些生产行为。
