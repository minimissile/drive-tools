# 光鸭云盘与 PikPak 接入调研及开发计划

调研日期：2026-10-17。开发环境实施，不打包、不提升版本。官网接口属于兼容适配，并非官方承诺稳定的第三方开放 API；模拟验证与真实账号验收分别记录。

## 调研结论

| 项目 | 光鸭云盘 | PikPak |
| --- | --- | --- |
| 官网 | https://www.guangyapan.com/ | https://mypikpak.com/drive |
| 登录 | 独立窗口本人登录；捕获本账号官网请求的 Bearer 会话，凭据加密保存在本地 | 同左；设备、客户端与验证令牌均来自本人官网窗口，不复制其他客户端身份 |
| 官方开放 API | 已公开 v1.3，包含 OAuth Device Code / PKCE、用户与容量、文件列表、建目录等；需要申请应用身份 | 本轮未找到可据以承诺分享全流程的公开开发者文档；不能将社区 SDK 当成官方开放 API |
| 分享转存 | 官网 `/userres/v1/get_share_access_token`、`get_share_page_files_list`、`restore_share`，以目标文件核验结果为准 | 官网 `/drive/v1/share`、`share/detail`、`share/restore`，支持指定目标目录 |
| 本人新分享 | 官网 `share_file` + `get_share_list`，再核验分享内容与归属 | 官网创建分享 + 本人分享列表，核验账号 UID 和文件 ID |
| 转存统计 | 公开 OpenAPI 未列出分享统计；本次官网代码亦未发现可确认的逐分享转存次数。标记不支持，不用本地转存任务数冒充平台统计 | 官网“我的分享”明确使用 `view_count` 与 `restore_count`，可适配浏览及转存次数。下载次数未找到证据，不推算；字段缺失/负值标记未知 |
| 真实验收 | 待本人登录及有权保存、再分享的小文件链接 | 同左 |

光鸭原始官方文档：https://ossdata.guangyapan.com/doc/guangyapan_openapi_cn.md （v1.3，2026-09-20）。该文档未覆盖分享转存，因此本轮不以 OAuth 文件权限推断分享权限，也不混用 OpenAPI 应用 Token 与官网会话。
PikPak 官方帮助：https://pikpak.me/zh-CN/help-center ，官网 JS 的分享列表字段及 API 调用为本轮技术依据。公开脚本只作接口调研资料，不引入其中的客户端密钥、设备标识或验证算法。

## 实施顺序及验收条件

1. 提供统一网盘注册信息，扩展类型、链接解析、表单/批量/导出过滤、账号与白名单。分享只接受各自精确域名；光鸭 `code`、PikPak `pwd` 不得在规范化时丢失。
2. 将现有迅雷的同族协议实现参数化供 PikPak 复用，保留迅雷原行为；光鸭使用独立适配器，避免把不同协议强行合并。复用原有队列、批量转存、三级树拆分与归档工作流。
3. 会话按网盘和账号隔离。官方窗口仅收集允许头字段；仅固定官网 Origin 读取有限的会话存储；不向渲染进程暴露 Token，不绕过验证码。只读鉴权失败可刷新一次；不确定写入禁止自动重放。
4. 转存前重读已选文件；创建目录后核验；转存任务未完成不建链。分享必须同时出现在本人列表并匹配目标文件；来源链接和跨账号链接不得作为本人新链接。
5. PikPak 统计落入现有本地统计快照与导出，未知值保持 null；光鸭同步明确返回未支持，保留旧快照，界面给出能力说明。
6. 使用模拟传输、临时数据库验证完整链路、分页、会话隔离、错误/不确定结果、UID 错配、本人分享恢复、缺失统计。运行类型检查和相关回归。
7. 用 `npm run dev` 当前源码检查新增账号、网盘筛选和能力说明，截图桌面与 840px 最小窗口；不使用安装版及生产构建。不得自动发起真实转存、建链或付费查询。

## 已知限制与后续

- 两家官网协议均可能变化；遇验证码、权限、实名或配额限制，交由用户在官方窗口处理。
- 光鸭将来若官方开放分享/统计权限，再加独立 OAuth 适配；当前不伪造统计接口。
- 未登录、未做真实转存和分享验收前，不声称生产可用或统计已实测。

### 光鸭真实登录联调修复（2026-10-17）

用户已在官方隔离窗口完成登录，本地加密会话捕获成功。首次 UID 核验出现 `net::ERR_FAILED`。

使用不携带真实凭据的独立 Electron 会话复现并确认两项 CORS 差异：

- 账号接口 `/v1/user/me` 不允许业务专用的 `did`、`dt`、`smid` 请求头；携带这些头失败，去掉后能正常收到 HTTP 401（无效测试令牌的预期响应）。账号请求现仅携带允许的认证头。
- 业务接口 `/assets/v1/get_assets` 返回通配来源，需与官网一致使用不附加 Cookie 的请求；`credentials: include` 失败，`omit` 正常返回 HTTP 401。桌面传输现尊重适配器声明的凭据模式，其他网盘默认行为保留。
- 补充光鸭业务码 117 及账号鉴权码的失效会话识别，明确引导重新登录。

新增头字段及凭据模式、失效令牌专项回归通过。本阶段只核验登录，不执行真实转存、分享建链或付费查询；修复加载后，已在本人账号完成真实 UID 和容量核验。
