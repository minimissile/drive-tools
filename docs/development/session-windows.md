# 共享工作空间的会话窗口

当前源码开发使用一个 Vite 服务、一个 Electron 主进程和一个 `AppService`。开发与自动化窗口共用源码、数据库、Cookie、缓存、账号会话与附件目录。每个窗口的导航、筛选、选择和本地输入按稳定窗口 ID 暂存；主窗口保留原有暂存键，其他窗口使用同一 localStorage / IndexedDB 中带窗口前缀的键。

## 手动开发

正常启动 `npm run dev`。首次采用本功能需要有序重启原开发服务一次，因为开发监督器脚本不会自行热更新；不要同时再启动一套服务。

前端 React/CSS 继续热更新。后端和 preload 编译完成后先暂存，实际运行产物有变化时，各开发窗口顶部显示“后端有更新待应用”；当前客户端继续使用已加载的代码，新开的会话窗口也使用同一版后端与 preload。源码注释等未改变运行产物的改动不产生待更新提示。

结束当前手动验收后，点击“应用更新并重启”，一次加载已编译好的完整版本。后台任务、登录窗口或自动化占用会阻止本次应用，并显示原因；完成占用操作后需要再次点击，不会排队自动重试或突然重启。编译失败时保留原客户端，修复后重新编译；应用过程中产生的新改动留待下次点击。

采用本次改动之前已启动的旧监听器仍使用自动重启策略，需有序重启一次 `npm run dev` 才能启用手动应用。更改监督器脚本、Vite 配置或开发依赖同样需要有序重启开发服务。

顶部“会话窗口”可以修改当前窗口的内容描述和会话名称、打开新窗口、切换窗口。原生标题栏同步显示这些标识。自动化窗口还显示运行、暂停、通过、失败或手动接管状态。

也可以从另一个开发会话执行：

```sh
npm run dev:window -- --label "资源目录编辑" --session "资源清单开发" --page resource-catalog
npm run dev:window -- --list
npm run dev:window -- --focus 窗口ID
npm run dev:window -- --close 窗口ID
npm run dev:window -- --finish 本任务新建窗口ID
```

主工作台（窗口 ID 为 `main`）留给用户操作和最终手动验收，自动化不能导航、点击或修改主窗口中的输入。工作台页面的功能测试也在本任务新建的测试窗口执行。

任务专线窗口只用于开发过程。创建时记录返回的窗口 ID；代码修改、相关自动化测试及必要的视觉核验结束后，在最终回复前清理本任务新建的窗口并切回主工作台。开发窗口使用 `--finish`，多个窗口可重复传入 `--finish 窗口ID`；自动化窗口由下述测试运行器通过 `--close` 清理。不要按标签或会话名称批量关闭。没有新建窗口时执行 `--focus main` 即可，不改变主窗口的页面和筛选。

收尾命令仅处理明确传入的开发窗口 ID，跳过已经关闭的窗口，拒绝关闭主窗口和自动化窗口。主工作台不存在时保留所有专线窗口并提示恢复主窗口；不能关闭的窗口会报错，不会退出共享后台。任务开始前已有的窗口、其他任务的窗口及用户要求保留的现场不纳入本轮清理。

命令通过本地开发监督器申请窗口，不启动第二个 Electron。连接描述保存在被 Git 忽略的 `.panxu-dev-session.json`（仅当前用户可读写），包含本地认证令牌；不要提交或打印该文件。开发调试通道只绑定本机回环地址，用于连接现有测试窗口。生产应用不开启该通道。

## 共享窗口自动化

自2026-11-05起，日常开发、修复和验证默认主动运行与改动相关的自动化测试，无须逐次请求授权。优先用脚本连续完成导航、输入、操作和断言，只在关键结果、异常或视觉验收节点查看截图；不用逐步界面操作替代可批量执行的脚本。纯文档改动只需相应静态检查，不必启动界面测试；也不例行运行与本次改动无关的全量测试。

可从多个终端运行不同模块，每轮创建自己的可见窗口；操作同一业务对象或账号时需避免并发冲突：

```sh
npm run test:session -- --module ./scripts/my-feature-check.ts --label "资源目录专项" --session "资源清单会话" --page resource-catalog --close
```

模块需导出 `async function run({ page, checkpoint, windowId })`。`page` 是本轮窗口的 Playwright 页面代理；定位器构建保持同步，页面操作开始前检查暂停/接管状态。长时间的自定义异步步骤在阶段边界调用 `await checkpoint()`。测试模块由实际任务提供，以上路径是接口示例，项目未附带或自动执行示例测试。

运行器用窗口 ID 查找页面。开发任务默认传入 `--close`，直接调用时设置 `withDevTestSession({ close: true, ... }, run)`，仅关闭本轮已完成或失败的窗口；用户明确要求保留现场时省略该选项。运行中断后核对本轮窗口状态，未被手动接管的残留窗口按记录的 ID 清理，不能退出共享后台。顶部暂停在当前操作结束后生效；“手动接管”中断本轮，之后的人工操作不再作为自动化通过结果。运行器只应通过给出的页面和检查点操作，不能调用 Electron 全局求值、修改进程级 `fetch` 或使用共享 BrowserContext 的全局拦截。页面级 mock 只覆盖渲染器请求，不能冒充后端第三方调用的模拟覆盖。

常规自动化授权不包含付费调用、真实远端转存、建链、发布、清库或重置登录态，按本次用户已授权的业务范围执行。后端仍由用户手动应用更新；尚未加载新后端时，不把旧版本的测试结果记作新改动已通过。

真实业务验收沿用正式使用流程和实际内容，不在稿件标题、正文、摘要、图片说明或资源名称中添加“功能测试稿”“仅供测试”“demo”等验收标记。验证说明与结果写入任务日志或报告。需要验证修改与更新时，使用有实际意义的内容调整；保留原有来源信息，不编造作者经历，也不改动用户正在编辑的内容。

脚本异常、SIGINT 和 SIGTERM 会尽力更新本轮状态。若运行器被强制终止，保留窗口可能仍显示运行中；手动接管或关闭该窗口可以解除重启等待。

## 生命周期与数据

任一窗口保存业务数据后，后台向所有工作台发送变更事件，各窗口按现有读取逻辑刷新，不替换本地未提交输入。原生文件对话框通过请求上下文绑定发起窗口。关闭一个窗口不会退出其他工作台；最后一个窗口仍遵循现有后台任务退出确认。

自动化处于运行或暂停状态时，手动应用也会被阻止。结束、接管或关闭后，需用户再次点击应用。监督器在手动应用重启期间保留窗口 ID、标签与会话，窗口重新打开后恢复各自暂存。普通刷新优先恢复已保存的当前页面，创建时的初始页面只在首次使用。

前端仍共用 Vite 热更新；本方式用于当前工作区的并行调试，不冻结测试代码版本。同一个业务对象、账号登录态和全局设置仍然共享变更；测试不能清空公共数据或以完成测试为由撤销其他窗口的操作。

历史 `scripts/e2e-*.mjs` 中有些依赖临时数据库、`electron.launch()`、全局 mock 或退出应用，仍属于独立/安装包验收。它们不能直接当共享窗口测试运行，也没有在本次批量改写为操作当前数据。新共享任务使用上述接入器，迁移旧用例时需逐项移除这些假设。

## 手动应用策略核对（2026-11-04）

TypeScript、脚本语法和差异检查通过，未执行自动化测试。经用户确认后有序切换同一开发服务，恢复主工作台及原有会话窗口；实际源码界面已查看待更新提示与应用按钮。随后产生的后端编译结果保留为待应用，当前运行版本保持不变；未额外点击应用触发第二次重启。编译失败及任务占用分支完成源码检查，尚未进行实际故障注入或自动化场景验证。

## 会话窗口初次接入时的检查

采用 TypeScript、脚本语法和差异静态检查；未执行自动化测试。实际界面工具拒绝访问当前页面，因此窗口布局、多窗口交互、调试连接与暂停流程尚未完成运行验收，不能据此宣称这些流程测试通过。
