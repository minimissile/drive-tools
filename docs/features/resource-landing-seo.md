# 资源落地页与搜索发现

## SEO/GEO工作标准（2026-11-04）

已引入项目级 `ai-seo` 与 `seo-audit`，并将盘序适配规则接入运行时的生成、修订和独立审核。首段明确资源身份与适用需求，标题承诺须在正文兑现，关键结论保留条件与依据；不强制FAQ、统计、专家语录或模板长度。旧草稿下一次显式发布时按新规则复核，现有公开页不自动撤下。

公开页新增同源匿名访问和网盘入口统计，附隐私说明；桌面落地页面板新增“访问与获取”及站长工具入口。按新开发约定，当前桌面后端补丁保留待手动应用；线上采集已部署并通过真实浏览核对。标准、指标边界和维护方式见 [SEO/GEO实施标准](seo-geo-operating-standard.md)，本轮证据与待核对项见 [基线记录](../reviews/seo-geo-baseline-2026-11-04.md)。

## 使用

资源库选择资源，在右侧「固定入口 → 落地页内容」中编辑。先确认本人分享及文件记录已核验，展开左侧文件记录，点击「读取正文」；其他网盘可「导入原文件」。目前支持20MB以内的PDF、DOCX、TXT、Markdown，导入时核对原文件名称与大小。读取后按需补充可公开的事实，再点击「生成落地页草稿」。生成不自动发布；可切换阅读预览、修改正文、保存草稿，最后发布。修改后的正文在发布时重新审阅。编辑补充变化需重新生成，使生成依据与正文对应。

右侧可分别复制落地页地址与固定直达链接。前者适合说明、分享与搜索发现，后者直接打开当前网盘页面；两种地址使用同一资源短码。

公开资源目录为 [panxu.site](https://panxu.site/)。同一个短码同时保留两个用途：

| 地址 | 用途与索引规则 |
| --- | --- |
| `/r/<短码>` | 完整资源说明；经过质量检查并发布后，规范域名允许收录 |
| `/go/<短码>` | 302 跳转当前网盘，禁止收录，更新分享后地址保持不变 |
| `/` | 已发布资源目录；未发布内容不进入目录 |
| `/about` | 整理方法、AI 使用说明与资料边界 |
| `/sitemap.xml` | 站点地图索引，分片仅包含可公开的资源 |
| `/robots.txt` | 允许公开内容抓取，排除管理接口及跳转 |
| `/llms.txt` | 已发布资源的文本目录，方便机器发现，不代表搜索平台承诺支持 |
| `/r/<短码>.md` | 与网页相同内容的 Markdown 表达，禁止单独索引并指向网页规范地址 |

搜索、分类筛选与翻页结果允许跟随链接但不独立索引。Pages 和 Workers 默认域名继续可用，内容规范网址统一为 `https://panxu.site`，别名页面不建立第二份索引。

## 内容与质量边界

正文为服务端 HTML，关闭 JavaScript 仍能读取标题、概述、文件信息、正文、FAQ 和整理依据。前往网盘使用稳定跳转地址。页面提供描述、canonical、Open Graph、WebPage / CreativeWork / BreadcrumbList 数据，不虚构评分、评论、出版信息或 FAQ 富媒体资格。

AI 输入包含脱敏后的资源资料、已核验的文件记录以及本机实际提取的文档文字，不发送网盘Cookie、签名下载地址、系统路径、管理令牌或提取码。夸克/UC提供只读下载能力；其他平台目前使用本地同名原文件导入，不能把文件名当正文。PDF使用Mozilla PDF.js提取，最多取48页、约11万字符，优先前12页并覆盖文中及末页；长文档会明确标注抽样。加密、损坏、扫描或正文不足的文件不能冒充已读，需要提供可提取文字的版本；尚未接入OCR或压缩包内容提取。DOCX通过本地Mammoth提取段落、表格和文本框文字，引用按文本片段定位，不冒充Word分页或排版预览。

全文提取保存在本地生成依据中；公开页只保存短摘录、文件指纹、读取范围和页码引用，不上传原PDF或整份原文。事实段落必须对应实际提取页。公开页展示正文实际引用的依据；被引用的编辑补充也会公开，应只填写可公开信息。文章署名不推断为PDF作者，抽样没读到的内容不能推断不存在。

取消强制正文长度、三节正文与三项问答要求。要点和FAQ可为零；介绍以具体资料内容为主，通用建议不能占主要篇幅。页面提供目录导航、可定位的条目介绍与适用范围，不用通用方法补足字数。

发布前进行独立审阅，并由五项分数计算内部总分，而不是采用模型直接报告的总分：

| 维度 | 满分 |
| --- | --- |
| 正文依据与准确性 | 25 |
| 帮助读者判断和使用 | 25 |
| 资源特有信息与增值 | 20 |
| 自然表达与信息密度 | 15 |
| 来源、范围与可信度 | 15 |

总分至少82/100（8.2/10），每项至少达到满分70%，且无不支持的事实，才可发布。正文实际读取、引用存在、摘要完整且不超过120字符、无虚构承诺、无模板空话、无联系方式和重复内容，均是独立硬门槛。旧版仅有文件名或模型总分的页面仍可读取，但不再满足新发布与目录要求。模型审阅与内部评分不是搜索平台评分，也不能替代逐句核对；本轮人工复核曾发现模型高分漏过截断摘要和抽样推断，已补规则并校订成稿。

落地页按当前可用模型目录选择撰写与审阅模型，可用时使用不同模型。已记录地区不可用的提供方不会被继续选作增强模型；回退使用已配置的文字模型，保持其他业务的默认设置。本轮真实撰写与复核使用 DeepSeek / Kimi；Qwen 曾返回结构异常，异常内容未发布。一次生成通常包含撰写、审阅及一次修订，摘要不完整时额外单独改写，整个流程最多六次 AI 请求；单次长文请求最多等待三分钟，沿用 OpenRouter 凭据、用量记录与预算保护，不在访客访问时调用 AI。

资料不足时保留草稿，不为凑页面数量批量发布同质文章。当前未自动公开整库资源。可通过编辑补充逐步增加真正核实的信息，再重新生成。

## 发布与恢复

本机数据库 v29 保存草稿、生成请求和发布意图。窗口中的未保存编辑按工作空间、资源与窗口暂存，刷新或关闭弹窗后可恢复。另一个窗口改稿时使用版本检查，避免覆盖。

云端 `0002_resource_pages.sql` 新增页面、版本和操作回执，独立于固定链接的目标版本。发布之前核对固定入口、本人分享、来源指纹与内容质量；近似重复正文在本机阻止，完全相同正文在 D1 全局阻止。写入后读取云端核对，超时或结果不明确时保留原请求，可「重试原发布」或「读取云端状态」，不重新计为新一次发布。

「撤下公开内容」保留本机草稿与固定领取入口，移除公开正文、目录条目及站点地图条目。停用固定入口后资源页返回410并从目录移除。此前已被搜索引擎抓取的缓存不会立即消失。

## 标题与摘要选词（2026-11-02）

生成时优先保留资源主词，再按实际文件格式和获取方式组合格式词、下载意图词，选择一个具体的读者问题作为点击理由。搜索摘要自然补充少量正文支持的主题、用途和场景词，并说明真实获取方式。相同规则用于初稿、修订与独立审核，兼顾搜索匹配、自然表达与事实边界。

例如本页选择“人情世故指南PDF下载”作为候选主词，围绕“不会拒绝、怕得罪人”表达具体问题，摘要覆盖“职场沟通、人际关系、拒绝话术、夸克网盘”等实际内容与获取方式。不同资源重新选词，不复用这组示例词。未查询搜索量的词只视为候选，不标注高流量或编造热度；不增加无关词、关键词密度目标或meta keywords。无依据的免费、最新、完整版、免登录、直链下载等不用于吸引点击。

本轮按项目约定进行源码及类型检查、当前源码窗口的手动编辑与发布核对，未运行自动化测试流程。

## DOCX读取修复（2026-11-04）

此前DOCX被前后端格式白名单排除，界面隐藏读取入口，生成又以实际正文为前提，因而无法生成草稿并进入发布。现在统一前端、后端和本地文件选择的格式规则，支持20MB以内的DOCX原文件读取与导入；旧版DOC提示另存为DOCX或PDF。解析只提取文字，不渲染文档HTML或读取外部文件，并限制压缩容器与XML展开体积。

三项以内文件默认展开，所有已记录文件均可访问；暂不支持的文件显示具体原因，读取期间显示进度。保留正文及8.2分发布审核门槛，不通过解除禁用跳过内容依据。本轮按开发约定进行源码检查与当前源码窗口手动核对，未运行自动化测试。

同时修复生成与发布的摘要长度规则不一致：原生成结构允许180字，发布只接受120字，导致模型审核通过仍无法发布。现在生成、编辑、保存与发布共用120字限制，保留完整句子要求；旧草稿超长时明确提示当前字数及精简要求。

使用实际的《实习校招商业分析 简历模板.docx》手动读取2238字正文，完成真实AI生成及独立审核；新摘要112字，所有发布检查通过，内部内容审核9.6/10，草稿已保存且发布按钮可用。本轮未将该简历实例公开发布。TypeScript检查与差异格式检查通过，专线窗口已关闭并切回主工作台。

## 草稿自动优化（2026-11-04）

未通过内容检查时，弹窗顶部提供“自动优化”。它以当前编辑的草稿、最新正文依据及有效的检查意见为输入，优先修复摘要截断、无依据的表述、引用和内容质量问题，保留已有的有用信息与结构；无需先把不合格草稿保存。已编辑内容或编辑补充变化时，也可显式检查并优化。

优化后重新进行独立审核，最多再按新问题修订一次，不循环调用。仍未达标时显示剩余问题，不降低8.2分及事实依据门槛、不自动发布。生成与优化复用模型选择、预算、请求回执和资源锁；旧稿在请求失败时保留，多窗口版本冲突阻止覆盖。优化结果成功后作为新草稿保存，公开版本保持原样，仍由用户点击发布。

摘要遇到截断、超长或过短时，先单独重写成60–90字的完整句子，再进入独立审核，不直接裁剪文字或补标点。该步骤使用JSON模式以避免受约束解码在最大长度处强制闭合字符串，本机仍严格检查120字及句子结束规则。

手动使用《社招toB运营 简历模板.docx》的截断摘要草稿核对：优化后摘要102字，以完整句子结束，全部发布检查通过，内部审核9.9/10，生成结果已保存为第3版草稿，未公开发布。已查看当前源码窗口中的提示、忙碌及完成状态，TypeScript与差异格式检查通过；未运行自动化测试。
