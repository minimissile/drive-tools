# 本地视频制作

在“内容工作室”选定资源后展开“本地视频制作”。默认采用12秒竖屏目录展示，使用当前副本已记录的真实目录（最多120项）；“资料预览”可使用资源封面和手动导入的本地 PNG、JPEG、WebP。默认说明会移除历史摘要中的站外网址和提取凭据，仍可手动编辑。支持横屏、6–60秒、可选本地配乐，输出1080p MP4和PNG封面。本地合成无需AI模型、API Key或云端渲染服务；可选的TikHub热门配乐单独消耗数据接口额度。

文件夹资源可点击“读取文件夹内容”，通过已有网盘只读接口读取所选目录及直接子目录内的真实条目，不再只展示外层文件夹名称。一次最多展开12个直接子目录、展示120项；显示读取时间及截断提示，不把未读范围当成完整清单。目录快照按窗口、工作空间、副本及文件夹隔离暂存，读取失败保留上次目录与编辑内容，不覆盖资源库原文件清单。该操作显式触发，不在页面初次读取时自动联网，也不转存、建链或发布。

点击“制作视频”才会合成，切换页面不停止任务。支持取消、失败后按当前设置重试、制作记录、成片播放及分别导出视频/封面。文字与大附件分别沿用窗口/工作空间/资源隔离的本地暂存；未能恢复素材时保留原记录并提示恢复。制作记录只保存内容摘要，不把配乐、图片和大段base64重复写入数据库。

所有业务共用一个串行本地制作队列，同一来源不重复创建活动任务。重启时未完成任务标记为中断，不自动重做。成片和封面按内容哈希存入现有媒体目录，随工作空间备份恢复并检查引用完整性。视频播放使用限制文件范围的本地协议和Range响应，不向前端开放任意文件路径。

## 复用边界

- `shared/video.ts` 定义纯内容协议：标题、说明、目录项、图片、配乐、模板、比例和时长。素材只接受本地data URL，不接受远程素材网址。
- `core/video-renderer` 负责Remotion渲染、FFmpeg编码、进度、取消、临时文件清理以及成片/封面输出；不依赖数据库、网盘、平台、AI或发布服务。
- `video-templates` 管理共用画面框架及“目录展示”“资料预览”两个模板。模板通过数据驱动，每个模块无需复制渲染代码。
- `core/video-service.ts` 负责串行队列、记录和媒体归档；其它业务可通过独立的`sourceId`和`VideoProject`直接调用。
- `src/video/LocalVideoPanel.tsx` 的`LocalVideoMaker`提供通用编辑/制作控件；资源适配器只负责读取当前副本。前端调用统一经IPC类型契约。
- `src/video/resource-video-source.ts`及专用hook负责文件夹资源的有限展开与快照恢复，通用制作器和渲染器继续只接收内容数据，不依赖网盘接口。
- `core/music`及`shared/music.ts`提供独立热门音乐库，`src/music/HotMusicPicker.tsx`负责选曲。其它业务可以直接复用音乐库和选曲组件；视频渲染器仍只接收本地音轨，不依赖TikHub。

示例：

```ts
await videoService.create("other-module:object-id", {
  template: "directory-scroll",
  title: "本次资料目录",
  entries: actualFiles.map(file => ({
    name: file.name,
    kind: file.isDirectory ? "folder" : "file",
  })),
});
```

跨模块来源ID需包含模块名，避免与其它业务对象冲突。目录与图片须由调用方提供，不编造文件数量、内容、授权和下载效果。制作不包含B站账号操作、自动发布或私信导流。

## 免费资格与运行环境

2026-11-07核对[Remotion官方授权FAQ](https://www.remotion.dev/docs/license-faq)：个人和总人数不超过3人的组织/团队可免费商用及运行自动化，本次使用者已确认属于此范围。该资格不代表对任何规模的公司永久免费；主体或团队规模变化时重新核对授权。项目不注册付费账号、不购买按次渲染、不接入云端渲染。

依赖固定为Remotion、renderer和bundler同一版本4.0.541。渲染使用Remotion配套的本机FFmpeg编码组件及已安装的Chrome/Chromium/Edge；不会自动下载浏览器。缺少本地浏览器时会给出可恢复提示，也可通过`PANXU_VIDEO_BROWSER_PATH`指定已有可执行文件。

开发阶段模板按需本地构建；`npm run build:video`可预构建到`build/video-remotion`。正常源码构建也会预构建模板，打包配置将模板作为独立资源，并解包renderer及compositor二进制。此任务不生成安装包、不升版、不重启共享开发后台。新后端由用户点击“应用更新并重启”加载。

## 抖音热门配乐与每周缓存（2026-11-07）

用户已允许使用TikHub额度，并要求一周更新一次。音乐库复用“连接与设置 → 内容数据源”的TikHub Key，不单独保存密钥。[热门音乐榜](https://docs.tikhub.io/186826241e0)使用`chart_type=hot`的当前热门榜，保留最多20首；“每周”指本地更新频率，不把当前热门榜误称为近七天统计榜。必要时通过[音乐详情](https://docs.tikhub.io/186826235e0)解析所选歌曲，接口按请求计费，金额以TikHub结算为准。

展开“抖音热门配乐”只读取本地库。首次点击“启用每周更新”才启动首次获取及后续周期；正常每隔7×24小时更新一次，软件关闭时不运行，下次启动补一次。多个窗口同时操作会合并进行中的更新；一周内检查更新、重开窗口及重启都复用上次尝试记录。更新失败保留旧榜单并等到下一周期，不因打开页面或制作视频自动重试；用户可明确点击“重试更新”。支持随时暂停，保留已下载配乐。

选曲后明确点击“使用配乐”：已有本地音频直接复用，否则从榜单音频地址下载；榜单缺少地址时才请求单首详情。音频按内容哈希保存至工作空间`music`目录，并检查格式、大小、真实文件与哈希完整性。音频获取失败同样不在重选时自动重复请求，重试需显式触发。不能只缓存带时效的远端URL一周：实际音频落地后，重复选用、刷新、视频合成都不请求TikHub或音频CDN。

后台使用独立`tikhub:music`调用账本，先记录请求，再发往服务商；不挤占皮皮虾的专属预算。最近24小时最多25次音乐API请求，无自动翻页、自动重试或批量下载全部热歌。原始响应受大小限制并本地保存，解析规则更新后可重建已付费响应，避免为修解析重复消费；前端不接收签名音频地址或Key。音频缓存纳入工作空间备份，恢复保留本地素材并暂停自动更新。

抖音官方与第三方接口需分别看待。旧抖音开放平台音乐榜文档仍能访问，但[官方权限调整公告](https://developer.open-douyin.com/forum/question/post/672d828be9f6234d658c8dd2)已明确：移动/网站应用的音乐榜`data.external.billboard_music`权限自2024-11-05停止新申请，2024-11-29起分批回收；这不代表TikHub没有第三方音乐接口。5118公开目录暂未找到对应的音乐榜或音频接口。

榜单元信息、音频文件获取、视频配乐使用范围需要分别核实。[剪映素材使用许可协议](https://sf1-cdn-tos.douyinstatic.com/obj/ies-hotsoon-draft/vco/f72e9cd9-cc19-4db7-ba74-0794833ce854.html)第3.3、3.4条分别规定部分素材的平台限制及单独素材下载、剪映外编辑限制，不能由“剪映内可用”推定为可提取音频在Remotion中合成并跨发B站。当前本地视频可导入已有音轨；用于发布时应选择允许本地合成及目标平台用途的音轨。只发抖音的作品可在发布端按该曲目用途许可原生添加音乐，热度不作为授权证明。
