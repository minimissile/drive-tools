# 资源固定入口

固定入口为一份资源保存一个可长期引用的领取地址，例如 `https://<服务域名>/r/<随机短码>`。接收者打开领取页后，可以查看当前网盘分享及提取码、复制链接或打开网盘。分享失效或需要更换时，在盘序中更新入口目标，已经发布的领取地址保持不变。

固定地址只保证入口身份稳定，不保证目标分享永久有效。网盘分享的有效期、文件权限和实际内容仍由网盘决定。领取页不需要盘序运行；其可用性取决于独立部署的云端服务。

## 绑定范围

每条资源记录维护一个固定入口，目标必须是这份资源对应的本人网盘分享。资源当前按网盘类型保存，因此不同网盘类型的资源记录分别维护入口。更换目标前会核对本人账号归属及已记录文件，不通过来源链接、同名文件或其他网盘分享冒认本人资源。

固定入口不会改写资源的来源链接、副本原分享、分享版本、草稿或发布历史。“创建新分享”仍是独立操作，结果不入库，也不会自动替换已有入口；需要使用新结果时，在固定入口中明确更换目标。此处仅核验现有分享，不新建网盘分享、不转存文件。

现有“复制分享”、内容包、资源导出、资源目录和网盘搜索平台分发继续使用各自原有分享流程，不统一替换为固定入口。需要对外使用固定入口时，使用资源详情中的“复制固定入口”。

## 首次配置

云端服务使用独立的 Cloudflare Workers 与 D1 项目。部署步骤、环境要求、管理接口及迁移命令见 [Worker 部署说明](../../cloudflare/resource-links/README.md)。部署和数据库迁移需要单独执行，桌面应用不会代为创建云端资源。

1. 部署 Worker、应用 D1 迁移并设置 `ADMIN_TOKEN`。
2. 在盘序“连接与设置”的“资源固定入口”中填写服务的 HTTPS 域名和同一管理令牌。只填写 origin，不填写 `/r/…` 等路径。
3. 保存配置后，主动检查连接。连接检查核验令牌，并只读检查 D1 两张表、字段及回执触发器，不创建入口。
4. 根据需要开启“新资源入库时自动创建固定入口”，或在单份资源详情中手动创建。

自动创建默认关闭。未配置服务或令牌时，不执行自动云端写入。开启后只面向后续新资源入库，不扫描、批量补建已有资源；已有资源可逐份手动创建。关闭自动创建不会停用已经发布的入口，已有入口需分别维护。

已经创建入口后，服务域名与该入口绑定。不要直接换用新 Worker、清空原 D1 数据库或更换地址；这会让已发布的链接失去原来的领取服务与维护关系。管理令牌可以轮换，云端与桌面端需要同步更新。

## 日常使用

资源详情中的固定入口区域显示同步状态、领取地址与当前目标。

- **创建固定入口**：为当前资源生成地址。有已核验本人分享时绑定该分享；尚无可用分享时创建待更新的领取页。
- **绑定当前本人分享**：联网核验当前分享后，将其作为入口目标。
- **更换目标**：填写新的本人分享与提取码，通过账号、归属和资源文件核验后更新。入口地址保持不变。
- **复制固定入口**：复制领取地址。尚未同步、操作结果待核对或已经停用时不允许作为可用入口复制。
- **停用／启用**：控制领取页是否开放。停用后云端返回停用说明，不删除网盘文件或原分享。

首次入库尚未完成归档时，领取页可以显示“分享链接正在更新”。后续正式本人分享成功归档后，尚未绑定目标的入口可以补上首个目标。已经有公开目标的入口不会因普通保存、重新检查或单独创建新分享而自动换向。

领取地址是公开访问标识；持有地址的人可以看到领取页中的分享和提取码。管理令牌仅用于维护，不能放进文章、浏览器页面或领取地址。云端服务不接收网盘 Cookie、登录密码或网盘 API 令牌。

## 同步失败与未知结果

资源资料和本人分享先保存在本地，再同步固定入口。短链服务不可用、网络超时或令牌错误，不会把已成功入库或归档的资源改为失败，也不需要重新录入资源或重复创建网盘分享。

每次写入在发送前保存独立操作编号、原始参数和预期版本。云端按版本条件更新，并保留该操作的原始回执；同一个操作原样重试不会重复创建或覆盖更新后的目标。历史回执与当前状态是不同的数据，桌面端还会读取云端当前版本后再确认同步结果。

保存意图前会先校验完整请求。云端展示名称会折叠控制字符与多余空白，并在不截断 Unicode 字符的前提下限制为 200 个 UTF-16 单元；资源原名称保持不变。纯本地校验或加密准备失败不会留下启用的空入口记录。

只有首次发送收到兼容服务明确的前置 4xx 拒绝，才会释放本次未提交意图；首次未创建的入口同时标为未启用，避免阻挡资源删除。修正配置或资料后可再次执行原操作。已有未知结果的重试、409 冲突、5xx、超时及无法确认的响应均保留原操作编号，不据此重新创建或覆盖入口。

遇到“尚待核对”或同步错误时：

1. 保留当前入口，检查服务连接与令牌。
2. 使用“重试同步”重发原操作，或“读取云端状态”核对当前记录。
3. 待原操作确认、或明确采用已经更新的云端状态后，再更换目标和启停状态。

读取到旧版本或“云端不存在”不能证明先前写入未发生，不会据此清除未知请求或自动生成新入口。出现云端版本冲突时先读取并核对当前目标，不盲目覆盖。

## 删除资源

存在启用或待核对固定入口的资源不能删除。先在资源详情中停用入口，完成同步并处理原有未知结果，再删除本地记录。

本地删除不会自动删除云端入口、D1 操作回执或网盘分享。已同步停用的领取地址继续在原服务中保持停用；删除本地资源后，不再保留该资源的日常维护入口。需要恢复维护时，应保留原工作空间备份及云端数据，不能按同名资源自动建立关联。

## 本地保存与备份恢复

本地数据库 schema 升至 **27**，新增 `resource_links` 表，保存资源关联、随机管理 ID、短码、服务地址、版本、目标绑定和同步状态。配置保存在工作空间中，自动创建默认值为关闭。管理令牌、提取码及包含提取码的原始请求通过 `SecretStore` 使用本机系统加密保管，不写进普通入口数据或配置明文。

盘序工作空间备份保留入口身份与同步状态，但按原备份策略移除全部凭据，因此不包含管理令牌、提取码和加密原始请求。恢复后需要重新填写原服务令牌，并主动读取云端状态；云端仍存在的入口可恢复其当前目标和提取码。不要把缺失提取码理解为分享无需提取码，也不要用空码直接覆盖旧目标。

此前未创建入口的资源，如果本机已无原分享提取码，只会先创建待更新页，不自动发布可能缺码的目标。仅对已明确不支持提取码的平台（当前为 PikPak）允许无密码目标。其他情况需显式“绑定当前本人分享”联网核验，或填写本人链接与提取码；此保护不会改写已经绑定的目标。

如果原始同步参数已随备份凭据剔除，使用“恢复维护并停用”。此操作先读取云端当前状态，再对同一个管理 ID 和短码执行版本条件写入：保留已读到的目标并停用入口；云端尚无记录时仍使用原 ID 和短码创建停用记录。这个停用写入会使旧请求的预期版本失效，避免晚到的旧操作重新启用或覆盖目标。结果不明确时继续保留待核对状态，不凭一次 404 推断原请求失败。恢复成功后再核对分享和提取码，按需要重新启用。

云端 D1 的入口表与操作回执也需要独立备份；本地工作空间备份不能替代云端备份。

## 实现位置

- `core/resource-links.ts`：本地入口状态、版本核对、加密回执、云端请求和目标归属核验。
- `core/ipc/resource-links.ts`、`shared/resource-links.ts`：领域命令与类型契约；自动查询只包含本地设置和本地入口读取。
- `core/service.ts`、`core/queue.ts`、`core/drive-files.ts`、`core/ipc/sharing.ts`：资源与正式本人分享成功落库后的接入点。
- `src/resources/ResourceLinkPanel.tsx`、`src/settings/ResourceLinksSettings.tsx`：单份资源维护与服务配置。
- `cloudflare/resource-links/`：独立部署的领取页、临时跳转、D1 CAS 和幂等回执。
