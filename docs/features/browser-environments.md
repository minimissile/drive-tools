# 多平台账号与浏览器环境

状态：已接入当前开发源码，尚未随新版本发布。更新：2026-10-26。

浏览器环境是多个平台共用的基础设施。一个环境可以同时保留微博、CSDN、百度等不同平台的登录；平台账号引用环境，业务工作流再解析对应的会话、网络与执行租约。原先“按平台重复配置环境”的规划已落实为统一环境服务，本页记录实际使用方式和当前边界。

“指纹浏览器”是侧栏“工作空间”下的独立入口，与“账号管理”同级。账号管理仅保留网盘账号与其他账号；浏览器窗口、环境配置及环境任务调度统一在指纹浏览器页面维护。账号与环境仍可互相关联，既有页面地址和已保存的导航状态继续有效。

隔离边界在环境之间。同一环境的平台账号共用浏览器配置、代理出口与设备特征；站点存储仍遵循浏览器的域和源规则。同一平台的不同登录身份应放入不同环境，同一环境不提供账号之间的独立 IP 或独立设备指纹。

```text
环境 A：代理 A、浏览器配置 A
  微博账号 A
  CSDN 发布映射 A
  百度登录体系 A → 百度营销、百度知道分别核验业务身份与能力

环境 B：代理 B、浏览器配置 B
  微博账号 B
  CSDN 发布映射 B
```

## 当前能力与隔离范围

| 项目 | 当前实现 | 使用边界 |
| --- | --- | --- |
| 内置浏览器（Electron） | 每个环境独立的持久 Session；同环境多个平台共用 Session | 隔离 Cookie、站点存储与环境网络；设备特征仍受本机影响，不能当作独立指纹设备 |
| 比特浏览器 | 接入已有持久配置；代理和指纹由该配置统一管理 | 需先配置比特连接；同一配置不能重复登记为两个独立环境；拒绝会在打开时动态换 IP 的配置 |
| 内置环境代理 | HTTP 代理，可保存用户名与密码；无需认证的 SOCKS5 代理 | 不支持带用户名密码的 SOCKS5；比特代理在比特客户端设置 |
| 独立代理出口 | 勾选“要求独立代理出口”后，每次显式环境联网操作前通过该环境访问 ipify 核验 | 检查失败、未走代理，或与另一个要求独立代理且出口记录仍有效的环境同出口时停止；不回退直连 |
| 共享登录体系 | 环境内按 identity realm 维护登录身份及修订号 | 百度营销与百度知道共享百度登录体系，但业务 UID、权益和发布权限分别核验，不互相继承 |
| 环境任务调度 | 同环境串行，不同环境的队列任务最多同时执行 2 项；最多 100 项等待执行 | 排队可取消；执行中停止和结果核对回到原业务；调度“操作结束”不等于平台发布成功 |
| 平台工作流 | 微博、CSDN、百度知道的对应操作已接入环境服务与调度 | 后续平台仍需单独实现身份、请求、编辑及回执适配器；登记映射不代表已实现该平台完整自动发布 |

“允许本机网络”的环境可以不配置代理，这些环境不具备独立出口保证。已有环境迁移后保留原来的网络配置；需要出口隔离时应主动配置代理并启用要求。出口检查反映检查时的公网 IP，不能代替代理服务的稳定性配置。

## 创建环境与关联账号

### 从已有比特窗口接入

“工作空间 → 指纹浏览器”顶部的“比特浏览器窗口”列出当前 Local API 服务可访问的全部配置，包含未打开、未接入盘序的窗口。连接尚未配置时，可直接前往比特连接设置。列表显示窗口序号、名称、配置 ID、分组、备注、运行状态，以及已关联的盘序环境和平台账号。

- 支持按名称、序号、ID、备注或盘序环境名称搜索，按运行状态、接入状态和比特分组筛选；每页可显示 10、20 或 50 个窗口。列表读取会遍历比特分页，分页异常或重复时报告错误，不将部分数据当作完整列表。
- “刷新窗口”只读取配置列表与进程状态，不打开网页、不核验平台登录、不创建本地环境。运行状态优先读取活跃进程集合，兼容回退到批量进程查询；状态查询失败时保留列表并显示“状态未知”。整个列表读取失败时保留上次结果和时间，提供重试。
- 未接入窗口的“接入盘序”会打开已预填名称和配置 ID 的环境表单。名称与独立代理要求仍可调整，确认保存才登记；同一持久配置不重复接入。比特名称和分组变化不会替换本地环境名称或账号关联。连接地址在读取后变化时，旧列表的接入和控制操作会被拒绝，需重新读取。
- 已接入窗口显示本地环境及账号；“关联账号”进入其他账号页面并自动选中对应环境。“详情 / 诊断”展示比特代理配置、设备与内核、上次有效出口检查、业务占用、账号的本地身份核验记录及待处理操作；配置读取失败可单独重试。配置检查和进程状态均不代表平台已登录。
- “打开窗口”启动或唤起对应比特窗口；详情内的“打开平台”复用原账号与发布映射的官方入口流程，不覆盖已有编辑页，不自动提交或发布。
- “关闭窗口”先展示执行或排队占用，以及微博、CSDN 已填写或结果待核对的操作。执行或排队期间拒绝关闭；其余情况须本人勾选确认已保存页面并核对未完成操作。关闭请求不删除窗口、Cookie 或本地账号，发送后刷新进程状态确认结果。已登记环境在尝试关闭后增加配置修订号，使旧页面准备结果失效；未知提交结果仍须回原业务核对，不会自动重发。

窗口控制期间及环境任务排队或执行期间，不能更换比特连接地址。窗口详情只返回展示所需的配置字段，Cookie、网站密码和代理凭据不会随列表或诊断返回前端。

### 手动创建与迁移

1. 打开侧栏“工作空间 → 指纹浏览器”，点击“新建环境”，填写易辨认的名称，例如“内容运营 A”。环境名称不绑定某个平台。
2. 选择浏览器引擎。
   - 选择“比特浏览器 · 指纹环境”时，读取或填写已有配置 ID；代理与稳定指纹在比特客户端统一设置。启用独立代理要求时，还必须配置代理并开启网络异常停止打开（`stopWhileNetError`）。
   - 选择“内置浏览器 · 会话隔离”时，选择本机网络、HTTP 或无需认证的 SOCKS5；HTTP 认证的用户名与密码需同时填写。需要设备指纹隔离时使用比特环境。
3. 确认是否要求独立代理出口并保存。已登记环境的引擎与持久配置 ID 固定；需要替换时新建环境后迁移账号。点击“检查网络”可以主动核实出口，列表显示上次有效检查的 IP；保存成功只表示本地配置已登记。
4. 点击环境行的“关联账号”，进入“其他账号”，新账号的目标环境会自动带入。“关联指纹浏览器”默认关闭，直接使用内置浏览器登录并自动创建独立会话环境，无需安装比特。开启后只列出指纹环境，选定后使用对应指纹浏览器登录。从环境行进入时，按所带入环境自动选择登录方式。
5. 选择微博、百度营销或百度知道，登录官方页面后点击“检查登录”。当前页面如果登录了其他 UID，系统会阻止沿用原账号记录；不会自动将待发任务换到新身份。
6. CSDN 等既有发布映射显示在“其他账号 → 其他发布平台”。在“连接与设置 → 发布映射”选择已登记的比特环境，继续按该业务确认内容形式、入口和链接权限。环境可用不等于账号具备发布权限。

环境名称、引擎、配置 ID 和代理地址等非敏感长表单字段按工作空间和环境暂存，可在切页或刷新后恢复。代理用户名、密码、清除凭据勾选及独立代理要求不随表单恢复；保存到环境的凭据由 SecretStore 加密保管，查询只返回是否存在凭据，不返回明文。已有凭据留空可继续使用，也可明确勾选清除。

账号、环境和发布映射的读取区分首次加载、读取失败和真实空态。读取失败时保留已读内容并提供重试；发布映射没有可用指纹环境时，可直接进入环境管理。长列表打开环境表单会定位并聚焦名称，取消后回到原触发按钮。

## 身份、任务与页面保护

| 对象 | 保存的内容与职责 |
| --- | --- |
| 浏览器环境 | 工作空间内的环境 ID、引擎、持久配置 ID、代理引用、配置修订号与出口检查记录；不保存平台发布权限 |
| 环境登录身份 | 环境、登录体系及身份修订号；同一环境同一登录体系维护一个活动身份关联 |
| 平台账号引用 | 保留原本地账号 ID，关联环境、登录身份、平台、该业务 UID 及已核验的身份修订号 |
| 业务能力 | 继续由各平台账号和发布映射维护；知道权益、外链位置、发布形式等不能从其他平台继承 |
| 环境任务 | 记录关联环境和账号、调度状态与说明；提交内容与平台回执仍在原业务查看 |

微博填写与提交、CSDN 准备指纹、百度知道运行配置均持有环境和身份修订快照。绑定、代理、指纹配置、出口 IP 或登录状态变化后，旧快照不能继续提交；需在原业务重新核验和准备。重新登录会使同一登录体系内其他业务的旧核验失效，各业务再分别检查当前 UID 与权限。

同一环境的不同平台操作共用执行租约，不能通过换平台或换账号 ID 绕过互斥。多个环境可通过全局队列并发；排队表展示最近的调度记录，取消排队不会执行平台操作。队列不定时触发业务，也不会自动创建发布任务。

比特适配器在真实浏览器页面内执行请求，避免使用 Node 请求绕开环境代理。不同平台分别持有页面，不为了接入第二个平台而导航覆盖用户已打开的编辑页。环境有已打开的账号网页、执行中或排队任务时，配置修改与账号迁移会被阻止；先关闭对应网页并处理相关任务，登录数据会保留。

应用重启后，原来排队或执行中的环境记录转为“中断待核对”，不自动恢复提交。先在微博、CSDN 或知道的原业务中核对平台结果与回执，再手动继续；未知结果不能当作确定失败直接重发。

## 迁移、移除与历史记录

旧数据库从 v16 迁移到 v18 时先创建本机备份，再增加环境、身份关联与调度记录。已有账号 ID、UID、发布记录及业务引用继续保留；网盘客户端凭据不因此重建或迁移。

- 旧微博、网站账号与知道账号分别登记为兼容环境，精确保留原 Electron 分区名称，继续使用原有登录数据。
- 旧比特发布映射按持久配置归入环境；指向同一比特配置的映射共用一个环境。已有环境固定关联原连接器地址，不能通过更换服务地址静默切到另一套配置。
- 在“其他账号”的账号行点击“环境”可切换“关联指纹浏览器”。开启时选择指纹环境；关闭时选择已有内置环境，或“自动新建独立内置环境”。只有点击“确认关联”才会迁移；切换开关本身不改变现有账号。新建环境与迁移在同一事务内完成，失败不会留下空环境。共享同一登录体系的账号整体迁移；目标环境同平台已有账号时拒绝冲突，不能只搬动共享身份中的一个业务。
- 迁移保留原 UID，但不复制 Cookie 或其他认证数据；必须在目标环境登录原身份并重新核验。已有环境任务的旧准备结果随绑定变化失效。
- 移除一个平台账号只解除本地管理关系，不退出网站、不清空共享 Session，不删除远端账号；其他平台登录继续保留。历史发布与回执保留原引用，原业务仍按未完成任务规则检查是否允许移除。
- “移除配置”仅适用于没有关联账号、网页或活动任务的环境，删除本地登记与已保存的代理凭据，不清理浏览器的持久数据，也不删除比特客户端配置。清空浏览器数据不属于此按钮的功能。

v18 工作空间备份支持导出、预检和复制恢复。恢复副本保留环境配置 ID、账号 UID 与关联关系，不携带凭据；环境和身份修订号增加，核验与出口记录清除，排队或执行中的环境记录转为“中断待核对”。恢复后需重新配置凭据、检查网络和身份，旧准备结果不能直接提交。

## 常见阻止原因

| 提示或状态 | 处理方式 |
| --- | --- |
| 代理出口检查失败或无法确认 IP | 检查代理与 ipify 的可达性后重试；不会切为本机直连继续 |
| 与另一隔离环境使用同一出口 | 为对应环境配置不同的代理出口，再检查网络；仅更改环境名称无效 |
| 比特要求配置代理或网络异常停止打开 | 在比特客户端补齐代理与 `stopWhileNetError`，关闭动态换 IP 配置后重新检查 |
| 环境正在操作、排队或账号网页尚未关闭 | 在原业务完成或取消任务，关闭该环境账号网页后重试修改或迁移 |
| 账号环境或登录身份已变化 | 在目标环境检查原账号身份，重新准备内容；不要使用旧填写或旧运行配置直接提交 |
| 当前环境登录了其他 UID | 重新登录原身份；另一个身份应使用另一个环境和账号记录 |
| 中断待核对或结果未知 | 先查看平台页面和已有回执，在原业务手动恢复，避免重复提交 |

本轮 TypeScript 源码检查、差异空白检查及用户明确授权的 16 组隔离 E2E 均通过。入口为 `npm run test:e2e:environments`（`scripts/e2e-browser-environments.mjs`），覆盖创建环境、跨平台共享登录体系与独立权益、同平台冲突回滚、移除保留会话、租约互斥与跨环境并发、排队取消、旧任务失效、代理失败与重复出口、凭据查询隔离、比特配置变化、重新登录失效、表单和关联导航、读取失败恢复、v16→v18 迁移，以及 v18 导出→预检→复制恢复。结果见 [本轮隔离 E2E 报告](../../.impeccable/review/browser-environments/report.json)。

该 E2E 复用当前 Vite 源码服务，在临时数据库与模拟端口下运行真实 AppService，并用 Chrome 渲染实际页面；未另开第二个 Electron 桌面。比特本地 API 被模拟并连接同一真实 Chrome 上下文，模拟平台页覆盖微博单图上传、填写、点击提交和 CDP 回执保存，以及同上下文的微博与知道页面共存；外部 HTTP 被阻断，不访问真实账号或执行线上发布。

视觉记录位于 `.impeccable/review/browser-environments/`，包含 1440×900 和 1366×768 的环境列表、长表单、调度、账号关联及发布映射空态/失败状态；加载状态另由 E2E 交互检查覆盖。界面延续既有白色工作台，复用 `src/styles/tokens.css` 与公共 Panel、Field、Select、Notice、QueryError 和区域加载状态，未引入新的视觉系统。最终复核将原先列出的三项整改均评为 resolved，disposition 为 ship；该结论只覆盖这三项整改。
