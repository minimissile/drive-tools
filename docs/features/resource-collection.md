# 资源采集

资源采集位于“工作台 → 资源采集”。采集任务、结果、失败说明与进度保存在当前工作空间，结果可交给现有批量预检和转存流程。

## 渠道

- 百度知道：使用选中的已登录知道账号提取百度网盘分享。
- PanSou 本地搜索与验活：沿用现有本地服务和百度网盘验活流程。
- 97盘搜：调用 [97盘搜网页](https://pansoo.net/) 自身的搜索请求，读取已有的分享链接。
- 海搜：调用[海搜网页](https://haisou.cc/)自身的搜索请求，保留标题、分享链接与提取码。

97盘搜和海搜均不使用 API Key，不调用开放 API 或 iDataRiver 端点。勾选渠道后点击“开始采集”即可。原有加密保存的旧密钥不再读取；页面、IPC与任务配置不再提供密钥保存或计费授权入口。

### 网页请求与会话

网页会话按当前工作空间、采集渠道隔离。采集在受限的 Chromium 页面中调用原站已加载的搜索客户端，沿用站点自己的访客校验、请求上下文与 Cookie。客户端脚本地址从页面当前资源中发现，不固定部署哈希；不自行伪造访客凭据，也不绕过登录、安全验证或站点额度限制。

97盘搜使用网页 `/api/search`，按全部网盘类型、每页20条读取 `results / total`。仅采集返回结果中已存在的 `original_url / share_url`，不调用可能生成新链接的 `get_share`。海搜使用 `/api/v2/shares/search` 的 POST 请求，按标题、每页20条搜索，读取 `data.items / data.pagination`，由 `platform / share_code / share_pwd` 恢复官方网盘链接。

采集页提供“打开97盘搜网页”和“打开海搜网页”。原站要求登录或安全验证时，在对应窗口完成后继续原任务；被限流时稍后继续。原站窗口与后台请求共用该工作空间的渠道会话。关闭窗口不会清空本地会话。打开来源窗口是显式操作，任务列表读取和刷新不会启动搜索。

后台搜索页不改动用户可见的原站窗口。停止或超时会销毁本次后台页面，避免请求继续运行；失败同样关闭后台页面，保留可见窗口和任务结果。已打开的可见原站窗口会阻止开发自动重启和安装更新，避免中断登录或验证。来源网页无 Node.js 权限，主框架导航仅允许来源自身，权限申请和下载均被拒绝。

### 分页与恢复

精准模式每词保留一条；模糊模式逐页读取，按目标条数及现有任务轮次上限停止，已读至末页的关键词不再重复请求。网页搜索不等于实时验活，结果不会标记为已验活。

多渠道分页共用断点：每个97盘搜/海搜搜索页成功后，先保存该页结果，再继续其他渠道。后续渠道失败或用户停止时，继续任务复用已成功页面。完整处理一轮后清除该轮缓存，分别保存各渠道已读至末页的关键词。

登录、验证、限流、维护、网络失败和结果结构变化均区别于真实无结果；保留已有资源，不前移失败页的断点。网页客户端内部保持原站自己的正常访客票据更新行为；应用不无限重试，不自动刷新验证页面或追加付费请求。仅复用网页搜索，不执行转存、分享链接生成或发布。

## 按网盘类型查看

结果表显示“网盘类型”，包括百度、夸克、阿里、迅雷、123、115、天翼、移动、UC、光鸭和PikPak。“按网盘类型显示”对整个任务筛选并统计数量，然后分页，每页25条；不会只筛当前页。移动网盘链接保留用于定位资源的片段，天翼链接中的资源标识与提取码分开处理。旧任务按原链接域名识别类型，无需迁移数据库。未命中记录单列，区别于未知网盘链接。

切换网盘类型、历史任务或目标账号会清空选择并撤销本次权利确认。同一类型内支持跨页选择，最多100项。结果可复制或直接打开网盘分享；CSV/XLSX保留既有字段，并附加网盘类型和采集渠道。

## 转存衔接

选择本人已登录网盘账号后，只能勾选同网盘类型的资源。后端再次检查全部所选链接与账号匹配，再进行只读预检。百度、夸克、迅雷等应用已有适配的网盘复用现有转存能力；阿里云盘、123云盘、115网盘、天翼云盘和移动云盘暂提供链接查看、复制和导出。

候选链接按网盘与分享ID去重，提取码和跟踪参数不产生重复资源。自动备选仅来自同网盘、同名资源，避免把其他资源或其他网盘链接作为替代内容。

## 实现位置

- `shared/resource-collection.ts`：网盘识别、链接去重、筛选与结果契约。
- `core/resource-collection/pansoo.ts`：97盘搜网页结果适配。
- `core/resource-collection/haisou.ts`：海搜网页结果适配。
- `core/resource-collection/checkpoint.ts`：多渠道搜索页断点契约。
- `desktop/collection-web-session.ts`：隔离网页会话、原站搜索客户端调用与取消清理。
- `core/resource-collection/web-request.ts`：网页响应与错误的统一处理。
- `core/zhidao/workers/collect.ts`：沿用现有任务执行、结果保存及断点。
- `src/resource-collection/`：渠道连接与采集结果界面。

开发验证遵循项目 `AGENTS.md`：默认源码与 TypeScript 检查，复用现有 `npm run dev` 窗口；自动化测试、真实密钥调用、转存与发布需遵循用户明确授权范围。
