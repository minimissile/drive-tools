# 简书内容：首版功能规划

规划日期：2026-11-23。实现记录更新于2026-11-24。以下保留目标规划，当前已支持官网草稿自动填写标题、正文和本地配图，发布由用户在官网确认；实现与验证边界见文末。

## 维护交接入口（2026-11-24）

简书模块在专用对话“盘序｜简书模块维护”持续维护，沿用当前工作区。先阅读根目录 `AGENTS.md`、`DESIGN.md` 及本节，再按需要查阅后面的规划与历史验证记录。历史修订号只对当时的开发进程有效，不能据此判断当前后台是否加载了新代码；测试数量也有重叠，不累加为整体通过数量。

### 创作工作台排版（2026-11-25）

左侧可按标题搜索和切换稿件，右侧编辑正文或查看交付预览；切稿后的未保存内容仍按窗口和稿件恢复。「新建文章」先选择本人资源、第三方素材或空白文章，账号和模板在「新稿设置」中选填。编辑时账号、资料来源、AI 和历史版本集中在稿件设置栏，常用操作收于底部。需核对官网时，可从稿件顶部直接定位到发布核对。发布记录仍有独立页签。

在 1366×768 的真实工作台只读打开现有稿件核对首屏，并通过 1440×900 和 1366×768 的专属窗口验证搜索、键盘切稿、未保存输入恢复、选材、预览和核对跳转。账号核验、贴吧素材和官网恢复流程使用页内模拟，未调用模型或改写官网。

### 当前优先事项

1. **完成最新修复的完整实号验收。** 上次现场旧核验卡在页面保护登记，新修复只编译暂存；该次未获得官网地址或写入检查点。普通更新被占用拦住，已请求用户授权有序恢复源码后台，尚未获得该次恢复授权。转交对话不代表授权恢复；先核对现场，保留同工作空间、唯一源码后台、既有窗口及全部比特页面。
2. 恢复时保留原文章、正文、配图、版本和来源。服务启动会将中断的 `preparing` 转为 `uncertain`，不自动重发；明确核对未发布后回到编辑，再继续同一篇文章。不得为绕过占用另起后台、改端口或数据目录。
3. 首次重跑要取得**本次创建请求的准确 note 回执**，再核对官网服务器的标题、全文、真实链接、提取信息和图片。随后只读重开、官网刷新和盘序刷新，确认同稿、无重复上传、无发布回执。不能将只读重开旧稿记作新填写通过。
4. 完成以上流程后再依据实际问题改善易用性；暂不扩展自动发布或批量运营。保留原有紧凑白色样式，不借维护重做界面。

已修复的关键问题包括：当前用户读取错误、查看草稿误用通用文档接口、新建时误把恢复的旧稿当新稿、上传未知结果盲目重试风险，以及跨页面保护登记挂起。最新页面生命周期专项 **19 项（10 项模拟、9 项隔离 Chrome）及 TypeScript 检查通过**；这不替代最新源码的官网完整实号验收。

## 目标与对标观察

帮助经营网盘资源的用户，把资源库资料或第三方采集的素材变成能阅读、能跟踪发布结果的简书文章；资源营销文章还应提供准确的资料获取入口。入口建议为“工作台 → 简书内容”，沿用盘序现有白色紧凑桌面样式。

本次实际通过浏览器阅读了[爱追剧的小王](https://www.jianshu.com/u/03f80ba6b743)的公开主页，以及[样稿一](https://www.jianshu.com/p/783255fa1ea8)、[样稿二](https://www.jianshu.com/p/3da2f6afe4b4)。观察限于可见页面，不代表全账号抽样或平台规则研究：

- 核心形式是围绕资源名的文章：标题带检索词，正文介绍内容，并插入明确的资源获取区。
- 列表可见同一资源从不同标题角度发文。没有证据证明重复发文数量与实际获客效果相关。
- 两篇样稿都展示主入口、备用入口和复制打开说明，链接经过简书跳转页指向第三方短链接。本次未访问短链接，未核验最终资源、归属或可达性。
- 列表中有模型拒答文字进入文章摘要的情况。盘序需要检查生成异常、占位符和事实依据，不能只判断“生成接口返回成功”。

借鉴的是“读者了解资料后能找到资料”的路径。内容事实来自本次关联资料，对标账号的作品介绍、规格、链接及效果不进入新稿事实库。个别文章能显示外链，不代表所有简书账号都具备同样权限。

## 一个入口、两个页签

### 创作发布

默认路径：**选择来源 → 选择资源或素材 → 生成文章 → 编辑预览 → 发布到简书**。来源分“资源库”和“第三方采集”，在同一个创作区切换，不增加独立的必经采集工作台。内部保存、身份核验、环境排队、图片处理等由程序完成，不增加多页必经配置。

| 区域     | 用户看到的内容与默认行为                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 账号     | 默认使用上次选择的简书账号；没有账号时提供账号入口。账号仍统一放在“账号管理 → 其他账号”，支持内置和指纹浏览器。                                          |
| 资源     | 搜索、选择资源库资料，可从现有资源直接进入。显示标题、封面、摘要与本人分享状态；默认沿用资料名作为主题，无须重复填写。资料不满足发布条件时保留草稿，并定位缺失项。 |
| 模板     | 首版只提供“资源介绍（默认）”“使用指南”。模板决定文章结构；文风、篇幅和补充要求按需展开，不要求用户每篇重选模型。                                                   |
| 内容     | 直接编辑标题、正文、图片；编辑与阅读预览就地切换。默认复用已有封面，无图也可创作；生成图片沿用现有能力并独立显式触发。                                             |
| 获取入口 | 预览中固定可见，实际插入交付正文。优先复用用户选定的已有公开资源页；未提供公开页时使用已核验的本人分享及提取信息，不自动创建落地页、短链接或新分享。               |
| 操作     | “生成文章”“保存草稿”“发布到简书”；发布可自动保存当前版本，无须先点保存。复制全文、复制链接、导出文章作为辅助操作。                                                 |

资源介绍的推荐结构为：简短介绍 → 实际包含的内容 → 使用建议 → 获取方式。获取区清晰、易找到，不能只有后台字段有链接而最终正文没有链接。文章可用配图增强说明，不强制为每篇生成新图片。

第三方采集的范围、具体候选及验证结果见[简书第三方数据来源](jianshu-data-sources.md)。第三方区只需要“来源”“关键词或网址”和“采集”按钮，结果显示标题、来源日期、原文入口和资源匹配状态；选择后复用原编辑器。

素材可按两种用途继续：资源线索先匹配本地本人资料，未匹配时选择整理资源再继续；资料介绍、教程等内容也可整理为保留出处的文章，不强制绑定无关网盘资源。纯内容文章不生成虚假的“资料领取”承诺。第三方分享不标记为本人分享，转存、建链或新增公开资源页保持独立显式触发。

生成后提供一个“补充要求”输入框，例如“少一点营销表达”“突出适合自学的人群”。提交后生成新版本，保留当前稿与旧版本；用户手动修改不能被异步结果覆盖。缺乏原文件依据时，只能围绕已知标题、摘要及目录表达，不编造剧情、集数、清晰度、授权、亲测或效果。

为日常连续处理保留轻量批量能力：多选资料后，每份生成一篇，显示总进度和逐篇结果；默认每份一篇，不自动为同一资源铺多篇相似文章。初期逐篇审阅、明确发布，批量生成不等于批量发布。主题合集涉及多资源事实输入，后续再扩展，避免首版同时加入多种组稿模式。

### 发布记录

一个列表提供标题/资源搜索、账号和状态筛选。显示文章标题、关联资源、账号、发布时间、状态、文章链接及最后核对时间；直接提供“继续编辑”“查看简书文章”“核对结果”。

状态按实际证据显示：草稿、处理中、待核对、待审核、已发布、未完成。只有官方明确提供审核状态才显示“待审核”；已点击提交、拿到疑似 URL 均不能直接算“已发布”。

首版以准确保存文章与结果为主。阅读、赞、评论可先手动记录并标明日期与来源；真实自动读取列入后续适配。不能把其他平台热度当简书指标，不能把未知记为 0，也不能把公开阅读量当作网盘下载量。现有资源页统计只有实际支持的口径，不能默认宣称能归因到具体简书文章。

## 发布及恢复约定

- 默认使用账号已有浏览器环境，无需在每篇文章重新配置代理或指纹。登录状态与目标作者须可核验。
- 开发时先核验简书当前编辑器、图片上传、草稿恢复、发布设置、外链和官方回执，才能确定自动填写与提交范围；不预设存在可直接使用的开放发布 API。
- 目标设计是在审阅后点击一次“发布到简书”，程序提交当前准确版本并记录回执。若只能可靠填写，则按钮命名为“打开简书并填写”，由用户在官网完成发布并回填核对，不能把“打开窗口”包装成发布成功。
- 资源营销文章的资料入口沿用账号外链能力和本人资源检查。未核实或受限时说明当前问题，保留稿件；不静默删掉入口后仍显示“资料文章交付完成”，不自动改成私信或评论引导。纯内容文章保留实际出处，不强制填写网盘链接。
- 发布后核对目标作者、文章内容、资源入口与公开状态。仅检查简书域名和 URL 形状不足以证明发布成功或资料可获取。
- 生成失败保留原稿，部分图片失败只重试失败项；超时或中断导致结果未知时，核对原提交，不自动重发。双击不得产生两次生成或两次发布。
- 表单、选择和编辑位置按窗口、工作空间与稿件隔离暂存；账号凭据与付费授权不随表单恢复。

## 建议实施顺序与验收

第一批完成账号接入、资源库/第三方来源选择、指定网页与RSS采集、单篇创作/修改、实际获取区预览、复制/导出和草稿恢复。随后补齐官网填写、可靠提交/回执与中断恢复，再开放批量逐份生成。适配器按已核实的来源逐个启用，不把“输入任意网址”承诺为任意网站都能采集。对用户仍表现为上述一个工作区。

验收以一份实际可交付资料为起点，完成生成、修改、含准确入口的最终预览、官网交接、作者及发布结果核对，并覆盖无账号、无封面、分享不可用、AI 异常文本、部分失败、重复点击和中断未知。按根 AGENTS.md 在任务专属窗口执行，主窗口留给用户；付费生成、真实发布等另按当次授权执行。

首版范围集中在资源文章与图文交付。自动养号、多账号轮换、复杂排期与统计大盘不进入首版。当前方案没有验证简书登录后编辑器和发布能力，实施前需用用户本人账号完成能力核验；平台权限与可用数据以实际结果为准。

## 官网自动填写（2026-11-24）

日常操作：在简书内容中选择已有文章，点击“填写到简书”，到自动打开的官网草稿检查排版、资料入口和图片后自行发布。已经填写完成时，主按钮改为“查看已填写草稿”，只打开原稿。修改本地内容后可重新填写同一官网草稿，复用已上传配图。

- 内置浏览器和指纹浏览器共用同一套经官网实际验证的编辑器逻辑。每篇本地文章独立关联官网 note，不覆盖当前打开的其他文章；用户切到另一稿时保留该页面，另开原草稿。
- 配图按本地顺序追加到正文末尾；不自动下载第三方来源的外部图片。本地文件先校验安全路径、哈希与大小，再通过官网的图片上传控件上传。
- 创建官网草稿后立即保存具体 note 地址，逐步保存内容哈希、已上传图片与进度。重试使用原稿，已确认图片不重复上传；不会将草稿状态登记为发布成功。
- 每次写入在同一次官网页面执行中核对目标 note、标题、正文和图片，检测官网手工修改后停止覆盖。上传结果未知时保留上传记录，不盲目重传。用户检查官网、明确确认该图片未上传后，才可解除该项限制并重试。
- 备份保留具体草稿地址与填写检查点，恢复后重新核验真实账号；正文中的提取码继续只在实际交付时从 SecretStore 读取，不明文写入检查点。

真实联调已用当前登录账号的未发布测试稿验证：自动填写标题、460字交付正文（含实际资料入口与提取码）、上传1张本地测试PNG；修改标题和正文后重新填写同稿，复用原图，再恢复测试稿原文。保存后读取官网服务器的标题、全文、图片和真实链接目标，刷新官网后完整保留，再次填写未新增图片。

实测发现并修正了两处官网适配问题：Kalamu不以普通InputEvent保存正文，现改用其标准粘贴事件；编辑器有500ms内容更新防抖，不能把尚未更新的“已保存”提示当作本次保存成功。当前以服务器读回结果为准，内容一致时不发送多余保存请求；网络失败不记完成，保留同稿恢复依据。

### 新建回执与浏览器保护续验

加载修订44并确认本人身份后，实号发现写作页初始化会恢复上次文章，早期“URL变化即新建完成”的判定可能误关联旧稿。图片保护阻止了写入，原稿未被覆盖。现已改为监听本次官网“新建文章”的准确POST回执，核实文集、note ID与未发布状态；先记录该地址，再等待准确新稿、空正文、无图且加载遮罩消失。异常或未知回执不猜地址、不自动再次新建。

“改用新草稿”提供明确二次确认：解除本地关联，保留官网原稿、本地正文、配图及全部版本；默认“返回修改”仍使用原稿。相关领域保留测试、内存页面的取消/确认流程及1440×900弹窗视觉核对通过。该入口已用于恢复本轮尚未写入的误关联。

后续实号续测还发现共有页面保护登记可能被同一浏览器中其他页面的框架拖住。修复改为当前页CDP监听，保护登记、状态读取与关闭等待设置上限；登记失败、未知框架或可信输入、点击均撤销清理权限。进程归属不等于标签页归属：既有或用户新增空白页不授予清理权限，只有业务明确新建的临时页才可清理。临时读者显式声明受控导航目标，避免将任意人工导航当作可清理页面。

关闭命令发出前即撤销再次清理权限；关闭超时记为“结果未知”，不重试并继续处理其他页。已经发出的关闭命令无法取消，因此不将超时表述为页面必然保留。19项针对性回归（10项模拟、9项临时目录隔离Chrome真实操作）及统一TypeScript检查通过，包括已有和用户新增空白页保留、可信点击接管及关闭超时继续清理；未连接或关闭现有比特浏览器页面。

目前旧版本核验仍卡在保护登记，尚未核实账号、没有官网检查点或实际写入；文章、配图均保留。普通更新会被占用拦住，需要有序恢复源码后台后完成最终实号验收。两个既有源码窗口须按原ID保留，所有比特浏览器页面保留；此阶段仍未记录完整流程通过，也没有新增AI调用或文章发布。
