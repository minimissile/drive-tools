# 知乎内容运营、公共素材供给与日常参与设计

设计与资料复核日期：2026-11-03。范围是现有项目的下一阶段设计，以及本轮日志阅读界面改造。本文区分现有能力、缺失流程与待实施能力，不把设计当成已经运行的功能。

## 1. 目标与本次结论

用户的目标是前期建立稳定的创作能力，后期围绕网盘资源提供有用的信息。系统应围绕受众需求组织选题、资料、观点、编辑、发布、反馈及日常参与，不能把“按时发完文章”当成运营效果。

本轮重新阅读了两份飞书资料、2022年的知乎运营文章及当前可访问的知乎官方规则。采用可核实的官方要求作为产品边界；教程中的升级周期、账号权重、固定互动数量与高等级不容易删帖等判断只作为作者经验，不作为系统承诺。

主要调整：

- 皮皮虾成为公共素材来源之一，服务知乎、微博等渠道；不绑定知乎账号，也不直接成为可发布稿件。
- 为每个账号保持长期内容方向。初期内容与后期资源介绍使用同一受众和主题，避免先发泛化鸡汤，升级后突然切到软件、模板广告。
- “像资深创作者”落实为选题判断、具体证据、清楚取舍和持续回应；不虚构履历、职业、亲历或测评结果，不以规避AI检测为目标。
- 活跃功能包括阅读清单、提问/回答机会、评论草稿、关注候选和反馈跟进。没有每天必须提问、关注3人、点赞若干次的硬指标；不做拟人化伪装、多号互赞互评、刷阅读或随机行为躲检测。
- 发布保留已有身份、环境、内容版本和回执校验。当前两个计划继续暂停，不因写入本设计自动恢复或新增真实发布。

## 5. 公共素材供给流程

### 5.1 获取与成本

统一配置继续放在设置中。新增来源策略保存查询词、允许来源、仅图文选项、每次最大请求数、每日预算、刷新间隔、最低可用库存及授权有效期。Key仍由加密凭据服务维护，不进入计划、日志或模型输入。

先检索本地归档和已落地素材，再按明确授权的来源策略补给。页面读取、预览排期、普通轮询不访问服务商；请求失败、缺少游标或结果未知不能自动无限重试。

沿用历史实测结论：当时图文搜索最大观察到10条，未发现有效的单页条数参数；这不是全局上限。每次保存全部返回项，接口可用的最大值以正式文档与实测为准，不把`feed_count`误当条数。缺少有效续页游标即停止，不猜偏移量。重解析归档不再收费。

### 5.2 来源条目与评论

来源条目保留原帖ID、作者、链接、请求归档ID、抓取时间、原文、图片哈希、评论ID、评论作者、点赞数和原始标签。原始快照不可被编辑稿覆盖。采集失败可单项恢复，已下载图片按哈希复用。

“神评”只能采用来源明确提供的标记；高赞评论可以标为“高赞候选”，不伪称官方神评。记录评论覆盖范围、已获条数、总评论数及缺失提示。正文有评论但响应没有评论时，标记资料不全，不用模型凭空生成“网友神评”。完整评论补采若需要付费接口，应单列预算与请求记录，不能混在免费本地检索中。

### 5.3 匹配与筛选

自动筛选产出的是候选：领域相关性、是否有可讨论的问题、信息增量、图片可用性、评论可理解性、重复度、来源与使用依据。先用确定性规则筛掉广告、低俗攻击、来源损坏、重复条目，再按需要调用有预算的语义分析；每项分数附原因，分数不等于自动审阅通过。

图片、原文、评论分别记录使用依据：本人原创、明确授权、许可可用、公共领域、拟作必要引用或未知。未知项可保留在私人资料库，不能仅因来自皮皮虾而自动判定可整篇转载。出处署名与授权/适当引用是不同事项；原帖本身为转载，也不消除原作者的权利。

### 5.4 转成知乎稿件

每个候选先生成编辑简报：面向谁、解决什么问题、采用哪些资料、作者的核心判断、准备新增什么内容、哪些结论需要核实、采用回答/文章/想法哪种形态。

- 回答：先有真实存在且相关的问题；完整回答题意，不把“神评合集”塞到无关问题下。
- 文章：适合需要完整说明的单一议题；评论/图片只是讨论材料，正文要有自己的分析。
- 想法：适合短小观察、真实疑问、讨论或视觉材料；不为把短内容强凑成文章而注水。目前浏览器发布端只支持文章与回答，想法列为待开发并在此前人工交接。
- 资源介绍：从实际资源文件、版本、使用方法和适用边界生成说明；不能只写下载口号。链接可用性与来源合规分别核对，不能通过跳转链接、谐音或二维码规避平台规则。

状态流转：来源候选→已采集→待核实→选题简报→编辑稿→待审阅→已审阅→待平台提交→已提交/待核对→官方已发布。每一步保留来源、版本与原因；拒绝、资料缺失、预算不足、等待作者意见是正常终态，不自动凑数。

## 6. 作者表达与AI使用

“不AI化”应通过资料和判断提升，而非同义替换、故意错字、随机语气或AI检测分数。作者档案记录可公开的真实经验、明确观点、已审阅范文和措辞偏好；没有经历时就用资料分析或示例，不冒充多年从业者，不声称“亲测”未做过的操作。

建议工作顺序：明确问题→列可验证事实与实际文件→形成作者判断→写有依据的初稿→核事实/引用/图片→检查表达→按版本审阅。AI可辅助检索整理、大纲比较和检查，但不能自动批准自己的内容。要形成“资深创作者”的质量，仍需有可核对的实操记录或用户提供的真实判断。

审阅清单关注：

1. 标题与正文是否对应，回答是否解决具体问题。
2. 有没有可验证的新信息、步骤、比较或判断依据；删除空泛劝说和万能总结。
3. 每个数字、版本、引用、经验与图片有没有来源；假设和示例是否标明。
4. 是否只是拼接原帖和评论，是否缺少作者贡献，是否与自己的旧稿重复。
5. 文风是否自然、具体、克制，是否反复套用同一种开头和三段式总结。
6. 是否满足使用范围和平台要求；AI参与是否如实声明。

### AI标识会不会影响审核

应区分三件事：

- **创作声明**：官方治理细则要求主动披露AI参与，不能为“像真人”取消真实声明。平台声明与正文中的说明用途不同。
- **质量与分发**：官方重点治理的是大量生成拼凑、低质、事实错误等内容，可能减少分发、折叠或删除。不能把勾声明理解成免审，也不能仅凭前六篇带标签就认定流量变化由标签造成；本次未核实到足以承诺“标识绝不影响推荐”的最新官方原文。
- **收益资格**：本次读取的致知计划规则明确排除AI创作及AI辅助创作内容。可以发布与可计收益不是同一结论，不能把勾选/不勾选当作收益开关。

现有六篇的AI记录符合实际创作过程，保留历史，不自动删除、重发或改掉声明。后续不机械追加同一句“本文由AI辅助整理”；根据实际使用环节写准确说明，并保留平台要求的标识。导入草稿也应传递真实的创作来源，不能一直以硬编码`aiAssisted: true`替代溯源，更不能因为人工润色就改成纯人工。

## 7. 日常参与设计

“每天”指每天有相关内容可读、有反馈可处理，不要求每天同时完成提问、回答和发文。当天没有值得发布的观点，就不发布。文章来源中的“3个”用于初期建立候选观察清单，不作为每日新增关注指标，也不称为官方权重公式。

| 类型 | 系统准备 | 用户参与与完成证据 |
| --- | --- | --- |
| 阅读 | 按账号领域整理问题、官方更新和关注对象的新内容，显示推荐原因与摘要 | 用户打开原文、保存笔记或标记已读；打开页面不等于阅读完成，不刷停留时长或重复访问 |
| 提问 | 检索相同问题、整理尚未解决的具体疑问、补齐背景和范围 | 用户核实问题真实且不重复后在官方页面提交；没有真实疑问则跳过 |
| 回答 | 推荐有能力回答的题目，整理问题要求与证据，形成待审阅回答 | 逐稿核对观点与依据，再按平台允许方式提交，保存确切回执 |
| 文章/想法 | 组织系列主题、资料与编辑任务 | 审阅后交付；未支持的形态清楚标为人工处理 |
| 评论 | 针对已阅读内容提出具体补充、追问或纠错草稿，显示原文上下文 | 用户逐条判断并发布；无实质意见可跳过，不自动发“学习了”等模板评论 |
| 点赞 | 记录值得阅读的内容，不自动替用户表达赞同 | 用户根据实际观点决定；不以点赞数/点击频率衡量运营效果 |
| 关注 | 每账号初期准备3个相关话题或答主候选，显示领域与推荐理由 | 用户决定是否真正关注；已关注的不反复关注/取关 |
| 反馈 | 汇总本人内容下的新问题、纠错与有价值评论 | 优先回应真实读者，不让7、8号互相制造讨论 |

不实现自动批量互动、双号互赞互评、购买粉丝、为涨分而批量举报、虚构阅读、假装真人轨迹或通过更换IP绕过处置。差异化落在主题、证据、观点和受众上，不落在伪装操作的节奏上。

## 8. 排期、授权与停止

统一运营中心管理“采集、资料补全、编辑、审阅、平台提交、结果核对、反馈跟进”的依赖。知乎原服务仍是额度、内容版本、账号身份、环境与提交回执的最终校验方；不再平行建立第二个发布调度器。

自动处理适合归档去重、缓存复用、资料筛选、库存预警、本地排期预览、日志与数据汇总。付费采集/生成使用独立预算和授权；互动与内容发布遵守官方平台允许方式，不能凭长期授权绕过平台明确禁止的自动化行为。当前浏览器批量发布链路只保留历史能力说明，不把已有实号发布成功当成官方允许的证明。

暂停原因采用结构化字段：未定位领域、无相关素材、资料/使用依据不足、等待作者观点、等待审阅、预算不足、无可用游标、额度到达、未登录、验证/实名/协议待处理、平台限制、结果未知。前端显示具体依赖及可采取动作，而不是一律“素材不足”。

复用已有同出口60分钟及日周额度作为本地上限，但它们不是平台许可或安全阈值，不通过慢速化或随机化包装禁止行为。已记录`submittedAt`的未知结果只核对，不重发；重启不自动恢复真实操作授权。

## 10. 日志窗口

本轮先把知乎运行日志改为白色、固定高度、可滚动的log窗口，提供时间/级别/账号/消息、事件与任务详情，复用既有数据库及JSONL文件。支持本地全文筛选、隐藏重复心跳、暂停画面刷新、跟随最新、复制当前显示日志及全屏阅读；暂停刷新不停止任务，也不删除日志。

日志展示按时间从旧到新阅读；默认页仍取最近50条，保留历史分页。只有用户选择跟随最新才滚到末尾，用户向上读历史或展开详情时不抢滚动位置。筛选失败、首次加载、真实空态与无匹配状态分开；新日志不能覆盖用户正在复制的旧片段。

下一阶段日志增加来源供给的数量：服务商返回、归档、缓存命中、图文/评论完整、筛选拒绝、编辑候选、等待审阅、实际交付及平台结果。任务完成、审核通过、远端已发布是不同事件；没有证据不记成功。不在log窗口执行发布、重试未知提交或暴露Key/Cookie。

## 11. 实施顺序与验收口径

1. **本轮**：完成资料复核、断点诊断、领域建议和本文；实现日志阅读窗口，按AGENTS.md做类型检查与源码界面手动查看。没有执行新的计费采集、生成、互动或发布。
2. **公共素材供给**：先用现有4份归档完成离线候选及缺失项分析，再补来源策略、请求预算和采集进度；批量落地仍复用公共采集队列。验收须展示原帖、真实图片与评论覆盖，不伪造神评。
3. **编辑与审阅**：先跑通每账号一份相关的编辑简报和待审阅稿，验证来源、作者贡献、版本失效、同文多号去重及AI使用记录，不用“生成完即审阅通过”替代流程。
4. **日常参与**：接入观察清单、真实问题与反馈待办，提供人工操作交接；不开发刷互动执行器。
5. **运营复盘**：按官方可读取数据观察阅读、收藏、有效反馈、违规/删除与创作分变化，记录数据日期；不承诺等级、曝光或收益，不把账号权重虚构成一个分值。

本次日志界面交付不代表2–5已开发完成。后续真实端到端验收需要明确的数据和使用依据、费用范围及平台允许的操作方式；在此之前两个账号保持既有暂停状态。

## 12. 公共供稿实施方案（2026-11-03）

本次推进公共素材供给和编辑交付。“皮皮虾采集”统一提供供稿候选、编辑队列、供稿日志、发现与采集四个页签，与原列表发现共用知识库、采集器及图片附件；不在知乎内部再建采集器。候选按本地关键词匹配并显示理由，允许查看全部；无匹配时保留真实空态，不把生活段子标成软件或模板素材。

批量任务由后端持久化，每次最多20项；逐项记录采集、编辑、阻塞与交付，成功项复用本地图片。离开页面不丢队列；重启转为等待明确继续，不恢复计费请求或发布。已有归档可直接解析，评论缺失如实提示；这条批量链不调用TikHub付费接口，新增列表仍用已有显式请求入口。

编辑单按来源去重，冻结采集快照，保存方向、受众、核心问题、作者新增判断、事实核对项、图片/评论选择及各自使用依据。标题和正文起始为空，不把拼接原帖当成新稿。可手动编辑，或按次授权调用现有AI服务生成待审阅初稿；生成会永久记录该稿的AI参与，人工润色不清除。保存采用版本校验；交付后锁定本编辑单，渠道中的后续修改沿用既有审核失效规则。

交付仅创建本地待审阅渠道稿，保留来源、作者贡献、使用依据和AI记录。相同编辑单重复交付返回原稿；相同正文及附件不跨号重复创建。可选关联既有运营计划，限定库存的计划需加入新稿；加入失败单独提示，不能诱导再次创建稿件。计划启用、内容审核与平台提交仍由原模块负责。

运行事件复用RuntimeLog，按来源ID、编辑单ID记录缓存复用、逐项失败、生成、交付和计划关联结果。此次只做源码检查、类型检查及当前源码桌面手动操作验证，不运行自动化测试，不消费新的采集/生成费用，不进行实号发布或互动。

### 已实现的交接边界

- 编辑单可保存、暂不采用、恢复编辑及补全原素材。来源快照与文字按版本保存，付费调用、渠道交付确认不随表单恢复；AI使用事实保留。备份包含编辑单、快照配图及已关联的微博稿，恢复不自动执行采集。
- 交付复用`content_source_exports`，原采集入口也能识别新编辑层的渠道去向；重复交付保留原稿。图片先验证本地哈希，渠道稿与交付记录在同一数据库事务创建。
- 日常稿仍受原链接/推广检查约束，正文标明来源作者与帖子ID，完整来源URL留在记录；常规稿可在参考出处中显示来源URL。原文或评论中的推广信息不会被自动删除以绕过检查。
- 面向具体账号的知乎稿同时受原发布服务和统一运营库存的账号校验约束，不能分配给另一个账号。加入计划库存是独立显式动作；计划保持暂停、稿件仍待审阅。
- 渠道审阅页复用来源溯源组件，能看到核心问题、作者贡献、核对清单、使用依据与AI事实。当前编辑交付以文章/微博为范围，真实问题回答及日常参与待办仍属后续阶段。
