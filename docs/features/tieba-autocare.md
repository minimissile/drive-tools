# 贴吧自动养号：开发计划与实施记录

日期：2026-11-07。四阶段已有源码实现，但此前的离线及模拟测试没有覆盖完整实号流程，用户验收发现个人读数未取得、观察目标无签到接入入口、初始目标为空。此前“功能已完成”的判断撤回；本轮按真实账号修复，具体证据与未验证范围见“用户退回后的真实诊断与修复”。后端只编译暂存，不自动应用或重启；关注、签到、付费生成、上传和发言的实号结果尚未核实。

## 产品目标

选择已有贴吧账号，在“添加贴吧”中查找、筛选并勾选候选，或填写吧名/官网链接，再点击“添加并关注”。系统逐吧核实资料并自动关注，官网确认后成为可选目标；也可同步已有关注吧。勾选签到目标并保存后，再按需开启日常任务。前台保持一个签到总开关、目标吧、今日任务和运行日志；帖子读取与回复按需展开。后台区分账号、账号与吧的关系、内容和执行记录。AI只负责有限的内容生成，任务与预算由程序决定。

只复用现有网站账号及其浏览器环境，不新增另一套登录凭据。沿用公共环境队列，协调百度网盘、知道和贴吧共用环境。首阶段使用指纹浏览器关联账号；官网控件或身份无法确定时停止操作并保留具体原因。

## 调研依据与取舍

- [外虎贴吧系统](https://www.yyhuu.com/yhotiebapro.html)及其[使用教程](https://www.yyhuu.com/yhotiebapro_help.html)：借鉴账号、目标地址、内容分离及次数/时间上限。厂商版本与功能声明未经过安装验证，教程发送次数也不等于官网确认成功。
- [Tieba-Cloud-Sign](https://github.com/MoeNetwork/Tieba-Cloud-Sign)：借鉴逐吧状态、定时任务、独立失败复签；重新核对错误及成功语义，不沿用旧HTTP路径或将频繁操作判为已签到的逻辑。
- [TiebaMecha](https://github.com/hwdemtv/TiebaMecha)：参考持久化排期、配置快照、条件领取、逐次流水和账号×吧权限管理。其master的部分机制尚未发布；不采用崩溃后直接将未知提交复位重跑的策略。
- [aiotieba 4.8.0](https://github.com/lumina37/aiotieba/releases/tag/v4.8.0)已移除`add_post`，不将旧接口列表作为现成发言后端。
- [Buffer连接恢复](https://support.buffer.com/en-us/articles/refreshing-a-channel-in-buffer-7oDS4jk7l1)与[Hootsuite暂停恢复](https://help.hootsuite.com/s/article/suspend-scheduled-content)：借鉴连接恢复与任务重试分离、过期任务不追赶。两者不是贴吧产品。

“防封”“提权”“拟人”等宣传缺少可复现的独立结果，不作为产品能力或验收指标。随机安排仅用于分散工作，不用于规避验证或平台限制。

每阶段只展示已接通的操作。签到、自动回帖、主题发布分别保存范围，开启签到不会取得AI或发言权限。以下次数与间隔是产品预算，不是平台额度，也不承诺固定天数升级。

## 首阶段的运行契约

1. 快照、目标列表、历史和日志只读本地数据库；打开页面不访问官网。同步关注吧是显式请求，保留既有目标及历史，新发现的吧默认不参与自动任务。
2. 每个目标保存账号ID、已核实UID、吧ID、等级/经验/签到状态及读取时间。空字段显示“未取得”并提供具体原因，签到未知显示“签到未核实”，不得从缺失值推断0或未签到。
3. 保存与开关使用配置修订号，拒绝陈旧窗口覆盖。开启只对当前选中范围授权签到，不取得AI付费、发帖、回帖或新目标权限。
4. 同一UID、吧、北京时间业务日和动作在数据库中唯一。首次开启或持续开启到新业务日后首次调度时，创建精确两小时批次；同日切换开关或重启不延长截止或清除尝试。跨日提交和核对都需重新检查业务日，不能用今天已签到证明昨天的未知结果。首阶段按至少60秒分散提交，这是产品预算，不是官方额度；执行积压也不集中追赶，超出批次容量的目标保留过期原因。
5. 到期任务通过条件更新领取，环境队列持有租约后才打开官网。执行前及提交检查点重新检查账号身份、环境版本、选中范围、暂停状态、开关和截止。
6. 签到只点击官方页面明确的签到控件。点击前持久化提交检查点；点击后异常进入待核对，核对只读官网，不再次点击。已签到直接归档，不要求再次操作。
7. 关闭停止新任务及尚未提交的任务，已提交结果继续核对；只读核对不需要重新开启自动签到。单吧限制只暂停该吧，账号身份或登录异常阻断相关账号，其他目标仍可继续。
8. 每个任务保留计划时间、实际尝试、提交时间、状态与中文原因。自动日志不输出Cookie或凭据；不将尝试次数当作官方经验或成功数量。
9. 首阶段不使用补签卡、会员购买、付费AI、远端转存、建链或发言。电脑或应用关闭期间不执行。

## 第二阶段：上下文与回复

控制台增加默认收起的“帖子与回复”：选择观察吧或已同步目标吧，显式发现近期帖子，再打开“帖子上下文与回复”。打开控制台及展开面板只读本地快照；发现、读取和核对才访问官网。当前账号关注列表为空时，可通过下面的观察入口使用候选清单，无须先关注。

1. 候选按本人UID与主题去重，保存准确吧ID、主题ID和读取时间；置顶、锁定、本人及其他受管账号的主题不进入回复候选。重新发现仅刷新原目标与原身份，不迁移目标或清除已提交记录。
2. 阅读完整首帖与必要楼层后才允许准备回复。缺少正文、图片/视频无法完整读取、折叠或回复能力不明确时保留原因；提交前再次读取核对，原帖或身份变化即停止。
3. “AI生成回复”是显式付费操作，复用当前文案模型与全局AI预算。当前产品预算为北京时间每日最多4次生成尝试、每主题最多2次、每账号每日最多2次回复提交。生成与提交分别持久化记账；生成费用未知不自动再试。
4. 回复必须依据原帖，保存可核对的原文依据。检查20–800字长度、网址/导流、互赞互关、通用套话、无依据经历和复制片段。规则检查不能替代人工审阅，也不承诺已验证所有外部事实。
5. 草稿可编辑，按窗口、空间与草稿隔离恢复；修改后必须“保存并检查”，再明确“提交回复”。版本冲突保留本地未保存内容。界面不会在异步完成后重新打开已关闭的弹窗。
6. 同一账号的签到和回复共用至少60秒真实提交间隔。账号、UID、环境版本、暂停、目标范围、草稿版本及正文均在提交检查点重新校验；先持久化，再点击一次官网普通回复控件。已有本人参与则跳过新增回复。
7. 只有官网楼层的作者、主题、正文、真实PID及链接一致才记作核实成功。提交后异常保留“结果未知”，同号后续写入停止；核对只读原帖及官网尾页，不再次提交正文。验证码或频繁提示保留具体原因，不自动处理验证。
8. 重启、退出及备份恢复不重放付费或发言。未解决记录及关联候选始终保留恢复入口，已结束历史展示上限300条不截断未知记录。重新登录后需显式重新发现、读取与检查原稿。

## 自动回帖批次

“自动回帖批次”默认收起、关闭。保存目标与模式后明确开启，按北京时间建立两小时窗口；目标支持未暂停的观察吧或关注同步吧。推荐模式只准备草稿，每日所有目标合计准备1条，可调整为最多2条；“自动提交回复”是单独明确的运行模式。开启前直接展示当前文案模型、全局AI费用预算及发布范围，表单不恢复开启确认。

- 流程按发现→完整读取→生成→提交分步持久化，复用单条回复服务的去重、规则、AI预算、官网控件及回执，不新增绕过检查的发布路径。45分钟槽位分散主题准备；并非每个贴吧各生成2条。
- 每一步以及AI请求前、官网最终提交检查点重检总开关、批次、配置修订、业务日、截止、原UID与环境版本、目标暂停和原稿版本。保存新配置、应用预设、关闭或重启都撤销自动执行意图，付费返回的正文保留为待审原稿。
- 同日关闭再开启不延长旧窗口、清空已发生的尝试或重建已结束任务；跨日和过期不集中追赶。电脑或应用关闭期间不执行。
- 未知生成费用、未知回复、待检查记录不自动再试。自动批次的核对入口复用原回复只读核对，只核对原稿，不能借重建任务再次发出。
- 签到、回复和主题共享最近真实变更意图的至少60秒间隔。同账号回复/主题的未知提交与主题审核中阻断后续写入，最后点击前仍需重检。签到未知按其原有北京时间业务日处理，昨日未知不冒用今日签到读数核实。

## 主题与图文创作

“主题与图文”支持选择目标新建草稿，在同一编辑器切换标题正文与图片、本人材料与引用、本吧发布规则。草稿可先保存未完成内容；只有资料、规则、正文及图片检查通过才进入待提交状态。保存与刷新恢复编辑内容，但不恢复资料使用权确认。

1. 来源可选择本人材料或已获许可素材，保存标题、原始正文、使用依据及许可来源网址；材料及规则只作为不可信输入，不能改变生成任务、预算或执行权限。每吧规则独立版本，变更后原稿重新保存检查。
2. 手动正文及AI草稿均可编辑。AI只依据已提供材料、吧规及图片文件名，不声称看过未输入图像；生成保留原文依据，不编造亲历、职业或效果。每稿最多2次生成尝试，主题生成每日最多4次，均受公共AI费用预算约束。
3. 标题3–30字，正文80–10000字，最多6张小于10MB的本地PNG/JPG。图片使用现有内容附件存储，持久化SHA256与原名，读取检查原文件指纹；不新增远程图片下载或未经选择的上传。复制正文跨账号重复发布会被阻断。
4. 官网主题发布前验证唯一空标题、普通编辑器与按钮，保留既有官网草稿；不使用投票、付费主题、自动分享或签名附加内容。已保留AI正文的稿件若官网提供内容声明，选择准确“贴子含AI内容”，不声明原创；有入口却不能核实状态则停止。
5. 图片使用真实官方入口：工具栏图片→本地上传→免费无水印→下一步→原生文件选择。原生input可不在DOM树中，需捕获当前官方页面的filechooser；逐张上传，以唯一新增官网图片URL绑定本地SHA，不能按并发完成顺序猜对应关系，不点网络图片或付费水印。
6. 上传前持久化原始提交检查点，上传每张及最终发布前复验身份、环境、暂停、版本、正文与吧规；内部记录最近变更意图供所有贴吧动作共用间隔，长上传不会让后续提交绕过60秒。每账号每日最多1次主题提交尝试，未知尝试也计入。
7. 官网准确主题、首帖PID、作者、标题、完整正文和图片证据一致才记核实。官网明确的审核提示单独保存为审核中；上传或发表后异常仅可核对，不能重复上传/发表。未知TID时只读查找本人当前主题，须有可解析的官网创建时间，历史同文或缺时间不能冒充本次回执。
8. 同UID重新登录后可在当前环境只读核对原提交，旧提交stamp保留作审计，不要求用户恢复旧版本；换UID不能读取或接管原稿。备份与重启保留未知及有费用正文，撤销待提交资格和自动授权。

## 运营复盘与预设

“运营复盘”分为等级与经验、发布可见性、策略建议。展开只读本地快照；勾选最多5个目标或发布记录后明确刷新官网。读取等级不会顺带查询未选发布记录，读取发布记录也不会扩大到其他目标。部分失败显式反馈，保留原数据及原因。

- 每次官网实际读数保存历史，未知等级/经验保持未知，差值来自同UID与贴吧的历史读数。没有可比记录时不展示虚构增量，也不把操作次数当经验。
- 提交状态与当前可见性分列。可见必须匹配原作者、主题、楼层和完整可见正文；缺失、折叠、验证码或HTTP异常不推断为删除/限流。审核中要求准确本人主题的官网提示，用户正文提及“审核”不是证据。
- “延后复查可见性”默认关闭。开启后分别在提交后10分钟与24小时安排独立只读复查，每个时段有两小时执行窗口。排队中关闭、改配置、暂时停表或窗口过期都会停止旧授权；错过或失败仅消耗当次时段，不吞掉后续独立时段，也不追赶读取。
- 复查失败保留上一条确定官网证据与原读取时间，另记本次失败原因；没有真实读取时不伪造读取时间。无主题ID的未知提交保留在列表，指向原主题草稿核对，不自动猜链接或重发。
- 建议仅提供原结果核实、补读及低频/标准草稿预设。应用只把自动回帖调整为草稿模式、每日1或2条，保留原目标并关闭自动意图；不增加发言授权、不自动开启。自动复查意图在备份恢复时撤销。

## 观察吧接入与签到范围

“目标贴吧 → 添加观察吧”内置下列首批5个候选，首次打开默认勾选，已有草稿优先。选择账号后点击“读取并加入观察”，只读取官网并保存本地记录；可以取消预设，或每行输入一个吧名/官方HTTPS首页链接，每次最多5个。链接只接受准确的贴吧官方域名、首页路径和一个`kw`，后端仅接受规范吧名并重新核实。

- 官网返回的名称、真实FID、身份、环境版本和读取时间必须一致，缺少的等级/经验/签到字段仍为未知；静态预设不固化FID，也不声称本次已计算活跃度。
- 新增记录标记为“观察”，不关注、不选中签到、不创建签到任务。后端保存、开启、排期与提交检查均拒绝观察记录用于签到；帖子发现、上下文及显式草稿流程可正常使用。
- 在官网自行关注后，“同步关注吧”将同一记录升级为“关注同步”来源，沿用ID、暂停和历史，仍不自动选中。旧版本未保存来源的记录按关注同步兼容。空关注列表不会暂停观察记录。
- 每个吧单独返回成功与失败。部分失败保留已保存记录，表单剔除本次成功项、保留失败原名/链接，重试只请求剩余项；登录、身份、环境或验证异常中止后续读取，未执行项显示原因。
- 已在列表的吧可显式重新勾选读取，更新原记录而不重复新增，用于重新登录后的环境核验。网络返回不得覆盖其他窗口刚保存的暂停状态。
- 输入与打开状态按窗口、空间及账号恢复。切账号或关闭弹窗后，旧异步完成不会覆盖新账号输入或重开弹窗。加入观察本身不授予付费生成或发言权限；后续动作仍按原有显式流程触发。
