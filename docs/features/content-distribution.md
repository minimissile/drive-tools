# 内容分发

入口：侧栏 → 内容分发。每个平台有自己的“准备链接”“自动分发”和暂停操作，分发整个资源库中的全部已就绪本人分享，不需要勾选资源，也不提供跨平台批量分发。来源链接不纳入，不自动转存或创建分享。

## 使用

1. 选择平台，点击“准备链接”。系统从数据库分段扫描全部资源副本与拆分分享，保存当前平台的去重队列，并检查官网表单与登录状态。无需把数千条数据加载到界面后再挑选。
2. 需要登录的平台点击“登录平台”，自行在官方窗口登录，然后重新准备。盘库吧规则尚未核实，因此可以建立全库队列，但不会启用自动分发。
3. 准备好后，点击该平台的“自动分发”即可开始，不需要额外勾选或二次确认。
4. 后端按批读取资源库已保存的本人分享链接及本地加密保存的提取码，填写官方投稿表单、触发官方提交并读取回执，不重新联网核验网盘分享或查询有效期。每批最多 100 条，且受平台单批条数、字符数与每日限额约束；易搜每批 1 条，等对应链接处理完毕再继续。皮卡搜索自动填好一批链接后显示“待人工打码”：在官网窗口输入验证码，再回工作台点击“提交本批”，一批链接共用这一次验证码。批次间隔 5 秒。
5. 平台分别显示已提交进度、待分发、等待收录、已收录和需处理数量。需要核对结果时可直接筛出对应记录；切换页面不停止后台队列。
6. 可以暂停并继续。已经发出的请求等待回执，未发送的记录留在队列。结果未知会阻止继续分发，先在同一平台官网查询，然后在逐条记录中核对结果；只有明确失败的记录可显式重新入队。
7. 新增资源或修复本人分享后，再次“准备链接”增量入队。已提交链接不会重复发送。扫描保存当前数据上界；扫描中新增的分享留到下一次准备处理。

准备阶段只按已入库的本人分享记录建立本地队列，并检查目标平台官网的表单与登录状态。自动分发直接使用入库数据，不调用 `copy.link`、`split.link` 或网盘分享核验接口，也不修改原分享的核验时间或状态。尚未形成可分发分享的资源在左侧资源库概况中提示。

## 页面与交互（2026-11-05）

- 去掉内容分发页顶部标题与长说明，左侧平台列表和右侧内容分别滚动；右侧长记录不会带走平台入口。切换平台返回该平台操作区。
- 首屏保留当前平台、提交进度、必要状态和准备 / 自动分发 / 暂停等操作；平台登录与官网入口直接可见，打码时显示继续提交与验证码窗口入口。
- 默认查看“分发记录”，通过公共标签页切换“投稿须知”和“提交历史”。内部资源 / 分享 / 分发 / 批次 ID、域名、研究日期、单批参数和滚动计数不再直接展示；真实平台规则在投稿须知中保留。
- 列表优先显示资源名称、网盘、时间及状态，链接、详细过程与平台回执按需展开。后台轮询保留当前内容，避免加载提示使列表反复跳动。
- 当前平台、标签、关键词、状态筛选和页码按工作空间、窗口暂存；平台备注沿用本地草稿。原有队列、ID 关联、数据库分页和分发行为保持一致。

## ID 与数据关联

现有模型已经有稳定主键，无需用标题或行号标识：

| 数据 | 现有本地主键 | 分发中的用途 |
| --- | --- | --- |
| 资源 | `resources.id` | `resourceId`，关联资源库的原资源 |
| 本人资源副本 / 分享记录 | `copies.id` | `copyId`；记录键为 `copy:<copyId>` |
| 拆分分享 | `split_items.id` | `splitItemId`；记录键为 `split:<splitItemId>`，同时关联所属 `copyId` 和 `resourceId` |
| 网盘侧分享 | `share_id`、规范化网盘类型 + 分享 ID | 平台内按实际分享去重；本地记录 ID 与网盘分享 ID 分别保存 |
| 分发记录 | `distribution_tasks.id` | 当前平台这一条链接的生命周期 |
| 提交批次 | `distribution_batches.id` | 关联本批链接与官方回执 |

一个资源的不同本人分享分别入队。重复记录若指向同一个网盘分享，只发送一条规范化链接，但通过 `distribution_task_sources` 保留全部资源 ID 与分享记录 ID 的关联，不丢失来源。

本地分享记录 ID、链接及版本在组批和提交检查点保持一致，避免等待打码期间资源库已换链却提交旧内容；这些检查只读取本地数据库，不重新访问网盘。分享地址变化后保留旧分发快照及历史关联，新的链接在重新准备时增量入队。尚未提交而被替换的旧链接标为“旧链接已替换”，重新出现时可恢复待分发。热盘搜与易搜会在批次内和历史已接收记录中按资源 ID 检查整份资源的重复链接，跳过同资源的其他链接变体；不同拆分子项仍分别处理。待核对的旧提交不允许通过换链接绕过。

## 数千条数据的存储与读取

- SQLite 分表保存分发记录、资源与分享关联、批次、批次成员、事件、提交尝试与平台运行状态，不将整个资源库或不断增长的历史塞进单个 JSON / localStorage。
- 扫描按 SQLite rowid 游标每次最多 250 条，持久化扫描游标和本轮数据上界；每段事务完成后让出事件循环。扫描可恢复，不依赖前端快照原有的条数上限。
- 按“平台 + 规范化分享 key”唯一去重，同一“平台 + 分享记录 ID”只保留一个活动关联，并保留历次关联快照。平台、状态、资源 ID、提交时间、接收时间和逐条历史有相应索引。
- 执行每次最多读取 100 条待分发记录；提交前保存批次与检查点，回执和逐条结果在事务中提交。批次成员只保留实际发送的记录，本地资料不可用与字数延后的记录不归入成功批次。
- 记录、批次及逐条事件都在数据库分页，每页 20 条；历史按需展开读取，进度由 SQL 聚合，前端只轮询本地读取，不轮询付费或远端写入接口。
- 旧辅助投稿记录迁移为规范化数据，保留既有 ID、回执和事件。数据库迁移前保存本机快照；旧版 JSON 记录按游标迁移，不整库装入内存。

这是数据结构与分批读取的实现范围，本轮未进行数千条负载测试，不将此描述当作性能基准。

## 状态与恢复

- “已提交”仅在取得与当前链接匹配的官方成功结果后登记：爱搜与热盘搜观察对应请求及可识别回执；易搜等待官网逐条结果卡片及表单恢复空闲；皮卡搜索观察与本批多行正文匹配的官方请求和整批成功回执。HTTP 2xx 或开始处理时的成功提示本身不算成功。
- 提交进度按曾取得明确接收结果的去重链接计数，后续审核未通过不会把历史提交进度倒退。未提交的旧链接与规则跳过项不进入有效队列分母，单独展示跳过数与历史记录数；当前处理、审核与失败状态分别展示。已提交与已收录分开。
- 官网提交按钮点击前先存 `submitting` 检查点。超时、崩溃、窗口关闭或未知回执不能自动重试，记录为结果待核对。
- 启动时将中断的准备项、旧版核验项及未提交的人工打码批次恢复为待分发，将中断的提交项恢复为待核对；程序重启不会自行开始投稿，需要重新准备并点击启动。
- 暂停发生在请求发出前则不提交；请求已经发出时等待回执，再保留当前结果并停止下一批。
- 近 24 小时提交次数按独立提交尝试表累计，明确失败重投也另计一次。每日重置时区不明时使用保守的滚动 24 小时本地计数；不能替代官网实际剩余额度。
- 同一平台官网登录会话按工作空间隔离，无需账号池；密码由用户在官网输入，不写入分发记录。遇登录失效或验证要求暂停，不自动处理验证码。
- 活动队列、官网操作窗口及隐藏提交窗口阻止开发后端安全重启、更新和工作空间切换。
