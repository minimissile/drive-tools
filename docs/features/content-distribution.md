# 内容分发

入口：侧栏 → 内容分发。每个平台有自己的“准备全库链接”“自动分发”和暂停操作，分发整个资源库中的全部已就绪本人分享，不需要勾选资源，也不提供跨平台批量分发。来源链接不纳入，不自动转存或创建分享。

## 使用

1. 选择平台，点击“准备全库链接”。系统从数据库分段扫描全部资源副本与拆分分享，保存当前平台的去重队列，并检查官网表单与登录状态。无需把数千条数据加载到界面后再挑选。
2. 需要登录的平台点击“打开登录页”，自行在官方窗口登录，然后重新准备。盘库吧规则尚未核实，因此可以建立全库队列，但不会启用自动分发。
3. 准备好后，确认这些本人分享可公开并同意提交到当前平台，点击该平台的“自动分发”。确认只适用于本次启动，不随草稿或程序重启恢复。
4. 后端按批实时核验本人分享、填写官方投稿表单、触发官方提交并读取回执。每批最多 100 条，且受平台单批条数、字符数与每日限额约束；易搜每批 1 条，等对应链接处理完毕再继续。皮卡搜索自动填好一批链接后显示“待人工打码”：在官网窗口输入验证码，再回工作台点击“提交本批”，一批链接共用这一次验证码。批次间隔 5 秒。
5. 平台分别显示已提交 / 去重总链接数、关联资源数、待分发、核验与提交中、处理中、待审核、已收录、失败、分享未就绪和结果待核对。切换页面不停止后台队列。
6. 可以暂停并继续。已经发出的请求等待回执，未发送的记录留在队列。结果未知会阻止继续分发，先在同一平台官网查询，然后在逐条记录中核对结果；只有明确失败的记录可显式重新入队。
7. 新增资源或修复本人分享后，再次“准备全库链接”增量入队。已提交链接不会重复发送。扫描保存当前数据上界；扫描中新增的分享留到下一次准备处理。

全库扫描和分享核验是不同阶段：准备先检查本地资料是否就绪；只有点击自动分发后才逐条执行实时分享核验和远端投稿。尚未形成可分发分享的资源在顶部单独统计。

## ID 与数据关联

现有模型已经有稳定主键，无需用标题或行号标识：

| 数据 | 现有本地主键 | 分发中的用途 |
| --- | --- | --- |
| 资源 | `resources.id` | `resourceId`，关联资源库的原资源 |
| 本人资源副本 / 分享记录 | `copies.id` | `copyId`；记录键为 `copy:<copyId>` |
| 拆分分享 | `split_items.id` | `splitItemId`；记录键为 `split:<splitItemId>`，同时关联所属 `copyId` 和 `resourceId` |
| 网盘侧分享 | `share_id`、规范化网盘类型 + 分享 ID | 平台内按实际分享去重；本地记录 ID 与网盘分享 ID 分别保存 |
| 分发记录 | `distribution_tasks.id` | 当前平台这一条链接的生命周期 |
| 提交批次 | `distribution_batches.id` | 关联本批链接与官方回执 |

一个资源的不同本人分享分别入队。重复记录若指向同一个网盘分享，只发送一条规范化链接，但通过 `distribution_task_sources` 保留全部资源 ID 与分享记录 ID 的关联，不丢失来源。

分享版本在核验前、核验后和提交检查点再次检查。分享地址变化后保留旧分发快照及历史关联，新的链接在重新准备时增量入队。尚未提交而被替换的旧链接标为“旧链接已替换”，重新出现时可恢复待分发。热盘搜与易搜会在批次内和历史已接收记录中按资源 ID 检查整份资源的重复链接，跳过同资源的其他链接变体；不同拆分子项仍分别处理。待核对的旧提交不允许通过换链接绕过。

## 数千条数据的存储与读取

- SQLite 分表保存分发记录、资源与分享关联、批次、批次成员、事件、提交尝试与平台运行状态，不将整个资源库或不断增长的历史塞进单个 JSON / localStorage。
- 扫描按 SQLite rowid 游标每次最多 250 条，持久化扫描游标和本轮数据上界；每段事务完成后让出事件循环。扫描可恢复，不依赖前端快照原有的条数上限。
- 按“平台 + 规范化分享 key”唯一去重，同一“平台 + 分享记录 ID”只保留一个活动关联，并保留历次关联快照。平台、状态、资源 ID、提交时间、接收时间和逐条历史有相应索引。
- 执行每次最多读取 100 条待分发记录；提交前保存批次与检查点，回执和逐条结果在事务中提交。批次成员只保留实际发送的记录，核验失败与字数延后的记录不归入成功批次。
- 记录、批次及逐条事件都在数据库分页，每页 20 条；历史按需展开读取，进度由 SQL 聚合，前端只轮询本地读取，不轮询付费或远端写入接口。
- 旧辅助投稿记录迁移为规范化数据，保留既有 ID、回执和事件。数据库迁移前保存本机快照；旧版 JSON 记录按游标迁移，不整库装入内存。

这是数据结构与分批读取的实现范围，本轮未进行数千条负载测试，不将此描述当作性能基准。

## 状态与恢复

- “已提交”仅在取得与当前链接匹配的官方成功结果后登记：爱搜与热盘搜观察对应请求及可识别回执；易搜等待官网逐条结果卡片及表单恢复空闲；皮卡搜索观察与本批多行正文匹配的官方请求和整批成功回执。HTTP 2xx 或开始处理时的成功提示本身不算成功。
- 提交进度按曾取得明确接收结果的去重链接计数，后续审核未通过不会把历史提交进度倒退。未提交的旧链接与规则跳过项不进入有效队列分母，单独展示跳过数与历史记录数；当前处理、审核与失败状态分别展示。已提交与已收录分开。
- 官网提交按钮点击前先存 `submitting` 检查点。超时、崩溃、窗口关闭或未知回执不能自动重试，记录为结果待核对。
- 启动时将中断的核验项、未提交的人工打码批次恢复为待分发，将中断的提交项恢复为待核对；程序重启不会自行开始投稿，需要重新准备并点击启动。
- 暂停发生在请求发出前则不提交；请求已经发出时等待回执，再保留当前结果并停止下一批。
- 近 24 小时提交次数按独立提交尝试表累计，明确失败重投也另计一次。每日重置时区不明时使用保守的滚动 24 小时本地计数；不能替代官网实际剩余额度。
- 同一平台官网登录会话按工作空间隔离，无需账号池；密码由用户在官网输入，不写入分发记录。遇登录失效或验证要求暂停，不自动处理验证码。
- 活动队列、官网操作窗口及隐藏提交窗口阻止开发后端安全重启、更新和工作空间切换。

### 易搜接入（2026-10-31）

- 按用户更正，无需配置账号；未保存或使用本轮最初提供的登录凭据。沿用按工作空间和平台隔离的官方会话，无账号池。
- 官网已加载的公开脚本确认：提交按钮的开头成功提示出现在真正请求之前；页面随后逐条请求 `/api/member/share`，按返回 `data == 1` 展示成功卡片，每条间隔 3 秒。盘序通过官网按钮执行完整流程，不重建签名、不直接调用该接口、不读取框架私有状态。
- 本地每批仅 1 条、批次间隔 5 秒。仅当对应链接出现在成功卡片、输入区已清空且表单恢复空闲时记为已提交。明确业务失败停止；服务器异常、超时或页面变化视为未知结果，保留实际官网页，打开“投稿页”核对后关闭；不自动重投。
- 易搜有单投稿页限制，手动官网窗口打开时不会另起隐藏投稿页。正常处理结束后通过官网首页导航触发网站自己的卸载清理，再释放窗口；未知处理保留原页，避免中途关闭影响请求。
- 不在易搜支持范围内的网盘记为规则跳过；永久有效性在现有本人分享核验后，再只读核实原分享设置。有限期或信息不足保留未就绪，不改原链接、不创建新分享。资源库尚未接入阿里云盘，因此当前发送夸克、百度、迅雷。
- 新平台复用现有分发表、唯一约束、资源与分享 ID、索引和数据库分页，无需新的数据库结构迁移；不改写原资源内容与分享 ID。

### 皮卡搜索批量投稿与人工打码（2026-10-31）

- 官网 textarea 明确写“多个链接请换行”，公开脚本把整段 `content` 与一个 `captcha` 一起 POST 到 `/share-feedback/`。这证明前端支持批量整批提交；官网没有公开或在表单声明数量、字数和每日上限，未以真实投稿探测服务器上限。盘序本地每批最多100条，并沿用本地字符防护。
- 每批进入“待人工打码”后显示同一个官方窗口，链接只读，验证码由用户在官网输入。工作台提供“打开验证码窗口”“提交本批”和暂停；官网按钮保持禁用，只有工作台校验当前批次并写好提交检查点后，才触发一次官方按钮。验证码不经 IPC 传回、不写入数据库或草稿，也不自动识别。
- 回执只匹配当前整批正文对应的官方 POST。盘序仅将 HTTP 2xx 且 `code` 为非负安全整数的回执记为整批接受；官网负数回执表示拒绝，`code=-403` 明确表示验证码错误并由官网刷新图片。仅此明确未接受的情况会将链接恢复待分发、以新批次记录新的尝试，再等待用户重新打码；不是自动重发验证码。其他业务拒绝停止，网络失败、未知结构、超时或提交后关闭窗口都保留待核对，不自动重投。
- 打码前暂停或关闭窗口不会发送本批链接；已点击提交后暂停等待本批回执，再停止下一批。重启后未发送的打码记录回到待分发，不恢复验证码或公开授权。等待人工打码与在途请求阻止后台安全重启或切换工作空间。
- 只处理官网列出的、当前资源库已接入的夸克和百度分享；其他网盘在本平台记为规则跳过。沿用稳定资源/分享ID、独立平台队列、批次和事件分页，不新增数据库结构迁移，不改原资源内容或分享ID。“已提交”只表示整批接受，逐条收录仍以官网为准。
