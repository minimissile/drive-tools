# 异常日志

入口：左侧“工作空间 → 异常日志”。默认查看最近 7 天的错误与警告，每 10 秒读取一次本地记录，可手动刷新、按来源模块、级别、时间与关键词筛选。每页 50 条，展开记录查看诊断，支持复制单条或本页详情；筛选按窗口和工作空间暂存，刷新失败保留已有内容。

统一视图复用 `runtime_logs` 中各业务已有的警告、错误，以及 `api_calls` 中失败、结果不明和“计费成功但返回内容校验失败”的调用。旧 AI 失败记录也能直接查询；同一调用已有关联操作异常时不重复显示 API 条目。日志读取不会触发 AI、微信请求或重发。

`AppService.invoke` 在失败时保留原始错误，并记录操作、错误码及有限的账号、任务标识，不记录提交表单、正文、密码或 Cookie。同一分钟的相同自动读取错误只记录一次，主动操作的每次失败分别留痕。日志页自身读取失败不递归记录，日志写入失败不替换原业务错误。新增操作记录复用工作空间 `logs/<模块>/日期.jsonl` 镜像和数据库持久化；既有 API 异常仍使用原调用账本，不制造历史业务事件。

文字生成失败时补充模型、调用编号、服务回执编号、服务方、标准与原生结束状态、输入/输出 token 数、返回字符数及耗时；公众号改写的异常还保留输出模式、失败环节、字段校验路径与重试次数。异常诊断不包含提示词、原始文章响应或凭据。完整性校验继续阻止截断内容覆盖原稿，费用按服务实际回执记录，不把计费成功当作文章生成成功；日志页面本身不会触发重试，公众号业务中的有限重试见[公众号草稿箱](wechat-drafts.md)。

媒体生成失败保留模型、调用编号、图片/视频类型、参考图或主题方式、HTTP 状态与脱敏后的服务原因。公众号批量生成会捕获单张错误并返回结果，因此在业务捕获处另行记录 `image.generation_failed`，避免只有 IPC 抛错才能进入日志；同一图片复用失败回执时只记录一次，未提交的后续位置不冒充实际调用。已关联日志的调用不重复显示账本条目。

2026-11-10 只读排查公众号改写：模型 `qwen/qwen3.8-max-0902` 返回 `finish_reason=error`，保留的响应为未闭合 JSON。此次旧记录缺少原生结束原因和上游回执编号，无法据此进一步区分上游断连、模型故障或其他服务异常；新诊断会保留可用字段。提示已明确为生成过程中异常中断，并提示重试或更换文案模型；没有放宽原稿保护。

验收：72 项日志、IPC、AI 回执及公众号相关回归和 TypeScript 检查通过；1366×768 专属窗口通过侧边入口、首次加载、历史 AI 详情、脱敏复制、分页、全部筛选、空态、刷新失败恢复和筛选暂存检查，已查看关键截图。新日志读取逻辑以只读方式查到上述真实失败，未改写业务数据。界面测试仅在专属窗口使用隔离日志数据库和页面级业务传输，没有付费 AI 或远端写入。后端编译后仍需由用户点击“应用更新并重启”加载，未将旧后端界面测试冒充新后端联调。
