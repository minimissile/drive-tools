# 资源清单

## 目标与范围

资源库菜单下新增「资源清单」。运营者按资源库分类整理一份持续维护的目录，让访问者通过飞书、腾讯文档或石墨文档的分享链接直接查找资源。

本轮在当前源码中交付：清单创建、编辑与保存；全量分类聚合；有效本人分享筛选；公开内容预览；复制富文本与文件导出；关联其他账号中的文档平台登录；官方编辑器交接；发布链接与版本登记；本地变化比较；已有文档更新交接；归档维护。

## 可行性与发布方式

飞书开放平台的文档 API 需要应用权限与 access token；腾讯文档开放平台需独立授权；石墨官方 SDK 是企业集成体系。三个平台的网页登录均不等于开放接口授权。详细官方证据见 resource-catalog-platform-research.md。

首版采用适用于个人账号的辅助发布：生成清单 → 复制内容/导出文件 → 在关联账号的官方窗口创建或打开文档 → 用户粘贴/导入并设置可访问权限 → 回填分享链接并确认版本。界面明确标为「发布交接」和「登记发布」，打开窗口或复制成功不代表云端发布成功。不会调用未经核实的私有接口或自动改公开权限。开放 API 自动同步留给具备凭据的后续适配，网页登录不显示为自动发布授权。

## 数据与状态

- 清单保存标题、分类、介绍、展示选项、排序等本地配置，按工作空间隔离。
- 资源来源从数据库按分类读取全部资源，不能使用最多 500 条的首页快照；预览分页不限制导出总量。
- 对外内容只含已核实的本人分享及必要的访问说明；无分享、失效与未验证项给出排除提示。禁止导出来源地址、账号身份、内部路径和凭据。
- 交接时保存不可变快照。发布回执关联该快照，不能把交接后新增的资源算成已发布。
- 同一清单可分别维护多平台发布记录；每条记录含平台、关联账号、文档链接、登记版本与时间。
- 资源增加、删除、标题/简介/链接等公开内容改变后显示待更新；打开原文档交接，完成后再登记新版本。保留历史记录。
- 归档只影响本地维护状态，不删除远端文档。删除本地清单不暗示远端撤回。

## 界面与交互

沿用白色工作台、蓝色主操作、现有字体与紧凑桌面密度。主视图为清单索引与内容工作区；空态直接引导按分类创建。编辑配置和公开预览清楚分隔，发布维护与内容放在同一清单上下文。账号失效就近指向「账号管理 → 其他账号」。1366×768 与 1440×900 为本轮参考尺寸。

复用 Select、Dialog、Pagination、DataState/Empty/QueryError、公共焦点与 Toast 反馈。编辑暂存按工作空间与清单对象隔离，凭据和公开权限确认不恢复。异步读取错误保留现有内容，提交成功后刷新失败用警告提示，切页后异步结果不改变用户导航。

## 架构

shared/resource-catalog.ts 定义类型和规则；core/resource-catalog.ts 负责聚合、快照、比较与维护；core/ipc/resource-catalog.ts 校验传输参数；AppService 只组装依赖。前端通过 src/api/client.ts 调用，领域组件及 hooks 放在 src/resource-catalog。

文档平台登录扩展现有 WebsiteAccounts 和隔离浏览器环境，不新增第二套账号系统。文档地址须校验 HTTPS 与平台官方域名。身份检测保守处理，不能用存在 Cookie 冒充已核实用户身份。

## 验证与验收

按项目约定进行类型/源码检查与源码开发窗口手动操作验证，不运行自动化测试或脚本化截图回归。使用本地模拟传输验证首次读取、空态、创建编辑、长内容、预览分页、导出交接、链接登记、差异维护与错误恢复；不真实远端发布、不付费、不新建第二个桌面实例。实际账号登录和云端分享可访问性取决于用户平台账号与权限，在验收说明中明确实测边界。
