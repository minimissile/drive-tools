# 百度网盘比特后台环境

更新：2026-10-31。已接入当前开发源码，未提升版本或制作安装包。

创建百度网盘账号时选择内置浏览器或已登录的比特浏览器配置，保存后固定使用该方式及配置。已有账号保留当前方式。指纹账号的目录查看、文件增删改查、广告文件上传与清理、转存、本人分享及分享统计，统一通过该配置的浏览器页面发起请求。登录信息留在比特配置中，不复制 Cookie 到内置会话。内置百度账号及其他网盘继续使用原方式。

## 关联方式

1. 在“连接与设置”配置本机比特 Local API 地址和所需的 API Key，保持比特客户端运行。
2. 在比特配置中完成百度网盘登录。按用户确认，此配置可供百度网盘、贴吧和知道共用，同平台仍只允许一条账号关系；其他平台及独立发布映射不能加入。
3. 在“账号管理 → 网盘账号 → 新增账号”选择百度，填写别名，将“浏览器方式”选为“比特指纹浏览器”。选择内置方式时可直接添加，再在独立内置窗口登录。
4. 点击“读取比特环境”，选择空闲配置或仅关联贴吧、知道的配置。默认要求代理；需要 IP 隔离时，在比特配置代理并开启网络异常停止打开。关闭每次启动随机指纹、启动清理 Cookie 以及打开时动态换 IP。
5. 点击“读取登录账号”，核对实际百度 UID、昵称、出口 IP 和运行状态。同一 UID 不能创建为另一条百度账号记录。读取失败不创建账号；读取结果十分钟有效，不进入表单暂存。
6. 点击“添加账号”。创建前会再次核对 UID、出口及配置。创建后不能切换浏览器或改绑其他配置。如果比特可见窗口仍开着，在管理弹窗点击“转为后台运行”，保存未提交内容后确认“关闭窗口并转为后台”，再点击“核验后台登录”。也可以自行关闭整个比特环境后核验。普通读取和创建不会自动关闭已有人工窗口。

环境原本已关闭时，盘序通过比特 Local API 以无头参数启动，检查实际浏览器启动参数后执行。日常不显示浏览器窗口，但仍有浏览器后台进程，不能退出比特客户端。绑定仅保存本地环境关系与身份记录，不自动进行文件修改、转存或建链。

## 后续使用与恢复

- 网盘文件及分享操作仍在盘序原界面触发。请求使用同一比特配置的 Cookie、页面上下文、代理及设备指纹；不是将 User-Agent 或 Cookie 拼接到本机 HTTP 请求。
- 每次请求在环境租约中核对配置、实际出口与百度 UID。要求代理时检查代理配置和网络异常停止策略；比特不可用、可见窗口未关闭、身份或出口变化、无法确认无头模式时停止，保留错误，不切回内置网络。
- 需要重新登录或人工验证时，在账号关联弹窗点击“打开登录窗口”。仅尝试关闭盘序启动并确认归属的无头进程，再打开官方页面；其他程序的无头进程要求先手动关闭。完成登录后关闭比特环境，再核验后台登录。
- 共用的贴吧、知道通过同一环境租约与无头模式执行日常请求。新增指纹账号先关联并检查已有登录，不自动切换可见窗口。显式打开任一共用业务的登录、资格或问题窗口时，先检查所有共用业务占用，再关闭工具自己的后台进程并切为可见模式；旧准备结果随运行环境修订失效。完成后在网盘管理转为后台，再分别核验平台身份。不同平台的 UID 分别保存和核对，不直接比较或互相继承权限。
- 同一环境的代理、指纹或出口变化后，在管理弹窗“读取当前环境信息”，核对原 UID 后“更新当前环境核验”。不能选择其他配置或连接器地址。预览十分钟有效，确认时再次核对，不能重复使用。
- 当前可见窗口没有自动化标记时，调试协议无法返回启动参数。运行方式检查兼容读取对应本机进程，只接受所选配置 ID、进程、调试端口及浏览器端点相匹配的结果；启动端口为 0 时读取该配置的调试端口记录。只保留无头与启动归属状态，不向前端返回进程命令行或路径。无法确认时继续停止，不推测无头状态。
- 账号清理会清理工具中的核验并停用账号，保留创建时的浏览器与配置选择；再次启用仍需使用原环境。删除账号清理本地记录。两者均保留比特中的 Cookie 和网盘文件；后台进程未能关闭时由比特客户端手动关闭。
- 更新同一环境的核验会撤销相关本人分享的本地核验与发布审核。存在执行中任务或文件、分享、广告插入结果待核对时，先处理原操作。共享工作台使用同一账号互斥锁和环境租约。

IP 隔离依赖代理服务及比特实际配置，不为未配置代理的环境提供独立出口承诺。浏览器内核、指纹效果和平台风控仍由比特与百度决定。上传请求遵循浏览器跨域规则；不关闭浏览器安全策略，失败不回退本机上传。

自定义 SOCKS5 / HTTP 代理可能保留未启用的“每次打开提取新 IP”开关值。只有代理模式为“提取 IP”（`proxyMethod=3`）且该开关开启时才按启动换 IP 处理；自定义代理不因这个残留值被拦截。仍按实际出口进行核验。缺少代理与未开启“网络不通停止打开”分别给出对应提示。

## 实现与检查范围

核心路径为 `core/drive-browser-sessions.ts`、`core/bitbrowser.ts`、`core/browser-environments.ts` 及 `desktop/main.ts` 的网盘传输路由。复用现有百度提供器、文件管理和上传逻辑；前端入口位于 `src/accounts/DriveBrowserDialog.tsx`，使用类型化领域 IPC。

本轮进行 TypeScript 与源码差异检查，并复用现有开发后台创建独立会话窗口，手动查看 1320×900 逻辑尺寸的实际账号页、关联弹窗及比特未配置时的错误与重试入口。当前工作空间未配置比特 Local API 地址，未实际关联或更改真实账号、读取登录 Cookie、启动比特配置、执行网盘写入或查询真实分享统计。无头启动、真实代理出口、登录保持及百度跨域上传仍待配置可用环境后的联调；未运行自动化测试。

后续按用户报错只读核对序号 1 的实际比特配置，确认其为自定义 SOCKS5 代理，但带有提取 IP 的残留开关，修复这一误判。同时确认该环境尚未开启网络不通停止打开；未修改比特配置，未启动或绑定环境。初次检查与本次只读诊断的范围分别保留，均未执行网盘写入。

修复后在独立源码会话中手动选择同一个环境并点击“读取登录账号”，确认原自动换 IP 误报消失，实际显示“已配置代理，但未开启网络不通停止打开”的针对性提示，检查在启动浏览器前结束。TypeScript 和差异检查通过，未运行自动化测试；本轮检查窗口已关闭。

后续按用户要求继续真实联调：为所选比特配置开启网络不通停止打开，并只读核对代理地址、凭据和指纹配置未变。发现原 ipify 探测站在此代理下连接被关闭，改为在同一浏览器上下文中使用 IPIP 与 ipify 备用探测，两个来源均失败仍停止。实际读取百度 UID、昵称及出口成功，并保存到原账号记录；没有复制 Cookie。读取失败改为关联弹窗内保留单处恢复提示。

在当前源码独立窗口手动执行新增的后台切换操作，确认指定环境关闭后重新启动；本机进程标记核对为无头且由盘序发起。该比特内核未保留自动化标记，实际走进程及调试端点对应检查成功。前端查看了关联信息、切换前的范围提示和切换后的状态；TypeScript 与差异检查通过。独立窗口保留供用户继续核验。

此前直接查看比特网页时，电脑操作工具因 URL 限制终止会话。后续只在本机工具中查看界面、操作环境运行方式和检查进程元数据，没有改换工具读取受限网页。本阶段仍未验收后台真实目录、上传、重命名、删除、广告替换和分享统计，也未进行网盘写入；不能把后台进程启动成功视为这些流程通过。
