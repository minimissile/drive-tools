# 知乎日常参与与自主任务补全

日期：2026-11-03。用户要求补全现有仅以发文为主的养号流程。本轮先确定实现与复用边界，再开发。

2026-11-04更新：用户明确个人账号辅助用途并授权正常相关互动自主执行；新版独立权限、执行、未来排期及真实回执说明见[个人账号自主参与](zhihu-personal-interaction.md)。以下保留11月3日当轮边界与实际验证历史，不代表新版仍仅支持人工处理。

## 现有能力与新增范围

现有知乎领域已经具备账号环境队列、UID核验、文章/回答稿、准确版本审核、原任务去重、同出口错峰及发布回执。现有原生智能体能读取进度、检查库存、创建文章和安排已审核内容，尚无找题、读取讨论、评论建议或相关作者发现工具。

新增独立「日常参与」领域，服务知乎工作台及统一运营计划。复用原账号队列读取官方可见页面：发现相关问题/作者 → 保存账号隔离候选 → 读取完整上下文快照 → 安排参与任务 → 准备待审回答稿。每个任务保留目标、理由、计划时间、内容版本、依据与处理记录，智能体能看见这些真实状态并决定下一步。

点赞、评论和关注提供有上下文的候选、评论草稿及逐项人工处理入口，不建设互关增粉、双号互赞互评或模板评论执行器。打开页面不等于已阅读、已点赞或已关注；本人确认的处理记录明确标注为本人记录，不当作官方执行回执。相关作者发现不承诺对方会回关。

## 模块职责与流程

- `shared/zhihu-participation.ts`：候选、快照、任务、来源URL与IPC类型，避免前后端各自解释状态。
- `core/zhihu-participation/`：账号隔离、持久化、去重、版本校验、读取与任务工作流；通过已有`WebsiteAccounts.use`租约和专用浏览器端口读取，不绕过验证、限流或平台限制。
- 浏览器端读取官方页面上实际可见的搜索结果和正文，必要时仅展开当前目标的唯一“显示全部/阅读全文”控件；不点击登录、付费或互动控件。限定临时页、条数、正文大小与官方URL；结构无法识别和真正无结果分别处理。
- 原生决策层增加发现、上下文读取、参与计划和回答准备工具。读取受当前计划账号及read权限约束；本地回答创建要求create权限。第三方页面是资料，不能作为系统指令。模型不能把参与任务标记为本人已完成。
- 回答准备直接复用知乎素材池，绑定原账号及问题URL，初始未审核且保留AI参与与依据。重复请求返回原稿，不重复创建；审核与发布继续走原有准确版本和原任务检查，不由新领域直接提交。
- 前端「日常参与」展示候选、上下文、待办与编辑；复用公共选择器、分页、读取状态和表单暂存。网络读取只在显式动作或已授权的原生决策工具中发生，本地轮询不会发起付费采集或生成。

## 状态与记录

候选去重键为账号与规范化官方URL；正文快照带采集时间和版本。参与任务区分已计划、待审阅、已准备回答、本人已处理和不采用。未处理失败保留已有快照，提供重试；草稿变化需要按新版本再次确认。候选与任务有容量上限，不静默删除历史。

日志复用`RuntimeLog`，独立领域`zhihu-participation`，记录发现、上下文、任务、回答交付与本人记录；不存凭据、不把候选数量记成互动完成数量。决策轮次继续在智能运营中保留具名工具和实际费用。

## 兼容与验收

现有7、8号Lv.5计划及11月4日09:00/10:00两篇原排期保留，不借本次开发增加额度、重发旧稿或自动扩大互动范围。源码安全重启后核对原任务、身份、审核版本和费用状态，再按已有授权恢复原范围。

验收覆盖账号隔离、规范URL与错误恢复、精确版本、候选/任务去重、未审核回答交付、当前授权失效后停止写入、人工记录不冒充平台回执，以及1440×900实际工作台上的列表密度和主操作可达性。真实远端点赞、评论、关注不属于验收操作。

## 实施结果

已接通独立后端、类型IPC、只读浏览器端口、四个原生决策工具和两处工作台入口；右下角「自主计划」新增当前计划的参与待办数量与跳转。配置中的创建权限明确包含待审回答，自动自审权限仍独立控制；参与回答不进入模型自产稿的自动自审来源。

持久化记录与备份恢复保留候选、上下文和任务历史，恢复时清除查询缓存，不自动发起读取或互动。局部历史无法解析时在领域读取中报错，不阻塞整个工作空间启动或静默覆盖原记录。新回答稿的账号绑定在普通编辑时继续保留，AI参与不会因人工编辑被清掉。
