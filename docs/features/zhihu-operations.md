# 知乎多账号养号与内容发布

设计日期：2026-10-26。实施顺序：先完成本文的需求与复用设计，再实现领域服务、浏览器适配、界面和模拟验收。

## 文章理解

来源：[网盘拉新百问百答 / 知乎相关问题](https://my.feishu.cn/docx/MmEgd9neyo4rvjxe8ndcjeQgnlb#ECsVdJ3Ihoex51xdKqjcP3JBn7c)。已通过现有 Chrome 阅读知乎部分的 13 条问答。以下属于作者的运营经验，不等同于知乎当前规则或效果保证。

| 文章主题 | 产品中的落实 |
| --- | --- |
| 同 IP 多号 | 每个知乎身份绑定独立比特配置；显示出口 IP，默认按同出口至少间隔 60 分钟排队。作者建议每 IP 2–3 号，作为容量提醒，不作为防封承诺。 |
| 升级耗时、养号内容 | 以真实创作者等级为进度，目标默认五级；素材池支持文案、句子、知识内容及图片。升级时间受质量影响，不按使用天数伪造等级。 |
| 养号目标 | 未到目标等级使用无推广内容；达到目标后暂停养号计划，转入正常内容运营。 |
| 阅读量慢热 | 保留发布记录、回执与等级检查时间，避免因暂时无阅读量重复发布。 |
| 多号错峰、秒删 | 本地持久化排期，账号和同 IP 均设间隔；限额、验证、删帖和身份变化转人工处理，不自动切 IP 重发。 |
| 定时发布 | 作者不建议使用平台定时。本项目采用本地调度器，到时使用官方编辑器即时提交；应用关闭期间不执行，重启需要明确重新启动计划。 |
| 创作者中心 | 记录是否入驻、等级与核验时间；入驻由本人完成，读取失败保持未知。 |
| 分数更新时间 | 作者提到次日更新；界面显示实际检查时间，不在发文后推算分数。 |
| AI 内容 | 每份内容记录 AI 辅助；自动提交需要官方编辑器具备可确认的标识状态，否则暂停。 |
| 同问题回答 | 同一账号、同一问题只允许一项未取消的回答任务，避免重复提交。 |
| 内容方向 | 素材分类独立于账号，不强制垂直领域。 |
| 热榜、互关 | 可由本人选题；不把批量互关作为自动养号步骤。 |
| 封号后内容留存 | 保存本地内容和回执，不保证远端内容仍可访问。 |

文章存在“发到平台限制”“大量发布”等经验描述；系统以可配置本地上限和平台实际限制为准。默认每天 3 篇、每周 15 篇，单账号及同 IP 最小间隔 60 分钟，均是本项目保守初始值，不冒充文章或官方规定。

## 数据和工作流

1. 在账号管理创建比特环境，将知乎账号关联到该环境，打开官方页面由本人登录并检查 UID。
2. 在知乎运营页检查创作者状态，设置目标等级、日/周上限与间隔。无法可靠识别等级时允许用户凭官方页面记录等级，保留“人工记录”来源。
3. 新建或导入已有草稿，选择养号 / 正常内容、文章 / 回答，补充问题 URL、正文和本地图片。保存后显式审核；编辑会撤销审核。
4. 为账号建立养号计划；计划只消费已审核、未使用的养号素材。正常内容可指定账号与执行时间单独排队。素材不会自动跨号重复分发。
5. 用户启动调度，队列核对等级、入驻、身份、环境快照、内容版本、日周额度、账号与出口时间间隔后执行。
6. 官方编辑器填写、上传、校验内容；提交意图先落盘，再点击发布。仅收到属于本任务且作者匹配的成功回执才记成功。
7. 无回执、超时、中断等记录为“待核对”，不自动重发。用户可登记官方链接或确认未发布，之后另行安排。
8. 达标、素材耗尽、账号异常、平台限制或本人暂停时停止对应计划，显示原因。重启恢复任务状态，但不恢复自动提交授权。

## 架构边界

- `shared/zhihu.ts`：类型、Zod 参数和 IPC 契约。
- `core/zhihu/`：持久化、规则、计划调度、官方浏览器适配；浏览器端口可用模拟实现替换。
- `core/ipc/zhihu.ts`：入口校验；`AppService` 组装依赖并处理忙碌和关闭。
- `src/zhihu/`：账号进度、素材编辑、计划设置、队列和异常恢复，沿用现有白色桌面布局。
- 使用官方登录和编辑界面；不实现验证码代答、风控绕过或限制后换号续发。

## 使用方法

入口为“工作台 → 知乎内容操作 → 知乎多号运营”。账号管理允许内置浏览器登录；本模块的自动养号、自动发布仍要求关联比特环境。

1. 接入比特环境，在账号管理添加知乎账号，完成本人登录并检查身份。
2. 在“账号与养号”读取或人工记录创作者等级，保存日周上限和间隔，启用养号计划。
3. 在“素材池”新增内容或导入内容工作室中的知乎草稿；可选本地配图，保存后审核当前版本。新建和已有素材分别保留本地暂存，保存等待期间锁定切换与编辑。
4. 启动本地调度。计划会分配尚未使用的养号素材；正常内容在审核后指定账号和执行时间加入队列。养号计划每天首次执行前会刷新过期一天的官方等级；实际达标后停止。
5. 在“发布队列”查看明确回执。待核对任务需要本人查看官方页面，登记已发布链接或确认未发布；后者可重新排队，但保留先前尝试的时间间隔和额度计数。

### 已知边界

浏览器适配器采用严格的官方域名、唯一编辑器、正文/图片/AI 声明检查和作者匹配回执。真实知乎页面的登录挑战、分组开放的声明控件、富文本编辑器和发布接口仍可能不同；未在真实账号下验证这些契约，不能把本轮模拟结果当作实号发布验收。遇到无法识别的 AI 标识控件或发布回执会暂停，保留官方编辑窗口供本人处理。导入草稿按正文段落填写，本轮不转换 Markdown 为知乎富文本。

实际升级速度、推荐量和内容留存不在模拟测试可证明的范围内，需要后续真实运营观察。系统不宣称“固定天数升五级”或“不会封号”。

## 皮皮虾素材采集设计（2026-10-26，先设计后实现）

本节保留首版实施记录。皮皮虾采集现已独立为公共功能，当前入口、知乎/微博复用方式及数据兼容见 [公共内容采集](content-sources.md)；知乎运营顶部提供“公共素材采集”快捷入口，已移除原采集页签。

公开分享页实测包含 `RENDER_DATA` 结构化数据，可读取图文正文、配图及分享页返回的评论。首期采用分享链接导入，支持粘贴分享文案及短链接；不依赖私有接口、签名逆向或登录会话。视频帖子仅采集文案和评论，不将视频封面当作图文配图。

1. 在知乎运营的“皮皮虾采集”粘贴链接，明确点击开始。逐条处理，显示成功和失败，失败可单独重试。采集不会触发审核、排队或发布。
2. 后端限制官方分享域名、路径、跳转次数、响应大小与超时；只解析 JSON，不执行页面脚本。帖子和评论使用字符串 ID，避免超过 JavaScript 安全整数范围后串号。
3. 保存原帖链接、作者、文案、采集时间和页面评论。只有页面明确标注“神评”的评论才显示该标签；点赞排序只是本地排序，不冒充平台神评。页面返回的评论不是完整评论列表。
4. 图片使用页面给出的下载地址，保留现有水印，下载后复用本地内容图片存储与备份。遵循已有知乎每份最多 9 图的限制；截断、图片失败及视频不支持均明确提示。
5. 用户选择图片和评论、编辑标题后导入待审核素材。评论保留上下文和作者署名；来源作为独立元数据保留，不向养号正文插入外链。一个原帖只生成一份素材，重复采集更新来源记录，重复导入返回已有素材，避免重复分发。
6. 继续使用现有素材版本审核和调度；后续编辑保留来源并撤销审核。采集内容是否适合发布由当前审核流程处理；“源站也来自转载”不作为自动判定授权的依据。

模块划分：`shared/pipix.ts` 提供边界契约，`core/pipix/` 负责公开页解析、限域下载和采集导入；复用知乎存储、图片文件、IPC、暂存、选择控件和素材审核。来源独立持久化，备份同时检查来源引用的图片。自动化仅使用临时数据库和模拟网络，补充真实公开 HTML 的解析检查，不对真实账号发布。

### 皮皮虾采集使用方法

入口：“工作台 → 知乎多号运营 → 皮皮虾采集”。

1. 每行粘贴一个官方分享链接或整段分享文案，最多 20 行；点击“开始采集”。支持 `h5.pipix.com/s/…/` 和 `/ppx/item/…`，无需额外登录皮皮虾。
2. 查看逐条结果。可停止后续链接，当前链接处理完后停止；失败项单独重试。再次采集同一帖子更新采集记录，不覆盖已导入素材。
3. 在右侧核对原文和图片，选择评论，可切换页面顺序或按点赞排序；原页神评标签照录，普通评论不推定为神评。默认选择成功下载的图片，不默认选择评论。
4. 编辑标题后“导入待审核素材”，再“前往素材池”，点击对应素材继续编辑并审核。未审核内容不会被养号计划消费；导入不会启动调度。
5. 图片失败可重新采集或取消选择失败图片。单帖最多 9 图、单图小于 20MB；复用现有图片处理器，保留水印，最长边最多 1600px，动态图片转静态 PNG。素材来源链接、作者及选中的评论作者独立保存。
