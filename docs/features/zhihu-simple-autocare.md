# 知乎自动养号：简单模式设计

日期：2026-11-04。状态：默认发文链、推荐问题回答、内容读取和本人确认的点赞关注已接入简单面板；完成类型检查和手动界面验证，尚未进行新链的付费生成、实号发布或互动联调。

用户最新要求优先于早期“AI自主运营”和编辑工作台的入口设计：简单易用，默认就能运行；以提升实际创作者等级、曝光和浏览量为目标，不要求指定领域，暂不使用AI自主决策。

用户随后明确：**暂不使用的是AI自主运营，不是AI内容生成。**本模式采用“规则调度 + AI生成内容”：程序按所选操作、数量、时段和预算执行固定流程，AI只在指定步骤整理资料和生成稿件，不决定任务、调用业务工具、修改设置或扩展权限。

## 1. 用户只需要做什么

选择账号 → 勾选操作 → 开启。参数已有推荐预设，日常只看开关、结果和异常。

主入口命名为“知乎自动养号”。普通使用不需要理解运营计划、模型轮次、工具调用、候选版本、供稿编辑单、环境租约或多个调度器。这些是内部实现，不能成为开机前的必填步骤。

本阶段不要求用户配置领域、受众、核心问题、作者贡献或模型。内容生成复用全局默认模型和预算，提示模板由系统提供。原AI自主运营保留独立入口，关闭且不参与本模式，不把原AI计划的授权和待办自动迁移进来。

## 3. 推荐预设

| 项目 | 初始推荐值 | 说明 |
| --- | --- | --- |
| 总开关 | 初次关闭 | 用户第一次开启才取得本模式持续执行授权 |
| 账号 | 原7号、8号可选 | 只操作勾选且已核实的账号，不自动加入新账号 |
| 操作 | 仅自动发文开启 | 其他动作按需选择，不设“必须完成”的活跃量 |
| 目标等级 | Lv.5 | 每号独立达标后停该号，其他账号继续 |
| 每号发文 | 每日最多2篇、每周最多10篇 | 是本产品起始预算，不是知乎官方许可或升级保证；既有更严格额度继续生效 |
| 运营时间 | 北京时间09:00–21:00 | 无合法时段就等待下一天，不集中补发 |
| 发文间隔 | 同号、同出口至少60分钟 | 新任务与原有发布/互动记录共同核对 |
| 发文时间 | 在合法空闲时段内随机分散 | 一次抽取后保存，不在每次心跳时重抽 |
| 素材 | 皮皮虾图文、不限领域 | 以公共采集模块为唯一数据入口 |
| 素材策略 | 缓存优先、整页入库、自动去重 | 已采数据重复使用不再次请求；不同账号不发同一份内容 |
| 原帖评论引用 | 默认关闭 | 开启后只用实际取得、符合使用条件的评论，过滤平台词，不伪造神评 |
| 新采集预算 | 沿用内容数据源设置 | 不因开启本模式擅自提高已设置的次数或金额预算 |
| AI内容生成 | 开启 | 复用全局默认模型、预算和费用台账；只生成内容，不运行自主智能体 |
| 生成次数 | 每日最多8次，全部账号合计 | 包含失败尝试；仍受全局金额预算约束，不要求用户填写每轮模型参数 |

界面初始只露出账号、操作、预设、每日篇数和执行时段。目标等级、周限额、间隔、采集预算、评论引用等集中在一个“更多设置”里，显示继承值和修改去向，避免多处配置同一参数。

若旧账号上限更高，不静默继承为推荐值；首次迁移展示“旧配置10篇/日 → 推荐2篇/日”，由保存本次设置统一应用。若已有单独排期或其他运行模式占用额度，也计入总量。

## 4. 总开关的真实语义

### 开启

一次检查所选账号、绑定比特窗口、登录身份、剩余额度、数据源/内容生成配置和未确认提交结果；随后自动安排本轮操作。开启区域直接列出本模式会使用的采集及AI生成预算，用户开启即授权在显示范围内执行，不再分别启用账号计划、启动调度、授权模型和手动创建发布任务。

检查期间开关显示“正在启动”，成功后才显示“已开启”。部分账号异常只暂停对应账号并写明原因，其他正常账号可继续；全部账号不能执行时显示“需要处理”，不能用绿色“运行中”掩盖。

### 关闭

停止新采集、新任务及尚未提交的本模式排期；当前尚未提交的填写动作在提交检查点退出。已经提交的动作继续只读核对结果，状态显示“正在收尾”，不能谎称撤回或直接重发。收尾完成显示“已关闭”。不退出比特、不关闭共享后台、不取消其他模块的任务。

### 保存设置

关闭时保存供下次开启；开启时按钮为“保存并应用”。新设置仅重排本模式未执行的未来任务，保留已提交、成功、失败及待核对历史。设置变更不能将未知任务变成可再次提交。

### 应用重启

开启时保存账号/动作/预算范围内的持续运行意图，包含有限的内容生成授权；用户关闭即撤销。规则模式可在应用重新启动后核验同一身份、设置版本、额度、费用和提交记录，再继续原范围；不能恢复AI自主运营授权或扩大账号/动作/预算。停机期间错过的任务重新分散到未来时段，不追赶补发。

这部分需要实现专门的持久化规则授权；现有“开发后端重启即撤销AI授权”的行为不能直接套来作为用户每天重复开机的障碍。电脑或应用未运行时无法执行，不承诺后台独立常驻。

## 5. 自动发文：后台完成整条链

1. 优先选择本地未用的皮皮虾图文；不足时按现有预算获取推荐列表，不要求关键词或垂直领域。
2. 原始响应整页入库、图片落地，按来源ID及正文/图片指纹去重；同一来源不跨号重复发布。
3. 将本地原帖、可用配图信息及可选真实评论交给固定内容模板，通过现有AI服务生成知乎图文稿。第一人称表达观点，少套话，不虚构经历、资历或亲测；加入有依据的解释与信息增量，不以换词拼贴冒充原创。保留真实出处；评论继续过滤“皮皮虾、皮友、皮皮、虾友、皮一下”等词。
4. 对生成结果进行固定检查：结构完整、正文/图片可用、无推广、未重复、来源及使用依据满足条件等。来源不足以支持成稿、图片不可理解却描述画面、输出截断或事实无法支持时跳过并记录原因，不用套话凑数。AI参与记录按实际保留，正文不机械添加“AI辅助回答”，平台要求的标识继续准确填写。
5. 通过检查的稿件直接进入本模式自动发布队列，不要求用户逐条建立编辑单、填写方向或往返素材池审核。**需要新增独立的规则检查记录及自动发布授权，不能把旧的人工审核字段偷偷改成已审。**
6. 遵守账号总额度与同出口间隔，随机分散安排，按时复用原发布器提交；只有官方核实的回执才计为成功。
7. 自动读取官方等级/创作分；达标、额度用尽、数据源预算用尽分别按原因等待或停止，不靠不断重发补指标。

自动转载不能把“公开可见”直接等同于已取得使用许可。素材来源的使用依据和准入规则在数据源处集中配置一次，已准入内容可按上述流程直发，不为每篇重复增加长表单；未满足条件的项跳过，不能为了让开关看起来有效就绕开现有检查。原始来源保留以便追溯。

本次不承诺把每一条皮皮虾数据都变成文章。主面板显示“可用库存/已跳过及原因”，库存不足时自动尝试合法补料；耗尽预算后显示等待原因，不制造内容或无限付费请求。

## 6. 操作控制的边界

| 操作 | 规则调度模式的执行输入 | 缺少输入时 |
| --- | --- | --- |
| 自动发文 | 公共皮皮虾数据、已准入素材，经AI生成图文；可复用现成稿 | 自动补料与生成；预算耗尽则等待 |
| 浏览内容 | 当前官方推荐/明确内容链接 | 读取真实内容，不登记虚假的本人阅读回执，不反复打开自有文章刷浏览 |
| 点赞/关注 | 已明确选定、符合准入条件的真实内容/作者任务 | 没有合适目标就跳过，不随机对陌生内容表态，不做双号互赞互关 |
| 自动回答 | 推荐问题浏览量>1万、完整问题上下文，由AI生成针对性回答 | 上下文不足、无可靠依据或预算耗尽时跳过；不把皮皮虾评论拼成问题回答 |
| 自动评论 | 明确目标与完整正文，由AI生成有实质内容的评论 | 无具体可补充的观点就跳过，不发通用模板或将采集神评冒充用户意见 |

首版交付优先让默认的“自动发文”完整可用，其余开关只在对应执行链真正支持时可用。未实现的操作不画成可开启按钮；不为展示丰富而制造空功能。现有AI计划的历史待办不自动接管。

文章和回答共用每号每日2次发布额度；回答不是另外再加2次。评论、点赞及关注复用原互动总预算和发布/互动间隔，默认关闭。启用后程序按限定规则准备目标并请求指定内容，生成模型不能自行决定要执行哪一种动作。

AI生成由现有`AiService`及公共供稿能力执行有限的结构化请求，不启用`OperationsBrainRuntime`、工具循环或模型记忆。每次调用前检查本模式次数和全局费用预算，记录输入来源、模板版本、模型、结果和实际费用；未知扣费不自动重试。关闭开关后不再发新生成请求，在途生成的已计费结果可归档但不得继续发布。重启复用已生成稿，不重新生成同一份内容。

## 7. 随机时间与执行状态

根据当日时段、各账号剩余额度和其他已占用时段，先求合法位置，再抽取分散时间并持久化。随机只用于安排任务，不用于规避验证或限制。执行前再次校验，冲突则顺延并写明新时间及原因。跨号复用现有环境队列，不并行操作同一浏览器。

用户看到的状态只保留：已关闭、正在启动、运行中、等待下一任务、需要处理、正在收尾、目标已达到。技术层可以有更多状态，但不能要求用户据此手动协调多个模块。

日志按“时间 / 账号 / 动作 / 结果”展示中文消息，默认跟随最新，提供仅异常、暂停显示、复制、全屏和任务详情。每次采集记录缓存/新请求、数量及预算，每次发布记录来源、排期、提交、官方链接及结果；跳过和延期都有具体原因。普通等待只在状态变化时记录，心跳默认隐藏。

## 8. 目标与结果

等级、创作分及升级进度从官方读取。曝光/浏览量仅在账号后台确实可读时保存数值、统计周期和读取时间；尚未支持的指标显示“暂不可获取”。不把本地任务数、自身浏览次数或点赞量冒充曝光，不用估算值伪装官方数据。

默认目标是提升等级，曝光与浏览量用于复盘。没有任何固定发文数、互动数或随机间隔能保证等级增长，系统也不以增长目标为理由越过限制。

## 9. 已有模块如何收敛

| 保留复用 | 在简单模式中的职责 |
| --- | --- |
| 网站账号、比特绑定、环境队列与UID核验 | 自动定位账号及排队，不再次配置一套浏览器 |
| 皮皮虾列表/评论/原始归档、请求台账 | 自动补料、缓存、过滤、预算与追溯 |
| 现有AI服务、模型设置、生成模板及费用台账 | 在固定步骤生成文章/回答/评论，不要求配置自主智能体 |
| 原知乎发布适配、提交检查点、回执核实 | 唯一真实提交路径，未知不重发 |
| 原额度/同出口间隔与重复内容检查 | 统一计算所有模式已占用量 |
| RuntimeLog、LogWindow、CreatorProgress | 直接组合到主面板 |
| 原内容池、任务历史与参与记录 | 按需详情，保留历史，不要求作为日常操作步骤 |

新增轻量的`core/zhihu-autocare/`规则编排与`src/zhihu/AutocarePanel`，复用现有端口；统一该模式配置、运行意图、队列归属与状态。不能在原多个开关外面简单包一层总开关，否则状态不一致和重复执行问题仍然存在。

与AI自主计划使用互斥的账号执行所有权；同一账号已由AI计划占用时，在开启前说明并提供一次“切换为普通自动养号”，迁移仅针对所选账号，保留原已提交任务。不能同时让两套循环争抢账号，也不能因停止普通养号而关掉其他运营任务。

## 10. 开发顺序和完成标准

第一步建立统一配置、持续规则及内容生成授权、总开关状态机和旧模式交接；第二步跑通皮皮虾自动补料、AI生成、固定检查、随机排期、真实发布与回执；第三步替换主界面并接入日志/等级结果；最后逐项迁移已有参与操作，未实现项不对外启用。

必须达到：默认配置下选择原有账号后只需开启；不填领域、不建模型计划、不创建供稿编辑单；关闭能真正停止新提交；成功发布有链接和官方回执；额度/预算/素材不足、账号异常、未知结果分别显示；重启不重复执行；日志与界面状态一致。先把默认链做完整，再增加可选操作。

本轮产出为设计文档和项目设计约定；未改后台执行、授权、发布、采集或真实账号状态，没有新API消费，没有启动自动化测试。

## 11. 首版实现与本轮验证（2026-11-04）

主入口为“工作台 → 知乎自动养号”。7号、8号已勾选并保存推荐参数，总开关保持关闭。本轮只读核对：公共库存23条，其中6条满足图文/文字类型与40字的初筛条件，尚不代表都可成稿；当前数据源仍为日4次、每次准备最多2个请求、列表页上限0，因此只用本地库存。若需要自动获取新推荐列表，在统一的数据源设置将列表页上限设为至少1；本模式不擅自抬高原有预算。打开时只需核对预算并开启，无需建立AI运营计划、创建编辑单或逐篇人工审核。AI仅负责结构化成稿，任务顺序、数量、时段和发布权限由程序规则控制。

- `core/zhihu-autocare/`维护独立配置、运行意图、账号UID、任务归属与检查指纹；通过IPC组合现有采集器、AiService和知乎发布器。规则检查独立保存，旧`reviewed`字段保持真实，不改成“人工已审”。
- 优先按每批500份扫描本地皮皮虾图文/文字记录，确认本地没有可选来源后才请求新列表，选择至少40字、无明显推广且未用于知乎的来源；与已有知乎稿、公共交付记录、本模式历史和暂扣素材共同去重。当前先以有明确文字材料的来源稳定成稿，纯图片、过短标题不盲目生成。
- 库存不足时按公共数据源预算补一页推荐列表，原始响应仍整页归档。列表与可选评论补采共享本次准备的请求额度；列表上限为0时只使用本地库存，不自动改动全局设置。分页结束当天不反复请求第一页，下一天才可在预算内刷新。未解析响应、请求结果未知分别提示处理，不自动重发。
