# 公众号草稿箱

入口：工作台 → 微信公众号 → 公众号草稿箱。账号统一在“账号管理 → 其他账号”维护，选择“微信公众号”后扫码登录并检查身份。使用独立内置浏览器会话，无需填写 AppID 或密钥。

## 日常流程

1. 粘贴一篇 `https://mp.weixin.qq.com/s/…` 文章，点击“抓取到本地草稿”。保存来源、原文、插图和抓取提示；相同地址再次导入会打开已有草稿。
2. 在同一页面编辑标题与正文，查看排版预览。编辑区顶栏依次提供“流量词 → AI 改写 → 保存本地草稿 → 送到微信草稿箱”。“流量词”弹窗支持一行一个词，去空行、去重后随当前草稿保存，并展示当前标题与正文的已用、未用词；保存词表不会覆盖未保存的正文，也不会改变微信同步状态。“AI 改写”统一优化标题、正文和摘要，弹窗中选择风格，默认“自然润色（推荐）”，可补充一句要求。标题优先自然融入最相关的 1–2 个流量词，正文分布其余相关词，不强行堆砌。选择风格、保存词表均不调用模型，点击“开始改写”才使用当前文案模型与预算。作者与摘要默认留空，按需展开填写。
3. “网盘链接”会识别已支持的分享地址。优先关联已有资源；新资源点击“入库并继续转存”，进入现有资源录入完成文件选择、转存、建链和本人分享核验，再回到公众号草稿点击“同步替换为本人链接”。入库本身不代表已经转存。正文中的命名网盘链接会同时显示完整可复制地址，避免依赖微信的外链点击权限。发送前再次核验分享和提取码；暂未接入的网盘地址应移除或改为已核验的本人资源。
4. “插图与封面”可添加本地图片或 HTTPS 图片，替换、移除当前插图并设置封面。默认使用原文第一张插图做封面，无图文章需手动添加。发送时将配图和封面上传到目标公众号素材，失败时保留本地稿。当前支持 PNG、JPEG 和 GIF，单张最多 10MB；GIF 封面使用首帧。
5. 首次发送前在顶栏选择目标公众号，点击“保存为新微信草稿”直接保存，不弹二次确认或要求勾选审阅。一篇稿件只对应一个公众号，成功发送后固定目标，“更新本次微信草稿”只更新该公众号的原草稿；需要选择其他公众号时先点“再发一篇”。账号选择框始终展示，单个账号也可看清目标。发送前自动保存本地修改并校验内容，处理中禁止重复提交。工具只保存草稿；本人在微信后台预览并最终发文。

流量词窗口使用加宽编辑区，左侧集中编辑词表，右侧显示使用情况和下轮优先词；支持一行一个词，移出输入框及保存时统一去除首尾空白、空行与重复项，保留词内必要空格。编辑内容按窗口暂存，保存词表不覆盖正文。

标题输入框右侧提供“生成标题”：点击后按钮进入 loading，完成后再打开五条候选标题弹窗，点击一条即替换当前窗口标题，取消或失败保留原内容。生成依据当前屏幕上尚未保存的正文、完整流量词和本稿最近改写风格；调用本身不保存稿件、不改正文或摘要，不累计词覆盖。候选需通过五条、去重、64字、纯文本及正文支持的条件校验，不能只换标点，或仅因流量词含“免费、微信版、小程序”就添加正文未说明的信息。选中的标题按原编辑暂存机制恢复，随后可保存本地或发送。

## 同一素材多次发文

左侧按原文列出文章，使用原文标题、稿件数量和最近更新时间；同一文章的多稿集中到右侧顶部切换，每稿展示编号与最近一次成功改写的风格。四稿以内直接点击切换，更多稿件使用下拉选择，避免挤占正文空间。搜索同时匹配原文标题和各稿标题，分页按文章计数。每个窗口记住每篇文章最后打开的一稿，切回文章或刷新后继续编辑；各稿未保存输入独立暂存，不因切换丢失。旧数据中同一原文带跟踪参数重复导入的稿件归入同一篇，保留原有内容、ID 和送稿记录。

稿件切换右侧提供“再发一篇”：一键创建并切换到独立新稿，继承屏幕上的标题、正文、作者、摘要、配图、封面、资源关联、完整流量词和最近改写风格。屏幕上尚未保存的修改直接带入新稿，不覆盖原稿；回到原稿时仍可恢复本窗口原有未提交输入。已入库资源和本人链接复用，不重新抓取、转存或建链。创建本身不调用 AI，也不发送微信；新稿可直接使用，也可再选择风格改写或换图。

新稿以“第 2 稿、第 3 稿……”标识，编号不写入发文标题或正文。首次发送按钮为“保存为新微信草稿”，首次保存后绑定独立微信草稿；修改本稿后的按钮为“更新本次微信草稿”。再次点击“再发一篇”会创建下一份独立稿件，保留此前每稿的正文、风格和微信回执。创建使用版本检查及请求幂等，回传中断后重试不重复建稿；发送中或待核对稿件需先处理当前保存结果。

“送稿记录”位于稿件切换右侧，展示同一素材的各稿标题、风格、送稿账号、时间和对应微信草稿入口，可切换稿件。每次成功新建、更新或保存核验均保留当时标题及风格；旧记录只展示已有可信回执，不补造历史标题、风格或公开发布时间。可对某次送稿“标记已发布”并撤销，此操作只记录用户已在微信完成发文，不调用发布接口、不改变正文版本或微信同步状态。

各稿的词表独立维护，默认继承全部词；同一原文的覆盖记录仍共享，优先未覆盖的相关词，核心词允许复用。AI 改写会参考其他稿件和历史送稿曾用标题，在原文事实范围内调整标题角度与开头，不把已保存或已送稿当作已公开发布。

裸链接自动整理为 Markdown 超链接：资源使用 `[查看资源](URL)`，普通地址使用 `[URL](URL)`。导入、保存、整理排版、替换资源链接、AI 改写及创建新稿共用同一规则，保留已有自定义链接说明、图片、提取码参数和代码中的示例地址；旧稿中未编辑的裸链接会先在当前窗口暂存为规范语法，保存或发送时落盘。微信交付仍保留可复制的完整资源地址，外链点击能力由微信账号权限决定。

AI 换图提供两种基于参考图的风格：默认“自然重绘（推荐）”，以及突出主体、光影层次与色彩的“吸睛增强”。两种风格都保留主体含义、画面比例和视觉类型，同时在取景、视角、摆位、光线或背景层次中至少调整两项，形成有明显变化的新画面。实拍图保持摄影风格，忽略水印与账号标记，不主动添加海报标题、边栏、标注和印章，不承诺平台的版权或相似度判定结果。“按文章主题生成”是独立选项，可填写画面描述。单张与批量使用相同的生成规则，封面与正文引用同一图片时复用一次生成结果。

流量词每轮全部可用，按相关性选择，不要求全部填入。同一原文的成功改写共用覆盖记录，优先考虑尚未覆盖的相关词；全部覆盖后优先考虑使用较少的词。核心词允许重复，长尾词轮换。只有通过校验并保存成功的改写才根据标题、正文实际出现的词累计，每个词每轮最多计一次；失败、手动编辑和保存词表不计数，摘要、图片说明与链接地址不计入覆盖。词表随各草稿保存，新增词从未覆盖开始，移除后再加入仍保留历史。界面展示的是历史改写覆盖，不代表已发布次数；启用前没有可靠记录的旧改写不补计。流量词与 AI 改写弹窗均可展开查看下轮优先词，无需额外配置。

2026-11-07 在用户加载修复后的源码后端中，使用指定文章的两张原始照片完成实际批量重绘。逐图核对摄影风格与构图，未见新增海报文字、边栏或账号水印；封面同步使用生成的照片，图片解码、全屏预览与刷新回读均已验证。

## 发现爆款

在“工作台 → 微信公众号 → 发现爆款”按关键词和发布时间搜索。搜索和加载更多使用 TikHub，页面会展示每次请求的价格。发现列表不查询阅读数。

列表可按匹配顺序或发布时间排序。“原文”用系统默认浏览器打开公众号文章，“导入草稿”将文章送到本地草稿箱继续编辑。

## 保存与恢复

- 编辑文字按工作空间、稿件和窗口暂存；切页或刷新可恢复。
- 流量词随稿件保存，未提交的词表输入按窗口恢复；词表采用独立版本检查，其他窗口更新后会保留当前输入并提示载入最新词表。改动词表不改变正文版本或微信同步状态。
- 改写风格与补充要求同样按稿件和窗口暂存；旧暂存记录没有风格字段时，保留原有文字并使用自然润色。
- 稿件切换与送稿记录显示最近一次成功改写的风格。只切换下次风格、手动编辑、保存流量词或 AI 换图均不会改动此标识，改写失败时保留原记录。没有可靠历史记录的旧稿显示“未标注”；风格标识不写入发文标题、正文或微信草稿字段。
- 本地稿采用版本检查，避免其他窗口更新后被旧内容覆盖。图片保存在工作空间附件目录。
- 微信保存成功后记录目标身份、草稿地址与内容版本。修改本地稿后再次发送会更新原微信草稿；同一已保存版本不重复创建。
- 微信草稿已被改为多篇图文或无法确认结构时，拒绝覆盖，保留本地稿供处理。
- 微信返回草稿编号后立即保留回执及标题、正文、封面核验快照，回读失败或中断后只读回查同一篇草稿，不重新发送。界面自动检查一次，成功后恢复“已存微信”；失败时保留具体原因和“重新检查保存结果”入口。不再要求粘贴编辑链接、勾选核对，或点击“确认已保存 / 确认没有保存”。旧失败记录可使用已返回的可信编号回查，原草稿更新还可按既有编号核实；新建时既没有回执也没有编号则不猜测已保存，不重复提交。
- 保存成功需核实微信返回的草稿标识并回读编辑页；不能确认时不会显示“已保存”。新版编辑器支持读取与草稿编号一致的单篇 `multi_item` 保存数据，核对标题、正文、链接、插图与独立封面；旧版继续使用编辑器内容。单篇判断使用文章导航列表，标题、作者及正文表单不计为文章条目。保存异常保留具体原因和运行日志，恢复提示只显示一次。
- 封面与插图被微信迁移 CDN 地址时，使用尺寸和解码像素核对内容，不仅比较 URL。比较时规范化 PNG 色彩解释元数据，不修改实际配图；图片内容或顺序不一致仍拒绝确认。
- 登录使用原账号的持久化浏览器会话，身份核验成功及保存结束时刷新 Cookie 存储。应用重开或 Cookie 正常轮换只使身份暂待后台核验，不把已保存会话误标为登录过期；界面可显示“登录已缓存”，发送时自动核实实际账号。微信明确要求重新登录时才提示扫码，网络检查失败保留原会话。

## AI 改写风格

| 风格 | 适合的表达 |
| --- | --- |
| 自然润色（推荐） | 保留原意与语气，去掉套话，让行文顺畅 |
| 通俗科普 | 解释原文术语，让缺少专业背景的读者读懂 |
| 干货教程 | 按已有材料梳理步骤、条件与注意事项 |
| 清单要点 | 将并列信息整理成要点，保留理由和上下文 |
| 观点评论 | 理清原有观点和论据，区别事实、判断与推测 |
| 故事共鸣 | 用已有的人物、情节与场景组织叙事 |

风格只调整表达方式，不补造数据、经历、案例、对白、心理活动或操作步骤，不强行拉长篇幅或凑结构。标题、正文与摘要使用同一风格。事实、署名、版权及 AI 标记，以及现有图片和链接保护优先于风格和补充要求。输出仍为一次 `title/body/digest` 改写，不增加外部检索、多轮确认或多个候选标题。

所有改写风格统一加强 Markdown 排版：中长文按内容使用二级与三级小标题、少量重点加粗，已有并列信息整理为无序列表，已有步骤整理为有序列表，原有引语或提醒按需使用引用，全篇最多两处分隔线。标题与摘要保持纯文本，图片、链接和受保护段落仍由系统原位保留。工具正文预览、全屏对照与微信交付共用同一 Markdown 转换，支持列表、分隔线和代码，源 HTML 仍按文本转义。

模型漏段、重复段或返回空段时，自动携带完整性反馈重新生成一次；只保存完整且通过图链、排版校验的结果。连续失败保留整份原稿及风格、词覆盖记录，日志记录段落编号与尝试次数，不把不完整结果拼接到原稿。此自动重试仍使用当前文案模型和预算。

抓取文章只有单换行、正文与网盘链接在同一段时，按行分离并保护图链行，其余正文仍交给模型改写；不再因一条链接锁住整段正文。没有可编辑段落时直接说明原因，不调用 AI 后只保存新标题。短文也要求对已有概念作 Markdown 强调。第三版排版识别“测试🔗入口”等常见入口标签，同样输出资源卡片；旧排版核验仍按保存时版本执行。

微信交付 HTML 自带段落、标题、列表、引用和图片的内联样式，正文 16px、1.85 倍行高、段后 18px，使用左对齐和零额外字距，减少微信默认排版的影响。工具预览复用这些样式。独立的网盘链接显示为资源区块，自定义说明、完整可复制地址与提取码分行保留；正文句子中的链接保持原位。每条分享地址独立展示，不依靠微信保留外链点击权限才能使用。已送出的旧稿可点击“整理排版”显式升级模板，再“更新本次微信草稿”，沿用原微信草稿编号；重复整理同一模板不制造新版本。旧的未知保存没有核验快照时，按原模板检查，避免新增的排版文案影响恢复。

正文超链接由公众号能力决定；未开通时微信可能移除正文的链接标签。发送时自动把正文阅读顺序中的首条网盘资源填写到微信官方“阅读原文”入口，并保留提取码参数；对应卡片提示点击文末入口，样式不变。单篇只有一个官方入口，多资源文章其余卡片继续保留完整地址和复制提示。代码、图片中的地址不作为入口，非网盘正文不填入。保存后独立回读核对这个地址，缺失或被改为其他资源时不误报保存成功；旧回执没有此字段时继续按原快照核对。

第二版排版将列表标签之间的换行空白压紧，并清除空列表项，避免微信手机端将空白节点显示为额外圆点。保留实际条目、编号、正文换行及代码内容。旧稿需“整理排版”后更新原微信草稿；待核对旧稿缺少快照时仍按保存时的排版版本恢复。

上传图片按工作空间、已核实公众号原始 ID 和实际上传内容记录回执；同一图片的正文与封面、更新或再次建稿可复用，静态图统一转为 PNG 后比较，GIF 正文与静态封面保持各自内容。缓存写入发生在微信接受素材后，早于草稿提交，应用重开后仍保留。复用前读取素材并核对像素，短暂网络失败不会触发重复上传；明确 404/410 后才重新上传。旧素材库中的重复记录不自动删除。
