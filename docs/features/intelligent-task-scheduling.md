# 智能任务调度与可见计划

## 需求纠正：OpenRouter原生自主运营

2026-11-03用户进一步明确：需要项目内部具备类似OpenClaw工作方式的自主决策运营，不接入OpenClaw；模型通道继续使用现有OpenRouter。上一期规则调度+人工AI建议只完成执行底座，没有实现AI作为决策主体的主链，不能继续把它描述为自主运营。

原生自主模式的实施边界：

- 新增项目原生Agent循环：按计划授权定期唤醒、读取计划内账号/库存/真实指标与记忆，调用支持tools的OpenRouter分析模型；执行模型选择的具名业务工具，将工具结果回传模型，直到本轮结束或达到步数/费用/时间上限。
- OpenRouter继续使用现有Key、模型目录与全局费用台账。不安装/接入OpenClaw，不开放任意shell、任意网址浏览或任意IPC给模型。工具能力通过项目已有领域服务实现。
- 自主权限按计划区分：读取状态与反馈、创建原创内容、自动核验并审核本智能体创建的内容、提交已审核内容。权限默认关闭，启用自主计划需本次显式授权周期性模型调用与所选动作；此授权不随表单暂存或备份恢复。启用后每轮无需人工点击建议。
- 自动补内容必须是模型原创、明确AI辅助标识，并限制在当前计划/账号/内容方向。机器审核只作用于本智能体创建的版本，保留审核依据，不擅自审核来源不明的既有素材。未授权自动发布时可以准备任务并等待审核/发布授权。
- 模型可决定下一项任务、调用现有进度/统计读取、选用计划范围内内容、创建原创稿、提出具体发布排期、记录经验；模型不能提高额度、修改账号身份、取消本人暂停、绕过平台验证或重发未知结果。
- 现有规则层继续作为执行前约束与时间计算器；AI输出和工具结果共同形成下一轮决策，日志/记忆/轮次可见。按计划保存决策轮次、工具摘要、费用、完成/中断原因、下次唤醒与有限长期记忆。
- 每计划配置模型唤醒间隔、每日轮数、每轮步数、每轮及每日美元预算；使用模型目录中tools能力验证，未知/不支持的模型不偷偷降级为文字建议。每步请求预留费用并受全局及本计划预算约束，结果或费用不明时停止本轮。
- 应用重启仍默认停止自动执行，不回放中断工具调用，不恢复发布授权。公众号沿用真实已实现的人工交接能力；模型不能虚构公众号自动发布完成。
- 本轮开发不自动启用真实账号、不进行付费模型请求或真实发布；按AGENTS.md进行类型/源码与必要桌面手动查看。后续实际自主运行须由用户在配置后明确启用范围。

参考的接口能力：[OpenRouter Tool Calling](https://openrouter.ai/docs/guides/features/tool-calling)、[Usage Accounting](https://openrouter.ai/docs/guides/guides/usage-accounting)。它们提供模型推理、工具调用格式与费用信息；循环、工具执行、记忆、计划、恢复由盘序自身实现。

### 两种决策模式

| 模式 | 决策主体 | 内容供给与执行 |
| --- | --- | --- |
| 本地规则排期 | 确定性规则；不定时调用模型 | 消费本人选中的已审核素材；单次AI建议仍独立提供 |
| AI自主运营 | OpenRouter工具调用模型；按授权周期自动观察、选择动作、接收工具反馈并继续 | 可创建原创纯文字稿、核验自身准确版本、安排具体任务、执行到期任务及复盘；权限分别控制 |

自主计划从旧的规则自动分配器中分离；规则层只校验额度、时间与间隔。模型安排到未来的任务保留原标识，到期后仍使用已有领域执行器，并在提交前重查当前授权。保存计划、读取页面或单次建议都不会启动自主循环。

### 配置、启用与观察

1. 在“连接与设置 → AI与预算”保存现有OpenRouter连接与分析模型，刷新目录核实`tools`能力及报价。分析模型可以支持工具调用而不支持结构化文字输出；单次结构化建议另行检查自身能力。工具能力未知时不能启用自主模式。
2. 在“智能运营 → 运营计划”选择“AI自主运营”，保存目标、受众、知识、渠道账号、规则及费用上限。默认每60分钟唤醒、每日最多4轮、每轮最多6次模型决策、5分钟、0.20美元，计划每日1美元；这些数值可在允许范围内调整。新计划与权限均默认关闭。
3. 选择希望开放的观察/本地规划与记忆、原创、自产版本自动核验、发布，以及独立知乎个人互动权限。权限意向不会随未提交表单恢复。输出token与推理强度在同一计划维护，自动强度仅在模型目录明确支持low时使用low。保存后在“自主运行”查看准确范围并明确授权持续模型调用；此后不再逐轮要求点击“生成建议”。
4. 本次自主授权、业务计划启用、统一调度运行三项齐备后才自动唤醒。原知乎账号计划及身份仍由知乎专业工作台管理，智能体不能解除本人暂停。当前7、8号保持暂停。
5. 在“自主运行”查看各计划的授权状态、下次唤醒、今日轮数与费用，展开轮次查看模型动作摘要、工具结果、原任务状态与停止原因；本计划记忆单独保存。“任务计划”继续查看预计排期与实际回执，“决策日志”查看运行事件。

当前具名工具包括观察计划、查看完整素材、读取官方创作进度/微博回执反馈、创建原创稿、核验自身版本、安排发布、执行指定任务、记录经验和结束本轮。没有任意shell、任意IPC或任意网址操作入口。自主循环接受一次模型返回最多4个请求，先完整校验整批参数，再逐项顺序执行，失败后剩余调用明确跳过；不并发提交，每项均返回对应调用ID的结果。通用传输的旧消费者默认仍为单调用。提供商的推理上下文按原顺序保留，仅动作摘要进入可见记录。

知乎日常参与接入发现、读取、参与计划与待审回答工具。回答准备需要创建权限，按账号与问题绑定；它不进入模型自产稿自动审阅来源，须本人审核准确版本后才能经原发布器提交。个人正常相关互动另由`execute_zhihu_participation`、`schedule_zhihu_interaction`与只读核对工具处理，需要独立engage权限、完整上下文、原文依据及当前账号范围，不能为互赞互关或凑数量安排。模型可以安排未来的明确决定，到时本地执行器再次检查授权和版本，无需额外模型调用；候选、排期、本人记录及真实官方回执分开展示。详见[个人账号自主参与](zhihu-personal-interaction.md)，11月3日历史范围见[日常参与实施说明](zhihu-daily-participation.md)。

### 浮动快速查看

工作台各页面右下角提供“自主计划”浮动按钮，点击展开非模态面板。面板仅列出AI自主模式的计划，支持搜索切换，显示实际授权/运行状态、下次唤醒、今日轮次与费用，以及最靠前的3项待办和需本人处理数量；“查看此计划详情”及“打开运营中心”定位到正在查看的计划。没有自主计划时显示配置入口。

展开后每5秒刷新轻量本地摘要，关闭即停止轮询和变更订阅；只读查询不读取库存正文、不调用模型、不更改执行授权。支持再次点击按钮、关闭按钮、点击外部及Esc收起，Esc收起后焦点返回浮钮。面板低于审核/授权弹窗，页面底部预留浮钮避让空间；选择与跳转只影响本窗口，切换工作空间重新读取。

本轮已完成源码类型检查、独立静态复核和实际源码桌面手动查看，核对展开空态、Esc收起回焦点及打开运营中心的导航。现场仍无自主业务计划，未用虚构计划或付费运行代替验收；未运行自动化测试或新增发布。

### 渠道、审核与恢复

- 知乎：复用原内容池、AI辅助标识、准确版本审核、官方进度、原队列、日周额度及同出口错峰。原创供稿是文章纯文字稿；平台身份或发布状态未知时停止，不能重复开通或重发。
- 微博：复用普通草稿与其原填写、提交、回执和统计链路；原创稿保留AI辅助标识与可见范围，审核指纹包含正文、账号、图片、可见范围和AI标识。资源营销仍由独立工作台处理。
- 公众号：可创建本地原创纯文字稿并形成交接任务，或选择现有公众号内容；由于尚无自动发布器，由本人完成官网交接和链接登记。
- 机器审核只作用于本智能体为当前计划创建、正文未改动的准确版本，保存核验说明；不把它显示为人工审阅或版权鉴定。既有稿不能借此绕过原审核。
- 费用同时受全局AI日预算、本计划日预算、单轮预算约束。账本记录真实返回费用；发送后中断、账单不明或提交未知均停止自动继续，不重试同一未知请求，也不自动重发。
- 停止计划/调度、修改计划、重启和恢复备份都会撤销本次自主授权；保留轮次、记忆、原稿关系与提交记录，不回放中断工具。未执行原任务可在条件变化后由模型重新安排，保留原ID；本人取消、已执行及待核对任务不能复活。

代码职责：`core/ai-agent.ts`负责单次OpenRouter工具调用与预算；`core/intelligent-operations/brain-runtime.ts`负责循环、授权和唤醒，`brain-tools.ts`封装领域工具，`brain-state.ts`定义历史、自产稿关系及本地公众号稿；UI位于`src/operations/`。日志沿用工作空间`logs/intelligent-operations/日期.jsonl`及数据库运行记录。

## 首期规则模式实施契约

- 新增侧栏“智能运营”，集中管理计划、未来7天排期、决策日志和按需AI建议。连接与模型、总预算复用现有设置，运营计划保存目标、受众、内容方向、知识依据和渠道账号范围。
- 每个计划包含知乎、微博、公众号的独立策略：启用渠道、用途、日额度、执行时间窗、最小间隔、检查频率。账号可进一步收紧额度并独立暂停。同一账号不允许同时被多个启用计划调度。
- 默认所有新计划暂停，全局调度停止；读取快照、生成本地计划、重启均不会启动发布。已有双号暂停状态不变。用户需要显式启用计划和启动调度；发送任务还必须通过当前内容版本审核。
- 可见计划用真实本地内容与现有任务生成，带稳定业务标识、安排/阻塞原因、内容版本、预计时间及执行结果。暂停、取消或改规则保留历史；已进入提交阶段的任务禁止重发。
- 知乎复用已审核素材、原队列和官方创作进度检查；已有账号计划暂停时先显示阻塞，不暗中恢复。微博复用本地草稿、图文填写、提交、回执和统计，中心对准确内容指纹作显式审核，内容或可见范围改变即失效。公众号当前只支持选题/内容计划及人工交接，不宣称自动发布。
- AI建议由用户显式调用，复用全局分析模型和费用预算；只接收本计划必要的目标与非凭据摘要，结果不能直接发布、修改审核标记或突破规则。普通排期不消耗模型请求。
- 各渠道执行器负责身份、环境和回执；统一规划器不操作任意网页、不接管其他模块的人工草稿。只新增必要IPC和领域模块，不把所有规则堆入AppService。
- 本次按AGENTS.md进行类型/源码检查与源码桌面手动操作验证，不主动运行自动化测试或真实发布，不打包。

## 用户看到的结果

系统在已启用的账号、任务类型和规则范围内安排养号及运营任务。提供“今日 / 未来7天”计划，按账号、渠道、任务类型和状态筛选；显示预计时间、账号与环境、具体素材、依赖条件、安排原因和执行结果。

计划中的项目区分：待执行、执行中、已完成、已顺延、等待条件、待本人处理、已取消。仅对已确定素材和条件的任务给出可执行排期；素材缺失时显示等待条件，不用虚构文章占位。未来时间是预计值，远端限制、环境占用或人工操作可使计划重排。

每项计划可以展开查看“为什么此时执行”“受哪些规则约束”“等待什么条件”，并关联现有发布任务、回执和日志。尚未执行的项目可取消或调整时间；已提交的项目只能核对结果。可暂停单账号或全部自动执行，调整规则后重新规划，并保留旧计划及变更原因。

## 第一阶段任务

| 类型 | 安排依据 | 完成证据 |
| --- | --- | --- |
| 养号发文 | 实际等级低于目标、审核素材可用、额度及间隔允许 | 原任务对应的官方发布回执 |
| 正式内容发布 | 账号具备条件且内容已审核并明确用于该账号/渠道 | 对应渠道的官方回执 |
| 创作进度检查 | 检查频率、上次读取时间、账号登录及环境可用性 | 官方等级、创作分、平台更新日期与检查时间 |
| 发布结果核对 | 已有提交记录但结果未知 | 同账号官方状态及原任务内容匹配，失败则继续待核对 |

不会通过点赞、互关或虚构阅读来替代真实内容运营。素材采集、AI生成与审核仍复用已有独立流程；第一阶段仅消费已审核素材，不自动新增付费调用或把生成结果自动设为审核通过。

## 决策方式

先用确定性规则生成可解释计划：读取账号状态和任务回执，检查依赖及阻塞，寻找符合执行时间窗、日周额度、账号与同出口间隔的时段，再通过既有环境队列执行。以任务完成、检查结果、素材审核、规则调整或环境状态变化触发重新规划，定时器只负责唤醒。

同优先级任务采用可配置优先顺序并考虑最长等待时间，避免某个账号长期占用环境。发布结果核对是后续发布的依赖，优先解决；同一环境不与其他业务并行操作。规则变化只重排尚未执行的任务，不复制原任务或清除提交历史。

AI可以在后续阶段建议素材匹配及内容方向，建议和依据留档；不得直接修改额度、审核标记、账号身份或提交历史。没有足够的效果历史时不宣称掌握最佳发布时间；创作分按官方更新周期读取，不由发文数量推算。

## 复用与边界

- `core/zhihu/service.ts`、`policy.ts`：现有账号规则、额度、错峰、素材唯一分配及发布状态机继续作为最终校验。
- `core/browser-environment-queue.ts`：继续持有账号环境租约，处理与其他渠道的占用冲突。
- `core/runtime-log.ts`：记录每次计划生成、顺延、阻塞与人工调整，包含规则依据和原任务标识。
- 在规划与执行之间增加持久化计划记录，带唯一业务键、计划版本及任务引用；重复唤醒不能重复创建任务。执行前再次核对身份、环境、审核版本、额度与时间。
- 规划器只产出计划；领域执行器负责提交和核验，UI通过现有IPC与本地查询hook读取计划。跨渠道复用计划结构、状态和日志，不合并不同平台的发布规则及回执逻辑。
- 未登录、验证码、实名认证、协议或平台限制转为待本人处理；已提交但未知的结果不自动重发。重启后的执行授权沿用项目现有安全恢复规则。

## 结合当前两个账号

7号素材用尽时展示“等待已审核素材”，8号达到当日额度时展示“额度已满”和下次允许时间。当前两号均被暂停，因此规划器即使提供预览，也不能自行启用。用户启用对应自动执行范围后，才根据当时实际条件落地任务；不会为填满未来计划而生成新素材、提高额度或重复使用已发内容。

## 交付顺序

1. 先实现本地规则规划器、计划持久化及可见计划列表，支持暂停、取消和重排原因。
2. 接入创作进度检查与发布结果核对，使计划与真实执行状态联动。
3. 累积经过核实的效果历史，再加入可选AI建议与跨渠道素材匹配。

以上描述设计目标与边界，首期实际接入范围以下方实施记录为准，不保证达到特定创作者等级。

## 已实现的首期能力与使用方式

入口为侧栏“智能运营”。全局模型、API连接和费用预算继续在“连接与设置 → AI与预算”维护；运营中心不保存第二份Key或另设一套模型连接。

1. 在“运营计划”新建计划，填写名称、目标受众、目标、内容方向及本计划知识依据。可同时启用知乎、微博和公众号策略，选择已有账号或公众号内容交接映射。每个账号可填写定位，并独立暂停或收紧日额度、间隔及执行时间窗。
2. 选择本计划允许安排的本地素材。保存后计划暂停。修改已保存计划会增加版本、暂停执行、取消未执行旧排期并撤销相关审核；执行中的计划须先处理原任务结果。
3. 在“任务计划”点击“重新规划”，查看今日或未来7天预计时间、账号、内容、任务类型、阻塞依据和渠道关联记录。可按计划、渠道、账号、类型、状态筛选；可调整未执行任务的时间或取消，人工时间作为最早时间保留，规则仍可使其顺延。
4. 微博发送前，在任务行“审核内容版本”核对完整正文、可见范围和每张图片的文件名与SHA-256。内容变化会使审核失效。知乎继续使用原素材池的版本审核。AI建议不能将素材标为已审核。
5. 用户显式启用计划并启动统一调度后，才执行到期且条件满足的任务。同一账号同时只能属于一组启用计划。知乎须保留已核验的原账号规则并明确启用账号计划，同时停止知乎旧的独立调度；统一中心只执行指定原任务，不启动旧自动分配。当前已有7、8号暂停状态不会被中心读取或保存操作暗中改变。
6. “AI运营建议”需用户对本次调用显式授权，使用全局分析模型与预算；输入仅含本计划目标、知识依据、账号定位、选中素材标题与任务摘要。结果保留供审阅，不自动改规则、生成素材、审核或提交。
7. “决策日志”按计划与级别查询，记录保存、重排、暂停、任务状态及AI调用结果；数据库记录为准，另写入工作空间`logs/intelligent-operations/日期.jsonl`。首次加载、刷新失败、无记录与筛选无结果分别处理。

### 渠道边界

| 渠道 | 首期接入范围 | 仍由专业工作台处理 |
| --- | --- | --- |
| 知乎 | 已审核养号/正式素材、指定原发布任务、官方创作进度检查、未知结果提醒 | 首篇开通、身份和等级核验、未知结果登记、未提交原任务人工继续 |
| 微博 | 普通`WeiboPosts`本地草稿，准确版本审核、原填写/提交/回执、本人历史微博统计 | `WeiboMarketing`资源营销任务仍在微博图文营销模块；已有filled/attention/uncertain草稿不自动认领 |
| 公众号 | 已有公众号内容映射与本地文章的计划、完整稿件查看、人工交接及官方链接登记 | 账号登录、网页群发与发布审核；首期没有公众号自动发布器 |

普通排期无需模型请求，不自动新增素材或调用采集API。每个计划显式选择素材范围；活跃计划优先取得未使用内容，暂停计划的预览不占用活跃计划库存或时段；同计划多账号按就绪条件和最少分配数量匹配。

跨账号及同出口间隔在排期和提交前重新检查。知乎保留原日/周额度；微博从本次新增的真实填写/提交时间开始统计，旧记录未保存这些时间时不以更新时间猜测历史额度。工作空间切换、应用关闭、开发安全重启及更新安装前会停止中心调度。恢复备份保留计划文字及任务历史，清除执行与内容审核授权，不清除提交记录，不恢复自动发布。
