# 流量词库

2026-11-08更新，开发源码。界面随前端更新；存储迁移与精确历史接口需手动点击“应用更新并重启”后加载，本轮不自动重启。

## 筛选、选词与复用

打开模块默认显示“关键词库”，已有词条直接可见。工具分为“关键词库 / 我的词池 / 5118找词 / 百度营销 / 找热点”，整理好的词池不再混在查询表单下方。

“词条类型”新增“长尾流量池”，归集百度批量扩词和5118长尾词来源的关键词，是全部关键词的一个子集。分类按明确采集来源，不按词长、默认月量10或搜索量高低猜测。可继续组合来源、平台和月搜索量筛选，跨页选词后复制或保存为词池；选择不属于长尾的来源时显示无匹配结果。列表指标、采集次数、首次时间及历史CSV均限定到对应来源，避免其他来源的新指标混入。加载新后端后，已保存的历史词自动参与筛选，不另建长尾词数据表，也不修改既有词池快照。

- 按中文来源、平台、搜索量依据及词条类型筛选；支持最近采集、月搜索量和关键词排序。默认月量、实测月量与未提供分开，未提供的指标不显示为0。
- 列表保留关键词、来源与平台、核心指标、最近采集及详情。默认月搜索量10明确标为“默认值 · 非实测”，不与其他来源的实测指标互相覆盖。
- 支持全选本页、跨页选择、清空和刷新恢复，最多1000项。同来源词条使用稳定身份，新采集不会把它变成另一条选择。改变实际筛选范围时清空选择，翻页、排序或重复提交相同搜索保留选择。
- 所选词可以复制、带入找词或保存为命名词池。复制及带入按词去重；找词上限50词、每词100字，带入不自动请求接口。超过上限时保留选择并提示分批，不暗中截断。
- 词池保留选取时的指标和来源快照，已有稿件引用保持有效，不改为随采集自动变化的引用。全局快照与词池列表只带名称、数量及最多5词预览；展开、复制编辑、搜索选词时按ID读取完整内容。手工、AI和供应商词条仍可直接使用，无须先进入采集历史。异步读取或保存回执不覆盖期间新改的整理内容。

点击详情才读取该稳定词条的精确分页历史，不再用包含词搜索冒充单词历史。选择某次历史后再读取来源档案；原始查询与响应默认折叠，只作为文本显示。完整历史CSV及单查询JSON仍可导出，入口位于“查询档案与入库说明”。

## 存储结构

原结构把每次观察的词、来源和完整逐条原文重复保存，列表每次对全部观察执行窗口排序，再重复统计全库。历史增长会拖慢只需50条的普通翻页。

新结构分成三个有明确职责的物理层：

| 层 | 内容 | 读取时机 |
| --- | --- | --- |
| `traffic_entries` | 稳定词条身份、来源键与平台、当前指标、最新观察整数指针、计数及排序字段 | 列表与内容复用 |
| `traffic_observations` | 每次指标、当时词形、采集时间及查询引用 | 词条历史与历史导出 |
| `traffic_queries` | 查询上下文、状态及完整冷归档 | 用户打开来源档案时 |

冷归档透明压缩，读取与导出的原文字串不变。逐条观察不再重复保存完整原文；原查询响应缺失但仍有旧逐条证据的特殊记录单独保留，并说明它不是原始响应。旧`traffic_items`为兼容视图，不是另一份重复的物理数据。AI本地参考与内容选词也读取最新词条，不再对全历史重复排序。

v35进一步把来源身份与显示名称分开。同词同平台按稳定来源键保留独立当前记录，来源筛选和长尾类型直接命中主表索引；不再逐词去历史表查找来源。现有当前表就承担来源快照，不再增加一份重复的当前指标表。最新观察使用已有整数序号关联，观察对外ID保持不变。

列表默认不计算全库统计。`traffic.knowledge.overview`按需返回统计、种子词和词型摘要，缓存只随流量数据修订号失效；无关设置或日志写入不会导致全库重算，同连接和其他连接新增流量记录仍会刷新。列表下一页使用带筛选签名的游标，上一页恢复已访问位置；旧数字页码仍兼容。中文包含搜索仍扫描当前词条，不扫描全部历史。

查询、入库恢复和迁移分别维护在领域读模型、应用服务与存储迁移模块中。`traffic.knowledge.resolve`按原观察ID核对迁移后的词条身份，窗口暂存选择只修正身份，保留选取时的文本与指标；失去历史记录的选择仍可复制和保存，并显示说明。

## 迁移与验证边界

v34与v35迁移执行前自动保存一致性备份，在事务中完成。失败回滚表与版本；重复打开不重复迁移。v35保留单来源词条ID，旧版把不同采集接口混在一起的词条按来源拆分，所有原观察ID、指标、时间和查询原文保留；稿件及词池引用的观察ID不改。迁移需要备份及重建表的临时磁盘空间，不自动删除历史、不自动压缩整个数据库文件。释放的页可供后续复用，不承诺现有数据库文件立即缩小。

备份导出与恢复统一支持不超过8GiB的数据库，摘要校验采用流式读取，避免整库进入内存。超限在导出时即拒绝，保留普通文件、路径、旁文件、摘要、完整性及凭据检查；附件仍按各自上限处理。513MiB合法稀疏SQLite的预检与恢复专项通过，该测试验证文件容量边界，不替代大行数基准。

优化前的50万规模基准已记录在[原基准报告](../reviews/traffic-library-scale-2026-11-07.md)：50万独立词条时长尾筛选与深页超过5秒，因此不能用此前10万历史的小规模结果推断容量。v35[同机复测](../reviews/traffic-library-optimized-scale-2026-11-07.md)已完成：50万独立词/50万历史的首50词4.8ms、长尾筛选8.6ms、长尾最后数字页147.5ms，库体积780→675MiB；增加到150万历史时首50词41ms、长尾筛选8.2ms、长尾最后游标页7.1ms，最慢已测独立概要2313.9ms，均低于5秒。测试库独立于工作空间，分页计时包括后端读取与返回数据序列化，排除Electron传输、DOM渲染和操作系统冷缓存；该结果不是跨设备承诺，历史全量导出仍按所选历史规模读取。

词库核心与独立迁移审查49项通过，词池、ideas、大库备份专项通过，旧版本迁移fixture已适配，类型和差异检查通过。1440×900任务窗口使用仅本测试页面的业务传输夹具连续21组交互通过，不写真实词池或剪贴板；关键截图已查看，测试窗口已关闭并切回main。额外旧回归的无关失败与完整测试边界见复测报告。实际工作空间的迁移与最新接口联调须在手动应用更新后进行，本轮不自动重启后台，也不把旧后端的读取视为新结构验收。
