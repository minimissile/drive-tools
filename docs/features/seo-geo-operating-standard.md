# 盘序落地页 SEO / GEO 实施标准

本标准面向 `https://panxu.site` 的中文资源说明页。目标是让有实际需求的读者发现页面、判断资料是否适合并进入网盘；技术与内容达标不等于已经获得排名、AI引用或稳定流量。

## 维护依据

已项目级引入 `ai-seo` 2.12.0 和 `seo-audit` 2.2.2，来源 `coreyhaines31/marketingskills`，固定提交 `88c79f6528a9347420e57ceb1fff9a60de651768`，保留完整参考资料与MIT许可。记录见 `.agents/skills/SEO-UPSTREAM.md`；产品上下文见 `.agents/product-marketing.md`。已有 `programmatic-seo` 用于规模化页面质量与重复内容。

上游是工作方法，不是搜索平台规范或效果保证。优先采用官方平台文档，第三方研究视为待验证假设。FAQ富媒体、训练爬虫、llms.txt、固定英文段落长度和“提升百分比”不作为发布条件。盘序使用现有中文摘要120字上限、完整句子与正文依据要求，不照搬英文150–160字符指标。

## 发布前应具备的条件

| 方面 | 标准 | 实现或证据 |
| --- | --- | --- |
| 抓取与索引 | 正式页200，正文在初始HTML中；规范网址正确，无意外noindex | Worker SSR；公开目录、robots和XML站点地图 |
| 页面身份 | 唯一明确标题、摘要、H1；标题承诺与正文一致 | 生成、修订、独立审核使用同一搜索编辑规则 |
| 资源价值 | 介绍实际内容、具体例子、适用范围及局限，帮助判断是否需要资料 | 实际正文提取、文件记录、可定位依据；通用攻略不替代资源说明 |
| 可引用性 | 关键结论明确对象、条件和依据，摘取后仍不误导 | 搜索审核规则影响intent、specificity、readability和trust |
| 可信度 | 品牌统一，整理范围、AI参与和更新信息真实 | WebSite/Organization、图标、关于页、隐私说明 |
| 质量门槛 | 内部至少82/100且每项至少70%，无无依据事实，正文与摘要完整 | 本机与云端发布校验；不把内部评分写成搜索评分 |
| 内容重复 | 相似正文不重复发布；不为同一资料拆出大量关键词变体 | 已有本机相似度门槛与云端正文去重 |
| 页面发现 | 首页可进入资源页，资源页按实际相关性连接其他已发布资源 | 资源目录、相关资源、站点地图、GSC/Bing、IndexNow队列 |
| 获取路径 | 获取按钮清晰，稳定入口指向当前网盘，提取信息不混入摘要 | `/r/`说明与`/go/`跳转分离 |
| 效果记录 | 能区分展示、点击、AI引用及网盘入口操作 | 站长工具、匿名来源汇总与人工引用记录分别衡量 |

规则版本为 `panxu-search-2026-11-04`。生成和修订前传入仅基于已知资源的searchBrief；不推断搜索量。独立审核记录由后端标记规则版本；旧草稿下一次显式发布时按现行规则重新审核，云端拒绝未按现行规则审阅的新发布。已公开的旧页面保持可读，不为规则更新自动撤下或刷新日期。

## 访问与获取统计

公开页面使用同域名 `/events` 接口，浏览器只传规范路径、固定来源分类及view/outbound/copy类型。按UTC日聚合，不保存IP、Cookie、访客ID、设备指纹、完整来源URL、搜索查询、原文件或提取码。每次文档打开，同类事件最多计一次；可见后才计访问，复制成功才记复制。尊重DNT与GPC，不加载第三方分析脚本。

来源分类覆盖Google、Bing、百度、其他搜索、ChatGPT、Perplexity、Gemini、Copilot、Claude、其他AI、站内、其他及直接/未知。分类来自浏览器可提供的来源域名，不推断AI训练或AI引用。匿名入口只接受正式域名同源请求，限制请求体、路径和事件枚举，核对资源仍为可公开页面；Cloudflare限流抑制滥用，触顶只影响计数，不阻断阅读或获取。

计数最多保留90天。桌面“资源落地页 → 访问与获取”按需读取近28天数据，管理接口沿用原令牌；页面仅公开采集接口，不公开统计明细。未成功读取前不显示0，失败可重试。

这些是可见浏览器事件，不是UV、下载成功数、搜索点击数或完整的机器人过滤结果。隐私信号、拦截器、来源丢失、限流与网络失败会使数据偏低；浏览器自动访问也可能计入。开发者的手动核验访问属于真实事件，不能冒充新增用户。历史数据不回填、不补造。

## 衡量流量与引用

- SEO：以GSC/Bing的“查询 × 页面”查看展示、点击、CTR和平均位置。待数据量足够后比较相同口径的28天；新站数据少时不硬套行业CTR阈值。`site:`不是索引总数。
- GEO：按引擎、日期、语言和查询分别记录回答中的实际引用网址、推荐与事实准确性。小样本查询需多次观察并注明样本数；未检查写“未测量”，不能写未收录或零引用。
- 转化：记录网盘入口点击与复制；它们不代表下载成功。AI来源点击不等于AI引用率，没有点击的引用也不会进入来源统计。
- 改动：先记录起点和具体假设，一轮只改影响判断的内容；不为新鲜度反复重写、改标题或请求索引。检索问题、内容或链接变更后，按实际观察决定下一步。

首批候选问题见 [SEO/GEO基线记录](../reviews/seo-geo-baseline-2026-11-04.md)。它们依据已知资源内容制定，尚未作为搜索量证明；有真实查询后应调整候选集合。没有用户请求，不创建定时任务或自动运行外部评估工具。

## 维护边界

技能安装只增强开发工作方法；运行时明确使用 `core/landing-search-policy.ts` 中经过筛选的规则，不把上游整份skill作为系统提示词直接发送给模型。保持真实AI调用、脱敏与现有显式发布流程；不抓取私人资料补文章、不虚构作者、评价、授权与外部背书。

日常开发按根 `AGENTS.md` 默认连续执行与改动相关的脚本自动化测试，使用本任务专属窗口，不操作主工作台。付费调用、真实发布及外部评估工具仍按本次用户已授权范围执行，不因上游skill推荐而扩大范围。

官方依据：[Google AI优化指南](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)、[Google AI功能与网站](https://developers.google.com/search/docs/appearance/ai-features)、[OpenAI爬虫用途](https://developers.openai.com/api/docs/bots)、[Cloudflare限流绑定](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)。
