# 微博单条数据统计

状态：已接入当前开发源码，尚未随新版本发布。更新：2026-10-26。

选择当前账号本人发布的一条微博，读取官方桌面详情页实际提供的指标，并在当前工作空间保存统计快照。打开面板、切换目标和普通列表刷新只读取本地记录；只有点击“读取最新数据”才访问官方页面，不自动轮询，不使用付费统计 API。

## 入口与操作

| 入口 | 操作 |
| --- | --- |
| 账号管理 → 其他账号 | 在已有 UID 的微博账号行点击“数据统计”，选择“已保存的微博回执”，或输入本人单条链接 |
| 直接发布 | 在“发布微博”的已保存回执下查看“数据统计”，目标为该回执对应的微博 |
| 微博图文营销 | 任务已保存回执与账号关联后，在回执下查看“微博数据统计” |

1. 确认账号记录的数字 UID 属于本人。账号尚未连接但已有 UID 时，仍可从账号行查看已保存的统计历史；读取最新数据前需要恢复该账号的官方登录身份。
2. 从已有回执中选择目标，或粘贴 `https://weibo.com/数字UID/微博ID` 形式的桌面详情链接。主页、其他作者、移动版或短链接不能直接作为统计目标；请先取得本人单条桌面链接。
3. 面板先显示已有本地快照。首次使用显示“尚未采集这条微博”，此时尚未访问官方详情页。
4. 点击“读取最新数据”。应用沿用该账号的浏览器环境、代理、任务队列和身份复核，核对当前登录者、微博作者与微博 ID 一致后读取。页面未提供的指标保留为缺失，不为凑齐指标读取其他微博。
5. 查看上次采集时间和指标。有多次快照时，展开“采集历史”按时间查看。每个账号与单条链接分别保留最近 30 次快照，最新一次在前；工作空间重载后可继续查看。

统计只读取本人单条微博，不涉及发布、上传、点赞或评论。读取使用新建的后台只读窗口（内置浏览器）或临时页面（比特环境），结束后关闭本次读取页面，不导航覆盖用户已有的网页编辑器或草稿。

## 指标口径

| 指标 | 当前口径与显示 |
| --- | --- |
| 阅读量 | 本人详情页提供的阅读／展示次数；不能作为独立访客人数 |
| 转发 | 目标微博的官方转发计数 |
| 评论 | 目标微博的官方评论计数 |
| 点赞 | 目标微博的官方点赞计数 |
| 链接点击 | 当前详情页未提供，保存为 `null`，显示“暂不可获取” |

真实的 `0` 显示为 `0`。缺失或无法证明属于目标微博的指标保存为 `null`，最新结果显示“暂不可获取”，历史表中显示“—”；缺失不代表无人阅读或互动。

网页出现“万”“亿”或“+”等约数时保留原文，最新结果同时标注“网页约数”。这些值不转换成精确整数，不用于计算精确增量或点击率。本功能保存采集时点的页面结果，不提供自动趋势分析、曝光归因、收益归因或任意账号／关键词统计。

## 失败与恢复

| 情况 | 处理方式 |
| --- | --- |
| 本地记录读取失败 | 保留可恢复状态，通过该区域的重试重新读取本地记录；不需要重新发布 |
| 主页、非本人链接或链接格式不符 | 更换为当前账号本人的单条桌面链接；非法目标在本地拒绝 |
| 登录失效、换号或身份无法核实 | 回到“其他账号”恢复原 UID 的登录并检查身份，再点击“读取最新数据”；不要把历史任务改到另一身份 |
| 网络、代理或环境占用阻止读取 | 处理环境提示后重试；读取沿用现有环境约束，不绕开代理或队列 |
| 页面跳转、安全验证、微博不可访问或结构变化 | 在官方窗口检查目标与安全验证后重试；无法确认归属时不保存猜测值 |
| 本次读取失败但已有历史 | 旧快照继续保留；核对“上次采集”时间，修复原因后手动读取最新数据 |

本地快照按工作空间、账号与规范化单条链接隔离，保存在现有设置记录中；本功能没有新增数据表迁移或第三方依赖。业务记录与 IPC 不存储或传递 Cookie、密码。环境配置、身份和登录的通用操作见 [多平台账号与浏览器环境](browser-environments.md)。

## 界面与适配边界

统计是既有白色工作台中的局部扩展，沿用原有字体、颜色与间距变量，以及公共按钮、Field、Select、QueryError、Empty、区域加载状态和表格。指标、读取操作与可展开历史仍在原账号或回执上下文内，没有新增视觉系统。

产品面向 14 寸及以上桌面设备；常规代表逻辑尺寸为 1366×768、1440×900 和 1920×1080，按受影响布局选择验收。本轮实际查看约 1710×1073 的逻辑桌面，物理截图为 3420×2146；未完成其他尺寸矩阵，也未将手机、平板或窄窗口纳入本轮验收。

## 本轮验证范围

2026-10-26 复用唯一现有 `npm run dev` 源码桌面实例，对一条已有本人私密测试微博进行了四次只读采集，没有发布、上传、点赞、评论或调用付费 API。最新一次为本地时间 15:21:05，阅读、转发、评论、点赞均为 `0`，链接点击为 `null`。四次历史全部保留，其中前两次的阅读量仍为 `null`，未用后续结果回填或删除；开发重载后也曾确认三次已保存快照可恢复。

实际界面已查看账号入口、长回执选项、首次空态、真实 0 与缺失指标、展开的四次历史，以及无效主页链接的本地拒绝；随后恢复原统计目标。记录见 [核验清单](../../.impeccable/review/weibo-statistics/verification.json)和同目录的 `account-empty-desktop.png`、`account-result-desktop.png`、`account-history-desktop.png`、`account-invalid-link-desktop.png`。

源码审查曾发现阅读标签查找范围过宽，可能取到其他区域的数据。修复后仅在与精确微博、作者、永久链接和正文对应的最小组件内容边界内查找，并排除含其他微博的候选；无法证明归属时保持 `null`。同一测试帖再次读取仍为阅读 `0`。独立复审将这一项 P1 修复评为 `resolved`，最终 disposition 为 `ship`，该结论仅覆盖所列修复，详见 [收尾审查记录](../../.impeccable/review/weibo-statistics/review.md)。

修复后 `npx tsc --noEmit` 与 `git diff --check` 通过；对改动统计界面和入口执行的一次 UI detector 返回 `[]`。本轮未运行单元、集成或端到端测试；编译、检测器与这次私密帖读取不代表全量场景已验收。

仍未实测：比特浏览器真实统计读取、非零或万／亿／加号约数、多帖干扰场景、两个回执入口的独立渲染、完整键盘流程及其他桌面尺寸。未提升版本、制作安装包或发布本功能。

实现位置：`shared/weibo-statistics.ts` 定义指标与 IPC 契约；`core/weibo/statistics.ts` 管理目标和本地快照；`core/weibo/statistics-page.ts` 限定页面读取与归属核对；`desktop/weibo-statistics.ts` 和 `core/browser-platform-ports.ts` 分别接入内置／比特环境；`core/ipc/weibo-statistics.ts` 校验入口；`src/weibo/Statistics.tsx` 与 `statistics.css` 组合三个入口的共用界面。
