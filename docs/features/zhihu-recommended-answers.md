# 知乎推荐问题回答

2026-11-04，先记录实现约束，再接入现有日常参与和统一调度。

读取每个账号自己的官方推荐页 `https://www.zhihu.com/creator/featured-question/recommend`，将显示浏览量严格大于10,000的问题保存为回答候选。数值支持逗号、万、亿；等于10,000、缺失或无法识别的指标不入选，回答数及关注数不能充当浏览量。保存原始指标、规范问题地址、账号、来源和观察时间。推荐列表不是问题全文，起草前仍读取完整问题；热度不替代内容依据。

复用账号环境队列、UID核验、日常参与候选、上下文、待审回答和发布任务。不新增通用站点请求器、不绕过验证或限制。单次读取当前已加载列表，最多50项；本地查询不重复访问远端，智能体读取复用按账号和来源隔离的10分钟缓存，工作台显式点击重新读取。卡片逐个水合，等待可见列表连续750毫秒稳定后再解析，加载上限10秒；仍持续变化时停止，不将首条已加载卡片当作完整列表。

回答以第一人称表达具体观点，例如“我更看重……”或“我的建议是……”，不虚构亲测、履历、年龄、职业或经历，不照搬来源回答。正文不机械追加“AI辅助回答”套话；后台AI使用事实及平台要求的真实标识保留。起草、审阅与发布继续遵守现有权限、费用预算和准确版本门禁。

推荐问题对应的回答稿在统一自主排期时，先求合法最早时段，再在当日剩余运营时段抽取时间，最后重用现有额度、同账号和同出口间隔校验。随机结果随原任务保存，不在每次观察、唤醒或重试时重抽，也不用于规避平台限制。无法排期或结果未知时按原规则停止。

本轮按AGENTS.md只进行源码/类型检查及桌面手动核对，不自动运行测试套件或脚本化界面测试，不提高原有发文与模型预算。

## 实现位置与使用

“知乎多号运营 → 日常参与 → 推荐问题·浏览量大于1万”在当前选择账号的绑定环境读取；无需填写搜索关键词，原关键词发现入口保留。候选行显示原始浏览量和读取时间，全文入口复用原上下文读取。自动工具`discover_zhihu`增加`source=creator_recommend`，`prepare_zhihu_answer`对新自动回答强制核对本账号推荐热度证据；没有读数的普通搜索候选不能被自动回答工具当成合格推荐。历史回答稿保留，不因规则变更复制或重发。

`core/zhihu-participation/recommended.ts`只读取可见DOM：每行必须包含唯一规范问题链接及本行浏览指标，支持万/亿的精确十进制换算，拒绝负值和无法识别的指标。`shared/zhihu-participation.ts`维护来源与数值契约，候选和缓存沿用原持久化与备份。

`core/intelligent-operations/answer-scheduling.ts`只为本计划、原账号、已绑定回答稿对应的推荐问题计算随机时段。先由原`publicationSlot`得到最早合法时间，再在该运营日结束前随机取整秒，重新过原额度及错峰计算；没有其他随机可用结果时保留原合法时间。抽取结果写进同一任务的排期下界，后续观察复用，不重新抽取。手动排期和其他渠道不改变。运行时额度/间隔变化仍可能顺延执行，不保证平台一定接受提交。

文风要求接入原生系统提示和回答工具描述，AI使用记录仍为真实`aiAssisted:true`，不修改历史文章的声明；没有以删标识绕过平台要求。第一人称用于观点和建议，不能把AI生成的叙述伪装成用户确实做过的经历。没有问题图片输入时不得评价图片细节。
