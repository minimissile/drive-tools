1. 产品定位与完整流程

默认面向一个运营者、一个本地工作空间；每种网盘可以绑定多个账号并选择目标账号。保留工作空间与账号标识，为以后多人协作留结构，首版不建设云端账号系统。产品名称“盘序”为暂定名。

录入资源 → 校验分享 → 选择文件与目标目录 → 同网盘转存 → 核验目标文件 → 创建自己的分享 → 写入本地知识库 → 提取关键词 → 5118扩词 → 人工选择词池 → 生成平台草稿 → 审阅 → 打开指定指纹窗口 → 人工发布与回填

需要补充的关键业务对象：来源分享链接、目标网盘文件、自己的分享链接是三个不同对象。转存成功不代表分享成功；知识库写入成功不代表内容已发布。每一步分别记录状态，避免文案错误使用他人的来源链接。

补充需求：同盘多账号与本人链接的强约束

同一种网盘支持多个本人账号，登录会话隔离，账号可以灵活切换。账号管理包含新增、改名、重新登录、设默认、切换使用、启停和移除本地凭据；展示网盘类型、账号别名、脱敏UID、会话状态、默认目录和关联资源/任务。别名只是显示名称，不能作为文件或分享的所有权证明。

  • 默认账号、当前账号和任务账号分别保存：默认账号用于新录入，当前工作账号用于筛选和新任务选择；任务创建时锁定目标账号ID与网盘实际UID。切换工作账号不会改变正在运行的任务、历史资源归属和旧分享链接。
  • 每次录入可选目标账号与目录：仅列出与来源同一网盘类型的账号。账号过期时等待该账号重新登录，不静默换成其他账号。重新登录后必须核对实际UID，登录成另一个账号要阻止恢复。
  • 同一资源可有多个本人账号副本：逻辑资源与资源副本分离；同一来源保存到账号A和B不算重复。转存幂等以来源文件集合、目标账号和目录组合判断；每个副本保留自己的文件ID与本人分享版本。创作时选择具体副本与分享。
  • 只使用本人的对外链接：在目标账号A转存→用A核验目标文件归属→用A创建分享→核对分享归属与可用性→获得“可分发”状态。禁止用A转存后无提示切换B创建分享，禁止分享失败时回退来源链接。
  • 对外链接单独校验：文案生成服务不接收来源链接；分发服务只读取已核验的owned_share。即使人工把第三方网盘URL粘进草稿，复制/导出/打开发布准备前也要拦截并提示。来源URL可保留在私有知识档案以便追溯，明确标记“仅内部追溯，禁止分发”。
  • 移除账号不删除云端内容：停用后禁止新任务；有活动任务时须先完成或取消并核对结果。被资源引用的账号保留历史UID和归属，只移除凭据。云端文件删除和分享撤销均是额外显式操作。
可分发条件（全部成立）：
  目标文件已核验
  target_owner_uid == selected_account.provider_user_id
  share_creator_uid == target_owner_uid
  本人分享已生成且有效
  分享版本与草稿绑定版本一致

切换“当前账号” ≠ 修改历史任务目标 ≠ 改写已发布链接
来源分享只用于读取、转存与内部追溯，永不作为分发回退链接。

2. 网盘转存：调研结论与实施建议

公开项目证明同网盘分享转存有可复用的工程基础，尚不能据此承诺你的账号下长期稳定。本次验证到文档和公开实现层面，未进行真实登录、转存、分享与容量测试。正式开发确认后，先做限量、可重复的技术验证，再锁定适配方案。

路线已确认依据建议与待验证项
夸克网页接口适配quark-auto-save公开实现会话登录与自动转存；可参考其源码理解分享解析、文件选择、转存及异步任务处理；另有同名社区项目在说明中列出创建分享能力，须独立验证，不推定两个项目功能相同作为首选验证路线，单独封装适配器。逐一验证登录态、加密分享、多文件、目录、任务轮询和建分享。属于社区封装路线，不能因请求发往官方域名就称为官方授权的开放API。许可证和依赖在引入前核对，当前不直接复制代码
百度开放平台官方平台提供网盘集成及文件分享相关能力，平台已公告整合升级优先核对应用审核、授权范围及“任意个人分享链接转存到本人网盘”是否覆盖。OAuth拿到访问令牌不等于获得该能力；公开资料不足以把它列为已确认主路径
百度社区实现BaiduPCS-Go包含普通分享链接转存、文件选择和分享命令，支持多平台；仓库标注Apache-2.0可作为独立Go辅助进程或实现参考；锁定版本与校验和。验证会话要求、目标路径、退出码与实际结果一致性；必要时扩展结构化输出。不依赖“秒传”功能，不对下载提速作承诺
浏览器辅助转存基于用户正常登录的网盘网页操作，保留人工完成步骤接口不可用时打开分享/目标目录，由用户完成转存并触发核验。DOM变化会增加维护成本，不作为首选高并发引擎；此为设计备选，尚未实测
跨网盘互转不同提供方的文件ID与会话无法直接通用预留下载→临时存储→上传→校验策略以及能力协商；未来需验证带宽、空间、配额、断点和清理，不能只新增一个按钮就称为已支持

转存引擎的必要约束

  • 按账号串行开始：首版每个账号默认同时执行一个转存任务，跨账号可有限并行；后续依据实际限流调整。网络错误退避重试；鉴权失败、提取码错误、容量不足、验证码和资源失效分别处理，避免无限重试。
  • 先预检再转存：识别真实域名与分享ID，检测分享有效性、提取码、账号身份、目标目录和可获取的容量信息；支持选择文件及按页读取目录。非网盘白名单域名不自动访问。
  • 幂等与恢复：以提供方、分享ID、源文件ID集合、目标账号和目录建立任务指纹；操作前记录任务与尝试ID。断网或崩溃后先查询远端任务及目标文件，再决定是否重试。不能仅按文件名判断转存成功。
  • 核验结果：获取目标文件ID、路径、数量和可取得的大小；部分成功逐项记录。能获取哈希时使用哈希辅助，不能获取时明确核验程度，不伪造“完整性校验通过”。
  • 新分享独立重试：目标文件确认后才创建分享。分享ID、URL、提取码、有效期与最后校验时间单独保存；分享失败可重试，不重复转存。分享失效会使相关草稿进入“链接需更新”。
  • 取消的真实含义：取消本地等待不保证远端任务撤销。显示“正在核对远端结果”，不自动删除已经转存的文件；删除需用户明确操作。

3. 桌面技术选型

建议：Electron + React + TypeScript + Vite + SQLite。界面为桌面应用，业务运行在受控的本地进程；网盘、AI、5118与比特浏览器各自使用适配器。以下为结合本项目需求的工程判断，非供应商对稳定性或性能的承诺。

方案适配性本项目取舍
Electron统一Chromium、Node生态，可管理本地文件、后台任务、隔离登录会话与CDP连接；包体和内存成本较高推荐。当前主要复杂度在网盘会话与本地自动化集成，优先降低两端行为差异。遵循官方安全建议，不让界面直接持有系统权限
Tauri 2较轻的桌面壳，Rust后端与系统WebView；支持外部辅助程序可行备选。需维护Rust、WebView会话差异及可能的Node/Go辅助进程。若安装体积成为首要约束，再通过验证重新比较
Python + WebView社区网盘脚本复用方便不作为主架构。桌面界面、分发和运行时打包仍需额外工程；可作为隔离辅助程序，用户不需要自行安装Python
React界面（无Node权限）
          ↓ 受限、校验参数的IPC
Electron主进程 / 应用服务
  ├─ SQLite仓储、持久任务队列、Outbox
  ├─ 资源与知识库服务 → 附件、Obsidian镜像
  ├─ 网盘适配器 → 受控Worker / 可选Go辅助进程
  ├─ OpenRouter适配器 / 5118适配器
  ├─ 平台模板与版本化规则策略
  └─ 比特Local API + CDP → 仅打开指定发布页

凭据加密存储独立于Vault；渲染层只显示状态与脱敏标识

凭据使用系统保护能力加密保存（例如Electron safeStorage 对接的系统机制），并验证加密服务可用性；不可用时不明文降级。每个网盘账号使用隔离会话。启用contextIsolation、sandbox，关闭nodeIntegration，校验IPC来源与参数，外部链接按域名放行。

打包工具建议electron-builder；目标为Windows x64的NSIS安装版.exe，macOS arm64/x64的.dmg（或经过验证的Universal构建）。SQLite原生依赖与辅助程序需要逐架构重建与签名。Windows与macOS分别构建、安装、升级和卸载验证；面向正常分发需要Windows代码签名及Apple Developer ID签名、公证。具体版本在开发启动时锁定，当前不预设过时版本号。参考打包文档及签名文档。

首版关闭应用后暂停本地任务，重新启动后核对远端状态并恢复。窗口关闭时有运行任务则提供“后台继续/退出”选择；系统休眠、网断和系统重启不应使任务被误记成功。

4. SQLite + Obsidian：各自承担什么

SQLite是运行记录的唯一权威源，Obsidian是可阅读、可迁移的知识视图。不能用Obsidian Markdown替代任务数据库，也不需要把Obsidian作为必须安装的服务。用户可以只用本工具，也可以指定现有Vault内的专用子目录。

数据保存方式一致性规则
资源、分类、标签、链接版本SQLite；外键、唯一索引、迁移与修订号先保存草稿；转存未完成也不会丢失录入内容。完成后更新状态
任务、尝试、远端任务ID、错误SQLite jobs / job_attempts / events事务提交、重启恢复、单账号互斥，不依赖界面内存计时器
封面与附件应用数据目录，按内容哈希去重；Vault内复制独立附件校验真实格式、大小与写入路径；封面失败不丢整条资源
知识笔记Vault/盘序/Resources/<资源ID>.md；封面用相对路径；YAML平铺属性数据库事务内生成outbox事件，导出用临时文件+原子替换；失败进入待同步，可独立重试
人工修改笔记自由正文保留，生成区域有边界与内容哈希首版从应用单向导出；检测外部修改后提示差异与冲突，不覆盖。用户可显式选择导入可编辑字段；任务与凭据禁止从笔记反向改写
关键词、词池与内容版本SQLite关系数据；可导出到资源笔记下的关联内容记录模型、模板、规则版本、输入快照、采集日期和费用，支持追溯
Cookie、API Key、会话系统加密的凭据存储或隔离会话存储禁止写入Vault、普通导出、日志和AI提示词；默认备份不包含凭据，迁移后重新登录

检索与备份

首版先做SQLite索引与FTS5。中文标题/摘要使用trigram子串检索；SQLite的trigram对不足三个字符的查询有限制，1–2字查询使用有结果上限的LIKE或分类/标签精确匹配，验证真实中文语料的召回率。参数绑定并转义查询语法，避免把用户输入当SQL或FTS表达式。大规模或语义检索后续再增加向量索引，不先引入独立数据库服务。

备份采用SQLite在线备份或受控检查点后的一致快照，连同附件和导出清单；不能只复制正在写入的db文件而遗漏WAL。先备份再迁移，保留恢复入口。删除本地条目默认为归档，不联动删除网盘文件或撤销分享。

5. OpenRouter 与 5118 的工作方式

  1. 用户补充资源摘要或选入的文件清单。仅有一个分享链接不能自动知道文件正文；首版不默默下载、OCR或阅读整个网盘目录。
  2. 使用用户的OpenRouter Key从标题、摘要、文件名中提取种子词；选支持结构化输出的模型，按JSON Schema验证，失败重试有上限并可手动输入。OpenRouter文档说明结构化输出取决于模型支持情况。
  3. 种子词先供用户删改，再调用已购买权限的5118“海量长尾词挖掘API v2”。记录查询条件、分页、来源、时间及接口实际返回字段，缓存同条件结果；调用前显示预估次数，支持单次与每日预算上限。
  4. 保留搜索量/指数的原始名称及来源，缺失值显示“未提供”。按需求意图、资源匹配度分组，用户选择词池。一个资源可以对应多个词池，相关度模型打分如有使用必须标为估计值。
  5. 根据平台和词池生成内容包：标题、正文、话题、封面文案、短视频脚本、资源说明与允许的获取方式。先通过确定性的渠道策略过滤，再提供AI建议；AI不能修改政策以放行外链。
  6. 人工编辑、预览、检查资源事实和链接版本后保存草稿。内容修改后重新检查；使用AI生成内容时保留平台所需的声明/标识入口，具体要求按平台后台核对。

v0.2补充调研已直接读取5118官方接口详情和从商城链接的官方文档压缩包，确认参数、返回字段及套餐计次方式。官方压缩包以https://apis.5118.com为域名，部分旧网页示例仍写HTTP并关闭证书检查；实现时统一使用HTTPS且验证证书，禁止照搬关闭TLS校验的示例。不同接口分别购买权限、配置Key和核算用量，不能假定一个Key和统一余额覆盖全部接口；真实账号额度仍需联调确认。

原型中的“百度PC指数（示例）”仅说明数据展示结构。不能将这些数值解读为真实当前流量或其他平台的搜索量，也不能根据AI生成的流量数字作选题判断。调用OpenRouter时默认只发送用户选择的资源文字，分享URL、提取码和Cookie不传入；OpenRouter费用按可取得的实际用量/金额记录；5118费用使用下节的独立台账与对账机制，提前显示的只能是估算。

费用统计结论：能统计本地用量并估价，尚未确认可自动查询官方精确账单

本次检查了公开商城目录、上述四个接口详情和商城提供的官方参考包。返回合同主要是errcode/errmsg/data和业务字段，未找到明确公开的账户余额、剩余配额、逐请求实际扣费或账单查询API；这表示“公开资料中未确认”，不是断言5118绝对没有内部或企业专属接口。管理我的API是需登录的网页入口，不当作机器可读费用接口。当前没有登录你的5118账号，也没有发出付费请求。

  • 请求台账：记录接口、API凭据引用、任务ID、请求/重试/轮询次数、结果码、时间、分页、关键词数和本地缓存命中。缓存不发出请求，外部请求数计0。
  • 计费台账：“预期计费单位”“供应商确认单位”“待核实单位”分开；成功响应也不自动等于已确认扣费。超时、失败、部分返回、异步轮询和重试要保留不确定性，不能默认免费或默认重复扣费。
  • 套餐估算：按用户实际购买的每接口套餐录入价格与额度，可记录多个套餐批次、试用及赠送。单位摊销价＝实付金额÷该批次有效计费额度；不把商城“低至”价格直接用到所有用户。费用以足够精度的整数单位记录，避免浮点误差。
  • 两种金额区分：“本地估算消耗”表示预付套餐的摊销消耗，不是这次请求新扣了一笔人民币；“已付款金额/官方确认扣费”必须有订单、账单或供应商明确字段依据。官方未返回则显示“未同步”，不能显示0。
  • 预算：发起前依据关键词×页数/平台数/关键词数预留额度；并发与超时占用预算，失败或取消只有在确定未计费后释放。提供单任务、每日预算上限和预计余额，预估余额必须标记为本地值。
  • 对账：首版允许手工记录官方后台用量/剩余次数/账单快照；仅在后台实际支持导出时提供文件导入。保留供应商适配器口子，若取得官方用量接口再启用自动同步。显示上次对账时间与差额，不自动覆盖本地历史。

例：使用长尾词首档0.02元/次，3个种子词各查询2页，预期6个计费单位，摊销估算0.12元；不是“发1个批量任务只算1次”，也不是6×最低宣传价。真实账单仍需官方确认；费用原型里的数字均为虚构演示。

热点选题流程：关键词/类别/时间窗口筛选→查看原始更新时间与事件脉络→匹配资源副本→人工收藏到词池→平台草稿。没有匹配资源时加入待采集清单；不编造热点事实、不承诺接口提供平台上全部最新热搜榜。

6. 10个平台：外链能力与营销规则分开建模

不能只分成“能明发”和“需要隐晦引流”两档。支持输入网址不等于允许用它营销；私信、口令、谐音、评论区和图片二维码也不是自动安全的替代方式。建议建模为：允许相关链接、需账号/场景确认、仅批准的站内能力、未核实，并按平台、场景、账号、内容类型、规则日期保存证据。

7. 比特浏览器：首版可靠地打开正确窗口

本地服务指南说明从客户端设置获取Local API地址；浏览器接口文档列出POST /health、/browser/list、/browser/open，打开窗口返回WebSocket/HTTP调试地址。文档中的open参数不是直接传任意发布URL的合同，不能假定/browser/open({url})可用。

  1. 用户在设置填写本机Local API地址及版本所需认证信息；默认只接受localhost/127.0.0.1/::1，远程主机需单独配置与评估。
  2. 健康检查→分页读取窗口列表→将“平台账号”绑定到指定窗口ID。显示窗口名称与平台，避免发错账号。
  3. 点击发布准备时，调用/browser/open指定窗口ID，再连接返回的CDP会话；复用或新建对应平台标签页并导航到允许的编辑器URL。首版只导航，不填表、不点发布。
  4. 每个平台发布入口可配置并保存最后核实日期；带登录态的token、临时素材ID不固化。公众号、贴吧、豆瓣、知乎存在不同编辑场景，需选具体目标，不假设一个URL适用于全部内容类型。
  5. 先显式复制文案，再打开页面；封面单独下载。比特未安装、未启动、API鉴权失败、窗口不存在、导航失败分别提示。可以手动复制入口，不能静默打开系统默认浏览器后报告“指定窗口已打开”。
  6. 成功打开仅记为“编辑器已打开”；用户实际提交后手动标记“已发布”并回填URL。版本记录保留实际使用的草稿。

不在界面写死某个默认端口；以用户本机设置为准。首版导航采用受限CDP，不需要安装额外Chromium。Windows与macOS、比特客户端版本/套餐/API权限均进入真实联调验收。
